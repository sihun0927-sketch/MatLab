# 🐞 오류 찾기 50선 — 해답

문제는 [problems.md](problems.md). 해설마다 `| 줄 | 원인 | 현상 | 수정 |` 표, 실행 순서(어느 오류가 먼저 보이고 그걸 고치면 다음에 무엇이 드러나는지), 고친 코드, 고친 코드의 Command Window 출력 순이다. 표에서 **오류 아님**으로 표시한 행은 문제에 섞인 미끼다.

오류 메시지는 R2026a 한국어 메시지의 **요지**다. 글자 그대로 외울 필요는 없고, "무슨 종류의 오류인가"(문법/실행/조용함)와 "어느 줄에서 멈추는가"를 맞히는 것이 채점 포인트다.

> B01~B40의 출력은 손으로 계산했다. 공백 수·빈 줄 수처럼 확신이 덜한 자리는 `> **[확인 필요]**`로 표시했다. B41~B50은 R2026a에서 실행해 확인했다.

## 문제 B01 🐞 자유 낙하와 연산자 우선순위

변수 이름 규칙과 대소문자, 암시적 곱셈, 그리고 `^`가 단항 `-`와 `/`보다 먼저, 왼쪽부터 계산된다는 우선순위가 핵심이다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `drop-dist = ...` | 변수 이름에 하이픈을 쓸 수 없다. `drop - dist`라는 뺄셈식이 `=` 왼쪽에 온 꼴이다 (2.3) | **문법 오류**. 파일 전체가 실행되지 않는다 | `drop_dist = 1/2*g*t^2` |
| `(2h0/g)^1/2` 의 `2h0` | 곱셈 기호를 생략할 수 없다 (2.4) | **문법 오류**(곱셈 연산자가 빠졌다는 취지) | `2*h0` |
| `(...)^1/2` | `^`가 `/`보다 먼저라 `((2*h0/g)^1)/2`로 계산된다 (2.4) | 조용히 틀린 값: `8.1549` (정답 `4.0386`) | `sqrt(2*h0/g)` 또는 `(2*h0/g)^(1/2)` |
| `pct = drop_dist/hleft*100` | 변수 이름은 대소문자를 구분한다. 정의한 이름은 `hLeft` (2.3) | 실행 오류: 정의되지 않은 함수 또는 변수 `hleft` | `hLeft` |
| `s = -1^2` | `^`가 단항 `-`보다 먼저라 `-(1^2)` (2.4) | 조용히 틀린 값: `-1` | `(-1)^2` |
| `scale = 2^3^2` | 같은 우선순위는 **왼쪽부터** 계산해 `(2^3)^2` (2.4) | 조용히 틀린 값: `64` | `2^(3^2)` |
| `1/2*g*t^2`, `1/2*m*(g*t)^2` | **오류 아님**. `t^2`가 먼저, 그다음 `*`와 `/`를 왼쪽부터 계산해 `(1/2)*g*t^2`가 된다 | — | — |
| `g = 9.81;  h0 = 80; ...` | **오류 아님**. `;`로 구분한 여러 문장을 한 줄에 쓸 수 있고, 모두 표시되지 않는다 | — | — |

문법 오류가 두 개라 처음에는 아무 줄도 실행되지 않고 화면에는 오류 메시지만 나온다. 두 문법 오류를 고치면 `drop_dist`, `hLeft`, `KE`가 표시된 뒤 `pct` 줄에서 `hleft` 오류로 멈춘다. 그것까지 고치면 끝까지 실행되지만 `tImpact`, `s`, `scale` 세 값이 조용히 틀린다.

고친 코드:

```matlab
clear, clc
g = 9.81;  h0 = 80;  t = 2;  m = 2;
drop_dist = 1/2*g*t^2
hLeft = h0 - drop_dist
KE = 1/2*m*(g*t)^2
pct = drop_dist/hLeft*100
tImpact = sqrt(2*h0/g)
s = (-1)^2
scale = 2^(3^2)
```

```
drop_dist =

   19.6200

hLeft =

   60.3800

KE =

  384.9444

pct =

   32.4942

tImpact =

    4.0386

s =

     1

scale =

   512

```

## 문제 B02 🐞 센서 샘플 시각과 범위

`;`의 출력 억제, 정수가 아닌 인덱스, 콜론 범위의 방향·끝점, `linspace` 인자 순서를 함께 묻는다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `t = 0:0.001:10` | 끝에 `;`가 없다 (2.4) | 원소 **10001개**가 Command Window를 뒤덮는다 | `t = 0:0.001:10;` |
| `tMid = t(n/2)` | `n = 10001`이라 `n/2 = 5000.5`. 인덱스는 양의 정수여야 한다 (4.1) | 실행 오류: 배열 인덱스는 양의 정수 또는 logical 값이어야 함 | `t((n+1)/2)` → `t(5001)` = 5 |
| `countdown = 10:2:0` | 증가폭이 양수인데 끝이 시작보다 작다 (4.1.4) | 조용히 **빈 배열**: `1×0 empty double row vector` | `10:-2:0` |
| `ticks = linspace(0, 6, 50)` | 인자 순서는 `linspace(시작, 끝, 개수)` (2.4) | 조용히 틀림: 0~6 사이 **50개**가 표시된다 | `linspace(0, 50, 6)` |
| `duty = 0:0.3:1` | 콜론은 끝값에 정확히 닿을 때만 끝값을 넣는다. 0.3은 1/3이 아니다 (4.1.3) | 조용히 틀림: `[0 0.3 0.6 0.9]`, 1이 빠진다 | `linspace(0, 1, 4)` |
| `nTicks = length(ticks);` | 표시해야 하는 줄에 `;`를 붙였다 (2.4) | 화면에 **아무것도 안 나온다** | `nTicks = length(ticks)` |
| `n = numel(t);` | **오류 아님**. 개수는 `fprintf`로 출력하므로 숨기는 것이 맞다 | — | — |
| `fprintf('samples: %d\n', n);` | **오류 아님**. `;`는 대입·표현식의 결과 표시만 막는다. `fprintf`의 출력은 그대로 찍힌다 | `samples: 10001` 출력 | — |

실행하면 먼저 `t`의 10001개 값이 화면을 덮고, `tMid` 줄에서 인덱스 오류로 멈춘다. 그 줄을 고치면 끝까지 돌지만 `countdown`은 빈 배열, `ticks`는 50개, `duty`는 4개이되 1이 없고, `samples: 10001` 다음에 `nTicks`는 나오지 않는다.

고친 코드:

```matlab
clear, clc
t = 0:0.001:10;
n = numel(t);
tMid = t((n+1)/2)
countdown = 10:-2:0
ticks = linspace(0, 50, 6)
duty = linspace(0, 1, 4)
fprintf('samples: %d\n', n);
nTicks = length(ticks)
```

```
tMid =

     5

countdown =

    10     8     6     4     2     0

ticks =

     0    10    20    30    40    50

duty =

         0    0.3333    0.6667    1.0000

samples: 10001
nTicks =

     6

```

## 문제 B03 🐞 저항 표와 `[ ]` 안의 구분자

`[ ]` 안에서 `;`(새 행), `,`/공백(같은 행), 줄바꿈(새 행), 그리고 공백 하나에 따라 달라지는 `[1 - 1]`을 구분하는 문제다. 문장 구분자 `,`는 결과를 표시한다는 점도 함께 묻는다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `R = [100 220 470], I = ...;` | 문장 구분자 `,`는 앞 문장의 결과를 **표시**한다 (2.4) | 화면에 `R =` 과 `100 220 470`이 나온다(`I`는 끝의 `;` 때문에 숨겨진다) | `R = [100 220 470]; I = ...;` |
| `sgn = [1 - 1];` | `-` 양쪽에 공백이 있으면 뺄셈이라 스칼라 `0` (4.1.1) | 조용히 틀림: `band = 100` (스칼라 하나) | `[1 -1]` |
| `data = [R, V]` | `,`는 같은 행에 이어 붙인다 (4.1.1) | 조용히 틀린 모양: 1×6 `100 220 470 2 2.2 1.88` | `[R; V]` |
| `P = [... V(2)*I(2)` 줄바꿈 `V(3)*I(3)]` | `[ ]` 안의 줄바꿈은 **새 행**. 1행 2개, 2행 1개라 열 수가 다르다 (4.1.1) | 실행 오류: 연결하는 배열의 차원이 일치하지 않음 | 1행 끝에 `...` |
| `M = [R; I];` | `R`은 1×3, `I`는 3×1이라 세로로 쌓을 수 없다 (4.1.1) | 실행 오류: 차원 불일치 | `[R; I']` |
| `I = [0.02; 0.01; 0.004;]` | **오류 아님**. `[ ]` 끝의 `;`는 무시되어 3×1 열이 된다 | — | — |
| `V = R.*I'` | **오류 아님**. `I'`가 1×3이라 `R`과 크기가 같다. 원소별 곱 (2.4 전치) | `2.0000 2.2000 1.8800` | — |

실행하면 `R`, `V`, `band = 100`, 1×6 `data`가 차례로 표시되고 `P` 줄에서 차원 오류로 멈춘다. `...`를 넣어 고치면 `M` 줄에서 다시 차원 오류가 난다. `M`은 `;`로 숨겼지만 오류 메시지는 숨겨지지 않는다.

고친 코드:

```matlab
clear, clc
R = [100 220 470]; I = [0.02; 0.01; 0.004;];
V = R.*I'
sgn = [1 -1];
band = R(1)*(1 + 0.05*sgn)
data = [R; V]
P = [V(1)*I(1) V(2)*I(2) ...
     V(3)*I(3)]
M = [R; I'];
sz = size(M)
```

```
V =

    2.0000    2.2000    1.8800

band =

   105    95

data =

  100.0000  220.0000  470.0000
    2.0000    2.2000    1.8800

P =

    0.0400    0.0220    0.0075

sz =

     2     3

```

## 문제 B04 🐞 스프링 배열 연산

행렬 연산자 `*`, `/`, `^`와 원소별 연산자 `.*`, `./`, `.^`를 구분하는 문제다. 크기가 안 맞으면 오류가 나고, 우연히 맞으면 조용히 엉뚱한 값이 나온다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `F = k*x` | 1×4 `*` 1×4는 행렬곱이라 안쪽 차원(4 ≠ 1)이 맞지 않는다 (2.4, 4.2.2) | 실행 오류: 행렬곱의 차원이 맞지 않음 | `k.*x` |
| `x^2` | 정사각 행렬이 아닌 벡터에 행렬 거듭제곱 (2.4) | 실행 오류: 정사각 행렬이어야 함, `.^`를 쓰라는 취지 | `x.^2` |
| `c = 1000/k` | `/`는 행렬 나눗셈. 1×1과 1×4는 열 수가 달라 실패한다 (2.4 함정) | 실행 오류: 차원이 맞지 않음 | `1000./k` |
| `r = E/F` | 두 1×4 벡터의 `/`는 열 수가 같아 **최소제곱 해 하나**를 낸다 (4.2.2) | 조용히 틀림: 스칼라 `0.0790` | `E./F` |
| `G2 = G^2` | 정사각 행렬이라 행렬곱 `G*G`가 계산된다 (2.4 함정) | 조용히 틀림: `[7 10; 15 22]` | `G.^2` |
| `Etot = 1/2*k*(x.^2)'` | **오류 아님**. (1×4)·(4×1) 행렬곱 = 내적이라 Σk·x²가 된다 | `17.6250` | — |
| `1/2*k.*...` | **오류 아님**. 스칼라 `1/2`와의 `*`는 모호하지 않다 (4.2.1) | — | — |

실행하면 `k`, `x`는 `;`로 숨겨져 아무것도 표시되지 않은 채 `F` 줄에서 바로 멈춘다. 그 줄을 고치면 `E`, 다음에 `c`에서 차례로 멈춘다. 셋을 모두 고치면 끝까지 실행되지만 `r`은 스칼라 하나, `G2`는 행렬곱 결과가 나온다.

고친 코드:

```matlab
clear, clc
k = [200 350 500 800];
x = [0.10 0.20 0.05 0.15];
F = k.*x
E = 1/2*k.*x.^2
Etot = 1/2*k*(x.^2)'
c = 1000./k
r = E./F
G = [1 2; 3 4];
G2 = G.^2
```

```
F =

    20    70    25   120

E =

    1.0000    7.0000    0.6250    9.0000

Etot =

   17.6250

c =

    5.0000    2.8571    2.0000    1.2500

r =

    0.0500    0.1000    0.0250    0.0750

G2 =

     1     4
     9    16

```

## 문제 B05 🐞 원리합계 저장과 불러오기

`%` 뒤는 모두 주석이라 `;`까지 지워진다는 점, 표시가 필요한 줄의 `;`, `%%` 뒤 공백, `clc`와 `clear`의 차이, ASCII `load`가 만드는 변수 이름이 핵심이다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `rate = 5%;` | `%`부터 줄 끝까지 주석이라 `;`도 주석이 된다. 문장은 `rate = 5` (2.5 주석) | 화면에 `rate =` 과 `5`가 **표시**되고, `balance = 1000*6.^years`로 조용히 틀린다 | `rate = 0.05;` |
| `balance;` | `;`가 표시를 막는다 (2.4) | 원리합계 표가 **안 나온다** | `balance` |
| `%%Section 2: ...` | `%%` 뒤에 공백이 없으면 섹션 구분자가 아니라 그냥 주석이다 (2.5.3) | 파일 전체가 한 섹션이라 Section 2만 따로 실행할 수 없다 | `%% Section 2: ...` |
| `clc` | `clc`는 화면만 지운다. 변수는 그대로 남는다 (2.2.3) | `final`이 파일이 아니라 **메모리의** `balance`에서 나온다. 다시 불러오기 검증이 안 된다 | `clear` |
| `final = balance(end)` | ASCII 파일을 `load`하면 저장한 변수 이름이 없고 **파일 이름** `growth`(2×6) 하나로 들어온다 (2.5.1) | `clear`로 고치면 실행 오류: 정의되지 않은 함수 또는 변수 `balance` | `growth(2, end)` |
| `save growth.dat years balance -ascii` | **오류 아님**. 두 변수 모두 1×6이라 6열짜리 두 줄로 저장되고, `load`가 2×6 배열로 읽는다 | — | — |
| `saved = size(growth)` | **오류 아님**. `load growth.dat`가 만든 변수가 `growth` | `2 6` | — |

오류 메시지 없이 끝까지 실행되며 화면에는 `rate = 5`, `final = 7776000`, `saved = 2 6`만 나온다. 원리합계 표는 보이지 않고, `final`은 이율 500 %로 계산된 메모리 값이다. `clc`를 `clear`로 바꾸면 그제야 `balance` 미정의 오류가 드러난다.

고친 코드:

```matlab
%% Section 1: 원리합계 계산
clear, clc
P0 = 1000;
rate = 0.05;                     % 5 %
years = 0:5;
balance = P0*(1 + rate).^years;
balance
%% Section 2: ASCII 저장 후 다시 불러오기
save growth.dat years balance -ascii
clear
load growth.dat
final = growth(2, end)
saved = size(growth)
```

```
balance =

   1.0e+03 *

    1.0000    1.0500    1.1025    1.1576    1.2155    1.2763

final =

   1.2763e+03

saved =

     2     6

```

> **[보강]** `-ascii`는 유효숫자 8자리로 저장하므로 불러온 `growth(2, end)`는 `1276.2816`이다. 원래 값 `1276.2815625`와 끝자리가 다르다.

## 문제 B06 🐞 성적 행렬 인덱싱

단일 인덱스와 `(:)`는 **열 우선**으로 센다는 점, 행 삭제 후 인덱스가 당겨진다는 점, `length`가 가장 큰 차원이라는 점이 핵심이다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `b = S(5)` | 단일 인덱스는 열 우선. 5번은 2행 2열 (4.1.3) | 조용히 틀림: `73` (학생 2의 시험 2) | `S(1, 2)` → `85` |
| `flat = S(:)'` | `(:)`는 1열, 2열, ... 순서로 이어 붙인다 (4.1.3) | 조용히 틀린 순서: `78 88 69 85 73 90 92 95 77 64 81 85` | `T = S'; flat = T(:)'` |
| `n = length(S)` | `length`는 가장 큰 차원. 삭제 후 `S`는 3×4라 4 (4.4.1) | 조용히 틀림: `4` | `size(S, 1)` |
| `x = S(3, 4)` | 2행을 지우면 학생 3이 **2행**으로 당겨지고, 3행은 학생 4다 (4.1.3) | 조용히 틀림: `100` (학생 4) | `S(2, 4)` → `85` |
| `y = S(4, 1)` | 삭제 후 행은 3개뿐 (4.1.2) | 실행 오류: 인덱스가 배열 범위를 벗어남 | `S(end, 1)` → `70` |
| `S(end+1, :) = [70 80 90 100];` | **오류 아님**. `end+1`행에 대입하면 행이 하나 늘어난다. 열 수 4가 맞다 | — | — |
| `S(2, :) = [];` | **오류 아님**. 행 전체에 `[]`를 대입하면 그 행이 삭제된다 | — | — |

## 문제 B07 🐞 특수 행렬 함수

`diag`가 행렬을 받으면 대각선을 **뽑고**, 벡터를 받으면 대각 행렬을 **만든다**는 점이 핵심이다. `sum`의 기본 방향과 `zeros(n)`의 모양도 함께 묻는다. 오류 메시지가 하나도 없다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `total = sum(A)` | 행렬의 `sum`은 **열별** 합 (4.3.4) | 조용히 틀림: 1×4 `34 34 34 34` | `sum(A(:))` → `136` |
| `offDiag = A - diag(A)` | `diag(A)`는 4×1 열(대각선 추출)이다. 4×4 − 4×1은 각 행 i에서 `A(i,i)`를 빼는 계산이 된다 (4.3.3 함정) | 조용히 틀림: `[0 -14 -13 -3; -6 0 -1 -3; 3 1 0 6; 3 13 14 0]`. 대각선만 0이라 맞은 것처럼 보인다 | `A - diag(diag(A))` |
| `Z = zeros(4)` | 인수 하나는 n×n (4.3.1) | 조용히 틀린 모양: 4×4 영행렬 | `zeros(1, 4)` |
| `I3 = diag(3)` | 스칼라도 벡터(1×1)라 1×1 대각 행렬 `3`이 된다 (4.3.3) | 조용히 틀림: `3` | `eye(3)` |
| `[r, c] = size(Z)` | 이 줄 자체는 맞다. `Z`가 틀려서 결과가 틀린다 | `r = 4`, `c = 4` | `Z`를 고치면 `1`, `4` |
| `rowSum = sum(A, 2)` | **오류 아님**. 두 번째 인수 2가 행 방향 합 | `[34; 34; 34; 34]` | — |
| `dg = diag(A)'`, `D = diag(dg)` | **오류 아님**. 행렬 → 대각선 열 추출 후 전치해 1×4, 다시 벡터 → 4×4 대각 행렬 생성 | — | — |

오류 메시지 없이 끝까지 실행되므로 크기와 값으로만 판단해야 한다. 특히 `offDiag`는 대각선이 0이라 겉보기로는 맞는 것 같지만 나머지 원소가 전부 바뀌어 있다.

고친 코드:

```matlab
clear, clc
A = magic(4);
total = sum(A(:))
rowSum = sum(A, 2)
dg = diag(A)'
D = diag(dg)
offDiag = A - diag(diag(A))
Z = zeros(1, 4)
I3 = eye(3)
[r, c] = size(Z)
```

고친 출력의 요점(`magic(4) = [16 2 3 13; 5 11 10 8; 9 7 6 12; 4 14 15 1]`): `total = 136`, `offDiag = [0 2 3 13; 5 0 10 8; 9 7 0 12; 4 14 15 0]`, `Z = [0 0 0 0]`, `I3`은 3×3 단위행렬, `r = 1`, `c = 4`.

## 문제 B08 🐞 사거리 격자와 meshgrid

`meshgrid(x, y)`는 첫 출력이 `x`를 행마다 반복한 것이고 크기는 `length(y)×length(x)`다. 여기에 행렬 연산자, 도 단위 삼각함수, 행렬의 `max` 방향이 겹친다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `[V, TH] = meshgrid(theta, v)` | 첫 출력은 첫 인수 `theta`의 격자다. 이름이 뒤바뀌어 `V`에 각도, `TH`에 속도가 들어간다 (4.2.3) | 조용히 틀림. 크기는 3×5로 맞아서 눈치채기 어렵다 | `[TH, V] = meshgrid(theta, v)` |
| `V^2*sin(...)` | 3×5 행렬의 `^`와 `*`는 행렬 연산 (4.2.2) | 실행 오류: 정사각 행렬이 아니라 거듭제곱할 수 없음 | `V.^2 .* ...` |
| `sin(2*TH)` | 각도가 도 단위인데 `sin`은 라디안 (3.4) | 조용히 틀림 | `sind(2*TH)` |
| `best = max(R)` | 행렬의 `max`는 **열별** 최댓값 (3.5) | 조용히 틀림: 1×5 벡터 | `max(R(:))` |
| `[nr, nc] = size(R)` | **오류 아님**. 행 3(속도), 열 5(각도) | `3`, `5` | — |
| `R30_45 = R(3, 3)` | **오류 아님**. 3행 = v 30, 3열 = θ 45° | — | — |
| `R = ... /g;` | **오류 아님**. 스칼라로 나누는 `/`는 원소별과 같다 | — | — |

실행하면 `g`부터 `TH`까지 `;`로 숨겨져 아무것도 나오지 않은 채 `R` 줄에서 멈춘다. 연산자만 `.^`, `.*`로 고치면 끝까지 돌지만, 이름이 뒤바뀐 채라 `R(3,3)`은 45²·sin(60 rad)/g = `-62.9196`이 된다. 이름까지 고치고 `sin`이 남아 있으면 `R(3,3)` = 900·sin(90 rad)/g = `82.0180`이다. 모두 고쳐야 900/9.81 = `91.7431`이 나온다.

고친 코드:

```matlab

v = [10 20 30];
theta = 15:15:75;
[TH, V] = meshgrid(theta, v);
R = V.^2 .* sind(2*TH)/g;
[nr, nc] = size(R)
best = max(R(:))
R30_45 = R(3, 3)
```

## 문제 B11 🐞 반올림·나머지·세제곱근의 음수

양수에서는 똑같아 보이는 `fix`/`floor`, `rem`/`mod`, `nthroot`/`^(1/3)` 이 **음수에서 갈린다**는 점과, `[ ]` 안의 `;`/`,` 혼동이 핵심이다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `cut = floor(dx)` | `floor` 는 −∞ 쪽으로 내린다. 0 쪽으로 자르는 것은 `fix` (3.3) | 조용히 틀린 값 `-8 -3 3 8` (의도 `-7 -2 3 8`) | `cut = fix(dx)` |
| `cube = dx.^(1/3)` | 음수의 `^(1/3)` 은 복소 주근을 준다 (3.3) | 조용히 틀린 값. 앞 두 원소가 `0.9787 + 1.6952i` 같은 복소수가 되고 배열 전체가 복소수로 찍힌다 | `cube = nthroot(dx, 3)` |
| `phase = rem(near, 4)` | `rem` 은 결과 부호가 **피제수**를 따른다. 0~3 범위는 `mod` (3.3) | 조용히 틀린 값 `0 -2 0 1` (−2 는 버퍼 위치가 될 수 없다) | `phase = mod(near, 4)` → `0 2 0 1` |
| `mag = [abs(dx); s, near]` | `[ ]` 안에서 `;` 는 행 구분, `,` 는 같은 행 이어 붙이기. 2행이 `s` 와 `near` 를 옆으로 붙인 1×8 이 된다 (2.4) | **실행 오류**: 연결하려는 배열의 차원이 일치하지 않음 | `mag = [abs(dx); s; near]` |
| `near = round(dx)` | **오류 아님**. `round` 는 .5 를 0에서 먼 쪽으로 보낸다. `-7.5 → -8`, `8.5 → 9` 가 의도와 같다 | — | — |
| `s = sign(dx);` | **오류 아님**. `sign` 은 음수 −1, 양수 +1. 의도에 "화면에 보이라"는 말이 없으므로 `;` 도 괜찮다 | — | — |

원본은 문법 오류가 없으므로 위에서부터 실행된다. `cut`, `near`, `cube`(복소수 4개), `phase` 가 차례로 찍히고, `s` 는 `;` 때문에 안 보이며, 마지막 `mag` 줄에서 차원 오류로 멈춘다. 즉 화면에는 틀린 값 세 개가 **오류 없이 먼저** 나오므로, 마지막 오류만 고치면 끝났다고 착각하기 쉽다.

고친 코드:

```matlab
clear, clc
dx = [-7.5 -2.4 3.6 8.5];          % mm
cut = fix(dx)                      % 소수부 버림 (0 쪽으로)
near = round(dx)                   % 가장 가까운 정수
s = sign(dx);                      % 방향
cube = nthroot(dx, 3)              % 실수 세제곱근
phase = mod(near, 4)               % 버퍼 위치 0~3
mag = [abs(dx); s; near]           % 1행 크기, 2행 방향, 3행 반올림
```

```
     0     2     0     1
```

## 문제 B12 🐞 log 세 종류와 factorial 오버플로

## 문제 B14 🐞 max/min 의 세 가지 호출과 열 방향

`max(x, 2)` 와 `max(x, [], 2)` 의 차이, 두 배열 비교 `max(A, B)`/`min(A, B)` 의 방향, `sum` 의 열 우선, 단일 인덱스 `T(2)` 가 핵심이다. 원본은 **오류 없이 끝까지** 돈다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `dayMax = max(T, 2)` | 두 번째 인수 2 는 차원이 아니라 비교 대상. 각 원소와 2 중 큰 값 (3.5) | 조용히 틀린 값. `T` 와 똑같은 3×4 행렬 | `max(T, [], 2)` → `30; 27; 29` |
| `low = min(T, 22)` | "22 미만을 22로 올리기"는 둘 중 **큰** 값. `min` 은 22 초과를 22로 깎는다 (3.5) | 조용히 틀린 값 `[21 22 19 22; 22 22 22 22; 20 22 22 22]` | `max(T, 22)` |

## 문제 B15 🐞 통계 함수의 차원 인수와 숨겨진 결과

"모두 화면에 보여라"는 요구에서 `;` 가 결과를 숨기는 것, `mean`/`mode` 의 열 우선, `std(S, 2)` 의 2 가 차원이 아니라 가중치라는 점이 핵심이다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `avgStu = mean(S);` (차원) | 행렬의 `mean` 은 **열마다** 평균 → 퀴즈별 평균 1×3 (3.5) | 조용히 틀린 값 `76.7500 72.2500 80.0000` | `mean(S, 2)` |
| `avgStu = mean(S);` (`;`) | 문장 끝 `;` 는 결과 표시를 억제한다 (2.2) | 화면에 **아무것도 안 나옴**. 요구 위반 | `;` 삭제 |
| `top = mode(S)` | `mode` 도 열마다 최빈값. 열 안에 같은 값이 없으면 **가장 작은 값** (3.5) | 조용히 틀린 값 `65 72 70` (1×3) | `mode(S(:))` 또는 `mode(S, "all")` → `72` |
| `sdStu = std(S, 2);` (인수) | `std` 의 두 번째 인수는 정규화(0 또는 1) 또는 가중치 벡터. 차원은 **세 번째** (3.5) | **실행 오류**: 가중치는 0, 1 또는 길이가 맞는 벡터여야 함 | `std(S, 0, 2)` |
| `sdStu = std(S, 2);` (`;`) | 위를 고쳐도 `;` 때문에 안 보인다 | 화면에 안 나옴 | `;` 삭제 |
| `var(S, 1)` | **오류 아님**. 1 은 차원이 아니라 "N 으로 나누라"는 정규화 옵션. 열마다 모집단 분산이 의도와 같다 | — | — |

## 문제 B16 🐞 sort 는 행을 지키지 않는다

`sort` 는 열마다 따로 정렬해 레코드를 깨뜨리고, 두 출력의 순서는 **값, 위치**이며, `fprintf` 는 인수를 열 순서로 한 줄로 늘어놓고 소비한다는 세 가지가 핵심이다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `ranked = sort(parts, 'descend');` | `sort` 는 **열마다 독립적으로** 정렬한다. 번호 열도 따로 내림차순이 된다 (3.5) | 조용히 틀린 값 `[105 10; 104 6.8; 103 4.7; 102 2.2; 101 1.5]` (105번이 10 kΩ 이 되어 버림) | `sortrows(parts, -2)` |
| `[idx, ohm] = sort(...)` | 첫 출력이 정렬된 **값**, 둘째가 원래 **위치** (3.5) | `idx` 에 `10 6.8 4.7 ...` 이 들어가 다음 줄 `parts(idx(1:3), 1)` 에서 **실행 오류**: 인덱스가 양의 정수가 아니거나 범위(5행)를 넘음 | `[ohm, idx] = sort(...)` |

## 문제 B17 🐞 난수 크기·구간과 1000개 출력

`rand(3)` 은 3개가 아니라 3×3, 구간 [a, b] 는 `a + (b−a)*rand`, 정규 분포는 `평균 + 표준편차*randn`, 그리고 `;` 없는 1000개 배열이 화면을 덮는 것이 핵심이다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `len = 50 + 0.2*randn(1000, 1)` | 문장 끝 `;` 가 없다 (2.2) | 오류는 없지만 **1000개 숫자가 화면을 덮는다**. 의도("찍을 필요 없음") 위반 | 끝에 `;` |
| `rand(3)` | 인수 하나는 정사각 **3×3** (3.6) | 9개짜리 행렬 | `rand(1, 3)` |
| `15 + 25*rand(...)` | 폭은 b − a = 10 이다. 25 를 곱하면 15~40 (3.6) | 조용히 틀린 구간 | `15 + 10*rand(1, 3)` |
| `randn(1, 500)*0.05 + 0.01` | `randn` 에 곱하는 수가 **표준편차**, 더하는 수가 **평균**이다. 둘이 바뀌었다 (3.6) | 평균 0.01, 표준편차 0.05 (음수 간격도 많이 나온다) | `0.05 + 0.01*randn(1, 500)` |
| `count = length(temp)` | 원본에서는 3×3 행렬의 `length` 가 가장 큰 차원 **3** 이라 기대값과 우연히 같아 **버그를 숨긴다**. 원소 수는 `numel` (3.5). `temp` 를 고치면 결과는 맞다 | 원본도 `count = 3` | 개수를 셀 때는 `numel(temp)` 권장 |
| `die = randi(6, 1, 10);` | **오류 아님**. `randi(최댓값, 행, 열)` 로 1~6 정수 1×10. 화면에 보이라는 요구가 없으므로 `;` 도 맞다 | — | — |
| `[n, m] = size(len);` | **오류 아님**. 두 출력으로 받으면 `n = 1000`, `m = 1`. `n` 만 써도 된다 | — | — |
| `rng(0)` | **오류 아님**. 시드를 고정해 실행할 때마다 같은 난수가 나온다 | — | — |

원본은 끝까지 실행되며 화면에는 `len =` 아래 1000줄, `temp =` 아래 3×3 행렬(15~40 사이 값), `count = 3`, `avgLen = 50.00xx` 쯤이 차례로 나온다. `die`, `gap`, `n`, `m` 은 `;` 때문에 보이지 않는다. 오류 메시지가 하나도 없고 `count` 도 3 으로 맞아 보이므로 **화면에 찍힌 `temp` 의 모양과 값 범위**를 직접 확인해야 잡히는 문제다.

## 문제 B18 🐞 i 를 덮어쓴 복소수 계산

`i` 를 전류 변수로 쓰는 순간 `X*i` 는 허수가 아니라 `4*2` 가 된다. 여기에 `angle` 의 단위, `'` 의 켤레 전치가 겹친다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `i = 2;` → `Z = R + X*i` | `i` 를 변수로 덮어써 허수 단위가 사라졌다 (3.7) | 조용히 틀린 값 `Z = 11` (실수). 이어서 `mag = 11`, `phase = 0`, `P = 121`, `V = 22` 가 모두 틀린다 | 전류를 `I` 로 바꾸고 `Z = R + X*1i` |
| `phase = angle(Z)` | `angle` 은 **라디안** (3.7) | 고친 `Z` 에서도 `0.9273` | `angle(Z)*180/pi` → `53.1301` |
| `Zs = [...]';` | `'` 는 **켤레** 전치. 허수부 부호가 뒤집힌다 (3.7) | 조용히 틀린 값 `3-4i; 1-2i; 2+1i` (`;` 라 화면에는 안 보임) | `.'` |
| `1+2j`, `2-1j` | **오류 아님**. 숫자에 붙은 `j` 는 리터럴이라 변수와 무관하다. 여기서는 `j` 를 덮어쓰지도 않았다 | — | — |
| `root = sqrt(-4)` | **오류 아님**. MATLAB 은 음수의 제곱근을 오류 없이 복소수 `0.0000 + 2.0000i` 로 준다 | — | — |
| `P = real(Z*Zc)` | **오류 아님**. Z·conj(Z) = \|Z\|² 이고 `real` 로 허수부 0 을 떼어 낸다 | — | — |

원본은 오류 없이 끝까지 돌며 `Z = 11`, `mag = 11`, `phase = 0`, `P = 121`, `root = 0.0000 + 2.0000i`, `V = 22` 를 찍는다. `root` 만 복소수로 맞게 나오는 이유는 `sqrt(-4)` 가 `i` 를 쓰지 않기 때문이다. 원인은 첫 줄 하나지만 증상은 다섯 줄에 퍼진다.

고친 코드:

```matlab
clear, clc

R = 3;  X = 4;                      % 저항, 리액턴스 (Ω)
Z = R + X*1i                        % 3 + 4i
mag = abs(Z)                        % 5
phase = angle(Z)*180/pi             % 53.1301 (도)
Zc = conj(Z);
P = real(Z*Zc)                      % 25
Zs = [Z, 1+2j, 2-1j].';             % 3+4i; 1+2i; 2-1i
root = sqrt(-4)                     % 2i
V = I*Z                             % 6 + 8i
```

## 문제 B19 🐞 NaN 찾기·format 은 표시만

`x == NaN` 은 항상 거짓, `format` 은 **표시만** 바꾸고 저장값은 그대로, `;` 는 `format long` 아래에서도 표시를 막는다, `intmax` 는 int32 최댓값이라는 네 가지가 핵심이다. 원본은 오류 없이 끝까지 돈다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `miss = find(R == NaN)` | NaN 은 자기 자신과도 같지 않다. 비교 결과가 전부 0 (3.9) | `miss = 1×0 empty double row vector` | `find(isnan(R))` → `2` |
| `avgR = mean(good);` | `format long` 은 표시 **형식**만 정한다. `;` 가 표시 자체를 막는다 (2.2, 3.5) | 화면에 **아무것도 안 나옴** | `;` 삭제 |
| `format bank` → `cost = avgR*1.234` | `format bank` 는 화면에 둘째 자리까지 **보여 줄 뿐** 값을 반올림하지 않는다 (3.5) | `cost` 는 `4.52` 로 보이지만 저장값은 `4.524666…`, 그래서 `total = 452.47` | `cost = round(avgR*1.234*100)/100` → `total = 452.00` |
| `top = intmax` | `intmax` 는 int32 최댓값 2147483647. double 의 최댓값은 `realmax` (3.8) | 조용히 틀린 값 `2147483647` (int32) | `realmax` → `1.7977e+308` |
| `volt ./ amp` | **오류 아님**. 0/0 은 `NaN`, 4/0 은 `Inf` 로 오류 없이 계산된다 | — | — |
| `cut = find(R == Inf)` | **오류 아님**. NaN 과 달리 `Inf == Inf` 는 참이다 | — | — |
| `R(~isnan(R) & R ~= Inf)` | **오류 아님**. 배열에는 `&` 를 쓴다(`&&` 는 스칼라 전용) | — | — |

원본 화면: `R = 5 NaN 3 Inf 3`, `miss` 는 빈 배열, `cut = 4`, `avgR` 은 안 보임, `cost = 4.52`, `total = 452.47`, `top = 2147483647`. `cost` 의 표시가 기대와 같아서 맞는 것처럼 보이지만, 다음 줄 `total` 에서 저장값이 반올림되지 않았다는 사실이 드러난다.

고친 코드:

```matlab
clear, clc

amp  = [0.5 0 0.5 0 0.25];            % A
R = volt ./ amp
miss = find(isnan(R))
cut = find(R == Inf)
good = R(~isnan(R) & R ~= Inf);
format long
avgR = mean(good)
format bank
cost = round(avgR*1.234*100)/100
total = cost*100
format short
top = realmax
```

```
     2

     4

   3.666666666666667


cost =

          4.52


total =

```

## 문제 B20 🐞 함수 이름을 변수로 덮어쓰기

`pi`, `mean` 을 변수로 만들면 이후 그 이름은 함수가 아니라 변수다. `mean` 은 **첫 대입 줄은 정상**이고 그 다음 호출부터 깨지며, 오류 메시지는 "인덱스" 문제처럼 보여 진짜 원인을 숨긴다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `help sqrt` | `help` 는 명령창에 요약 텍스트만 찍는다. HTML 문서 창은 `doc` (3.1) | 창이 뜨지 않고 명령창에 도움말 텍스트가 길게 찍힘 | `doc sqrt` |
| `pi = 3.14;` | 내장 상수 `pi` 를 변수로 가렸다 (3.9) | 조용히 틀린 값. 평균이 `4.877` 로 찍힘 (의도 4.880) | 줄 삭제 |
| `mean = mean(V);` | 오른쪽 `mean(V)` 는 아직 함수라 이 줄은 돌지만, 이후 `mean` 은 스칼라 변수가 된다 (3.9) | 다음 `mean(V)` 에서 문제 발생 | `avgV = mean(V);` |
| `V(V > mean(V))` | `mean` 이 변수라 `mean(V)` 는 인덱싱. `V` 가 1.57, 4.0192 … 라 정수 인덱스가 아니다 | **실행 오류**: 인덱스는 양의 정수 또는 logical 이어야 함 (원인이 함수 이름 덮어쓰기라는 말은 없다) | `V(V > avgV)` |
| `disp('Largest: %.3f m^3', max(V))` | `disp` 는 인수 하나만 받고 서식도 모른다 (7.2) | **실행 오류**: 입력 인수가 너무 많음 | `fprintf('Largest: %.3f m^3\n', max(V))` |
| `fprintf(...);` 끝 `;` | **오류 아님**. `fprintf` 뒤 `;` 는 아무 효과가 없다. 출력은 그대로 찍힌다 | — | — |
| `pi*r.^2*h` | **오류 아님**. `r.^2` 는 원소별 제곱, 스칼라 `pi`, `h` 와의 `*` 는 괜찮다 | — | — |

원본은 `help` 텍스트를 찍고 `Mean volume: 4.877 m^3` 를 출력한 뒤 `big` 줄에서 인덱스 오류로 멈춘다. 그 오류를 고치면 마지막 `disp` 에서 다시 멈춘다. 또 원본을 한 번 돌린 뒤에는 작업공간에 `pi = 3.14`, `mean` 변수가 남으므로, 고친 스크립트 첫 줄의 `clear` 가 반드시 필요하다.

고친 코드:

```matlab
clear, clc
doc sqrt                               % HTML 문서 창을 연다
r = [0.5 0.8 1.2];                     % 반지름 (m)
h = 2;                                 % 높이 (m)
V = pi*r.^2*h;                         % 부피 (m^3)
avgV = mean(V);                        % 평균 부피
fprintf('Mean volume: %.3f m^3\n', avgV);
big = V(V > avgV)                      % 평균보다 큰 부피
fprintf('Largest: %.3f m^3\n', max(V))
```

`doc` 창을 제외한 명령창 출력:

```
Mean volume: 4.880 m^3

big =

    9.0478

Largest: 9.048 m^3
```

## 문제 B21 🐞 자유 낙하 그래프와 세미콜론

`;`가 필요한 줄에는 없고, 결과를 보여야 하는 줄에는 붙어 있다. 그래프 함수 뒤 `;`는 아무 효과가 없다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `t = 0:0.01:10` | 대입 끝에 `;`가 없어 결과가 표시된다 | `t =` 다음에 **1001개 값**이 `Columns … through …`로 나뉘어 화면을 뒤덮는다 | `t = 0:0.01:10;` |
| `plot(d);` | 입력이 하나뿐이면 x 자리에 **인덱스 번호**가 들어간다 (5.1.1) | 가로축이 0~10 s가 아니라 1~1001 | `plot(t, d)` |
| 두 번째 `plot` 앞 | `hold on`이 없어 새 `plot`이 앞 그림을 지운다 (5.1.1) | 거리 곡선이 사라지고 속도 직선 하나만 남는다 | `hold on` 추가, 끝에 `hold off` |
| `xlabel(Time, s)` | 따옴표가 없어 `Time`, `s`를 변수로 읽는다 | **실행 오류**: 정의되지 않은 함수 또는 변수 `Time`. 이 줄에서 멈춘다 | `xlabel("Time (s)")` |
| `dmax = max(d);` | 화면에 보여야 할 값인데 `;`로 표시를 막았다 | Command Window에 아무것도 안 나온다 | `dmax = max(d)` |
| `plot(d);`, `title("Free fall");`, `grid on;` | **오류 아님**. 그래프 함수 뒤 `;`는 아무 효과가 없다. 막을 출력이 없으니 붙여도 되고 빼도 된다 | — | — |
| `plot(t, v, 'r--')` | **오류 아님**. 빨간 파선. 작은따옴표 char LineSpec도 받는다 | — | — |

실행 순서: 문법 오류는 없으므로 처음부터 돈다. `t`의 1001개 값이 화면을 덮고, 그림 창에는 인덱스 축 거리 곡선이 잠깐 그려졌다가 속도 직선으로 바뀐다. 제목까지 붙은 뒤 `xlabel` 줄에서 멈춘다. `xlabel`만 고치면 끝까지 돌지만, `legend`가 선 하나에 이름 두 개를 받아 남는 항목을 무시한다는 경고를 내고, `dmax`는 여전히 표시되지 않는다.

고친 코드:

```matlab
clear, clc, close all
g = 9.81;                         % m/s^2
t = 0:0.01:10;                    % s
d = 0.5*g*t.^2;                   % m
v = g*t;                          % m/s
plot(t, d)
hold on
plot(t, v, 'r--')
hold off
title("Free fall")
xlabel("Time (s)")
ylabel("d (m), v (m/s)")
legend("distance", "velocity")
grid on
dmax = max(d)
```

```
  490.5000

```

## 문제 B22 🐞 전력 곡선과 행렬 plot

`[ ]` 안의 `,`와 `;`를 헷갈렸다. 이를 고쳐도 `plot(X, Y)`는 **열 단위**로 그리므로 여전히 의도와 다르다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `Imat = [I, I, I];` | `,`는 옆으로 붙인다. 결과는 1×33. 3×11을 만들려면 `;`로 아래로 쌓아야 한다 (5.1.1) | 다음 줄 `plot(Imat, P)`에서 **실행 오류**: 벡터 길이가 맞아야 함(33은 `P`의 3도 11도 아님) | `Imat = [I; I; I];` |
| `plot(Imat, P, ...)` (`;`를 고친 뒤) | 같은 크기 행렬 둘을 주면 **열마다 선 하나**다. 3×11이니 열 11개, 즉 **점 3개짜리 선 11개** (5.1.1 column dominant) | 오류 없이, I = 0, 0.5, …, 5 자리마다 세로 선분 11개(각각 10I², 20I², 50I²를 잇는 선)가 그려진다. 범례 3개는 그중 앞 세 선분에 붙는다 | `plot(Imat', P', ...)` 또는 `plot(I, P, ...)` |
| `axis([0 1300 0 5])` | 순서는 `[xmin xmax ymin ymax]` (5.1.3). x와 y 범위를 바꿔 썼다 | x축 0~1300, y축 0~5. 곡선은 x ≤ 5 구간, y ≤ 5 구간에만 걸려 거의 보이지 않는다 | `axis([0 5 0 1300])` |
| `P = R' * I.^2;` | **오류 아님**. 3×1 × 1×11 = 3×11 **외적**이다. 행 k = R(k)·I² | — | — |
| `size(P)` | **오류 아님**. 확인용 출력이다. `ans =` 다음에 `3    11` | — | — |
| `"10 \Omega"`, `"P = I^2R"` | **오류 아님**. `\Omega`는 Ω, `^2`는 바로 뒤 한 글자 `2`만 위 첨자라 I²R이 된다 (5.1.3) | — | — |
| `plot(Imat, P, LineWidth = 1.5)` | **오류 아님**. `Name=Value`가 맨 뒤에 있다 | — | — |

실행 순서: `size(P)`가 `3 11`을 찍은 뒤 `plot` 줄에서 멈춘다. `;`로 고치면 오류는 사라지지만 세로 선분 11개가 나온다. 전치까지 고치면 곡선 3개가 나오고, 마지막으로 `axis` 순서를 고쳐야 곡선이 보인다.

고친 코드:

```matlab
clear; clc; close all

R = [10 20 50];                      % ohm
P = R' * I.^2;                       % W, 3x11
size(P)
plot(I, P, LineWidth = 1.5)          % x가 벡터면 길이 11이 맞는 방향(열)이 x, 행 3개가 선
legend("10 \Omega", "20 \Omega", "50 \Omega", Location = "northwest")
axis([0 5 0 1300])
xlabel("Current I (A)"), ylabel("Power P (W)")
title("P = I^2R")
grid on
```

```
ans =

     3    11

```

## 문제 B23 🐞 LineSpec과 Name=Value, hold off

LineSpec 문자 하나하나가 색·마커·선을 정한다. `Name=Value`는 맨 뒤에만 올 수 있고, `hold on`은 꺼야 한다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `plot(hr, TB, LineWidth = 2, 'g-.s')` | `Name=Value` 뒤에 위치 인수(LineSpec)가 왔다 (5.1.2) | **문법 오류**라 파일 전체가 실행되지 않는다: `=` 연산자 사용 불가, 이름-값 인수는 다른 입력 다음에 | `plot(hr, TB, 'g-.s', LineWidth = 2)` |
| `plot(hr, TA, 'b:*')` | black은 `k`, `b`는 blue (5.1.2) | 파란 점선 + 별 | `'k:*'` |
| `plot(hr, (TA + TB)/2, 'ro')` | 선 문자가 없으면 **마커만** 찍히고 선은 없다 (5.1.2) | 빨간 원 13개만 있고 실선이 없다 | `'r-o'` |
| `legend("B", "A", "mean", ...)` | 범례 이름은 **그린 순서**(A, B, mean)를 따른다 (5.1.3) | 오류 없이 A 선에 "B", B 선에 "A"라는 이름이 붙는다 | `legend("A", "B", "mean", ...)` |
| `exportgraphics` 다음 | `hold on`을 끄지 않았다 (5.1.1 "Don't Forget hold off") | A − B 선이 **기존 세 선 위에 겹쳐** 그려진다. 범례에는 이름 없는 `data4`가 자동으로 추가되고, 제목만 "A - B"로 바뀐다 | 앞에 `hold off` |
| `plot(hr, TA - TB, 'k', MarkerSize = 8)` | `'k'`에는 마커 문자가 없다. `MarkerSize`는 마커가 없으면 보이는 효과가 없다 | 오류 없이 검은 실선만 나오고 다이아몬드가 없다 | `'k-d'` |
| `sind(15*hr)`, `cosd(15*hr)` | **오류 아님**. `15*hr`는 도 단위이므로 `sind`/`cosd`가 맞다 | — | — |
| `"Location", "southwest"` | **오류 아님**. 옛 `'Name','Value'` 쌍 문법도 R2026a에서 동작한다. 섞어 써도 이름-값 쌍이 맨 뒤에만 오면 된다 | — | — |
| `exportgraphics(gcf, "sensors.png")` | **오류 아님**. 확장자가 있고 첫 인수가 figure(`gcf`)다 (5.7) | — | — |

실행 순서: 문법 오류 하나 때문에 그림도 파일도 하나도 만들어지지 않는다. 그 줄을 고치면 끝까지 돌지만 색·마커·범례가 틀린 그림이 저장되고, 이어서 A − B 선이 같은 축에 덧그려진다. `hold off`를 넣으면 새 `plot`이 축을 새로 만들면서 앞의 x축 이름도 지우므로, 두 번째 그림에서 `xlabel`을 다시 부르는 것이 맞다.

고친 코드:

```matlab
clear, clc, close all
hr = 0:2:24;                                  % h
TA = 20 + 5*sind(15*hr);                      % degC
TB = 18 + 3*cosd(15*hr);                      % degC
plot(hr, TA, 'k:*')
hold on
plot(hr, TB, 'g-.s', LineWidth = 2)
plot(hr, (TA + TB)/2, 'r-o')
hold off
legend("A", "B", "mean", Location = "southwest")
xlabel("Time (h)"), ylabel("T (^oC)")

exportgraphics(gcf, "sensors.png")

```

## 문제 B24 🐞 원·타원과 axis, TeX

`axis`에 범위를 네 개의 스칼라로 따로 주면 실행 오류가 난다. 그 줄만 고치면 나머지 세 오류는 **오류 메시지 없이** 그림만 틀린다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `'k.-'` | `.`는 **점 마커**, `-`는 실선. 일점쇄선(dash-dot)은 `-.` (5.1.2) | 타원이 검은 실선 위에 점 200개가 찍힌 모양 | `'k-.'` |
| `axis square` | 축 **상자**를 정사각형으로 만들 뿐, 데이터 간격을 같게 하지 않는다 (5.5) | 상자는 정사각형인데 x 범위가 y 범위보다 넓어 원이 **가로로 눌린 타원**처럼 보인다 | `axis equal` |
| `axis(-3.5, 3.5, -2, 2)` | 입력은 대괄호로 묶은 배열 **하나**여야 한다 (5.1.3). 스칼라 네 개는 각각 1원소 벡터로 해석된다 | **실행 오류**(벡터가 4, 6 또는 8개 원소여야 한다는 취지). 이 줄에서 멈춰 격자·범례·텍스트·제목이 붙지 않는다 | `axis([-3.5 3.5 -2 2])` |
| `ylabel("y_pos (m)")` | 중괄호가 없으면 `_` 뒤 **한 글자**만 아래 첨자 (5.1.3) | y 다음에 `p`만 아래 첨자, `os`는 보통 글자 | `"y_{pos} (m)"` |
| `text(1, 0, " r = 1")` | **오류 아님**. 순서가 `text(x, y, 문자열)`이고 좌표는 데이터 값 기준이다 | — | — |
| `"\leftarrow b = 1.5"` | **오류 아님**. `\leftarrow`는 TeX 화살표 ← | — | — |
| `title("x^2/a^2 + y^2/b^2 = 1")` | **오류 아님**. 위 첨자가 각각 한 글자(`2`)이므로 중괄호가 필요 없다 | — | — |
| `a = 3; b = 1.5;` | **오류 아님**. `;`가 같은 줄의 문장 구분자 겸 표시 억제 | — | — |

실행 순서: 원과 타원이 그려지고 `axis square`까지 적용된 뒤 `axis(...)` 줄에서 멈춘다. 대괄호를 넣어 고치면 끝까지 실행되고 Command Window에는 아무것도 나오지 않지만, 타원이 점 마커 실선이고, 원이 눌려 보이고, `pos`의 `p`만 아래 첨자다. 그림을 보고 판단해야 하는 문제다. `axis equal`과 `axis([...])`를 함께 쓰면 지정한 범위를 유지한 채 가로·세로 단위 길이가 같아진다.

고친 코드:

```matlab
clear, clc, close all
th = linspace(0, 2*pi, 200);
a = 3; b = 1.5;
plot(cos(th), sin(th), 'b-', a*cos(th), b*sin(th), 'k-.')
axis([-3.5 3.5 -2 2])
axis equal
grid on
legend("circle", "ellipse")
text(1, 0, " r = 1")
text(0, b, "\leftarrow b = 1.5")
title("x^2/a^2 + y^2/b^2 = 1")
xlabel("x_{pos} (m)"), ylabel("y_{pos} (m)")
```

그림: 파란 원이 원 그대로 보이고, 검은 일점쇄선 타원이 x −3.5~3.5, y −2~2 안에 들어간다.

## 문제 B25 🐞 칸을 합친 tiledlayout과 새 창

레이아웃 핸들을 받는 줄에 `;`가 없고, 전체 제목에는 핸들을 넘기지 않았다. 칸이 다 찬 뒤 `nexttile`을 또 불렀다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `L = tiledlayout(2, 3)` | 객체를 대입하면서 `;`가 없다 (5.2) | `L =` 다음에 TiledChartLayout **속성 목록**이 여러 줄 찍힌다. "아무것도 출력하지 않는다"는 요구 위반 | `L = tiledlayout(2, 3);` |
| `plot(t, 12)` | x가 벡터이고 y가 스칼라면 각 x 위치에 **점 하나짜리 선**이 따로따로 만들어진다. 기본 마커가 없으므로 보이지 않는다 | 오류 없이 j 칸이 **빈 축**처럼 보인다 | `plot(t, 12*ones(size(t)))` 또는 `yline(12)` |
| `title("Motion of a particle")` | 핸들 없이 쓰면 **현재 타일**(j 칸)의 제목이 된다 (5.2) | 레이아웃 전체 제목이 없고 j 칸 위에 "Motion of a particle"이 붙는다 | `title(L, "Motion of a particle")` |
| 마지막 `nexttile` | 2×3 = 6칸이 이미 다 찼다(x 3칸 + v, a, j) | **실행 오류**: 격자에 더 넣을 타일이 없다. 위상도는 그려지지 않는다 | `nexttile`을 지우고 `figure` |
| `nexttile([1 3])` | **오류 아님**. 칸 번호 없이 크기만 주면 다음 빈 칸(1번)부터 1행 3열을 차지한다 | — | — |
| `xlabel(L, "Time (s)")` | **오류 아님**. 레이아웃 핸들로 공통 x축 이름을 단다 (5.2 보강) | — | — |
| 시간 벡터 이름 `t` | **오류 아님**. 레이아웃 핸들 이름이 꼭 `t`일 필요는 없다. 여기서는 `L` | — | — |

실행 순서: 문법 오류는 없다. 먼저 `L =`의 속성 목록이 출력되고, x·v·a 칸은 정상, j 칸은 빈 축, 제목은 j 칸에 붙고, 공통 x축 이름까지 붙는다. 그다음 마지막 `nexttile`에서 멈춘다. `figure`로 고치면 Figure 2가 열리고 위상도가 그려진다.

고친 코드:

```matlab
clear; clc; close all
t = 0:0.05:4;                         % s
x = 2*t.^3 - 6*t.^2;                  % m
v = 6*t.^2 - 12*t;                    % m/s
a = 12*t - 12;                        % m/s^2
L = tiledlayout(2, 3);
nexttile([1 3])
plot(t, x), ylabel("x (m)"), grid on
nexttile
plot(t, v), ylabel("v (m/s)")
nexttile
plot(t, a), ylabel("a (m/s^2)")
nexttile
plot(t, 12*ones(size(t))), ylabel("j (m/s^3)")
title(L, "Motion of a particle")
xlabel(L, "Time (s)")
figure
plot(v, a), xlabel("v (m/s)"), ylabel("a (m/s^2)")
```

Command Window 출력은 없다. 그림: Figure 1에 위 줄 전체 x(t), 아래 줄 v·a·j(높이 12 수평선)와 전체 제목이 있고, Figure 2에 v–a 곡선이 있다.

## 문제 B26 🐞 막대·원그래프와 subplot 칸 수

`bar`의 인수 순서, `pie`의 합 1 미만 규칙, `[ , ]`와 `[ ; ]`의 차이, `subplot` 칸 수를 함께 묻는다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `bar(use24, month)` | `bar(x, y)`에서 첫 인수가 **위치**, 둘째가 **높이**다 (5.3.3) | 가로축 260~420 위치에 높이 1~6(월 번호)인 막대 6개 | `bar(month, use24)` |
| `pie(use24/10000)` | 합이 1보다 작으면 비율로 바꾸지 않고 값 그대로 쓴다 (5.3.3) | 합 0.1915이므로 원의 약 19%만 채워지고 나머지는 빈다 | `pie(use24)` (단위 변환은 비율에 영향 없음) |
| `bar([use23, use24])` | `,`로 이어 붙이면 1×12 **벡터**다. 그룹 막대는 행렬이어야 하고, 행 하나가 그룹 하나다 (5.3.3 그림: 2×5 배열 → 그룹 2개) | 그룹 없이 막대 12개가 한 줄로 선다. 막대 객체가 하나라 `legend`는 "2023"만 쓰고 남는 이름은 무시한다는 경고 | `bar(month, [use23; use24]')` (6×2 → 월마다 그룹 하나, 막대 2개) |

| `barh(month, use24), xlabel("kWh"), ylabel("Month")` | **오류 아님**. 가로 막대는 값이 **가로축**, 항목이 세로축이다 | — | — |
| `above = month(use24 > avg)` | **오류 아님**. logical 인덱싱으로 평균보다 큰 달 번호를 고른다 | — | — |

실행 순서: `avg`, `above`가 정상 출력된다. (1)은 축이 뒤바뀐 막대, (2)는 정상, (3)은 19%짜리 원, (4)는 막대 12개 + legend 경고가 그려진 뒤 `subplot(2, 2, 5)`에서 멈춘다. 그룹 막대를 `bar([use23; use24])`(2×6)로 고치면 **해마다** 그룹 하나(그룹 2개, 막대 6개씩)가 되어 여전히 의도와 다르다. 전치해서 6×2로 넘겨야 한다.

고친 코드:

```matlab
clear, clc, close all
month = 1:6;
use23 = [320 290 310 280 350 400];         % kWh
use24 = [300 310 295 260 330 420];         % kWh
avg = mean(use24)
above = month(use24 > avg)
tiledlayout(2, 3)
nexttile
bar(month, use24), xlabel("Month"), ylabel("kWh")
nexttile
barh(month, use24), xlabel("kWh"), ylabel("Month")
nexttile
pie(use24)
nexttile
bar(month, [use23; use24]'), legend("2023", "2024")
nexttile
bar(month, use24 - use23), title("Change")
```

```
  319.1667

     5     6

```

## 문제 B27 🐞 히스토그램 경계와 sprintf 제목

`edges`의 첫 경계를 빠뜨려 F 구간이 없어졌다. `%d`에 소수를 넘겨 제목이 지수 표기로 나오고, `>`와 `>=`를 헷갈렸으며, `;` 때문에 `nA`가 표시되지 않는다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `edges = [60 70 80 90 100];` | 경계가 n개면 구간은 n−1개 (5.3.4). 첫 경계 0이 없어 F 구간이 없다 | 막대 **4개**(2, 3, 3, 3). 58점은 어느 구간에도 들지 않아 빠진다(합 11명) | `[0 60 70 80 90 100]` |
| `xlabel(...), ylabel(...)` | 현재 타일(오른쪽)에만 붙는다 | 왼쪽 칸에는 축 이름이 없다 | 왼쪽 `histogram` 뒤에도 `xlabel`·`ylabel`. 또는 `xlabel(t, ...)`, `ylabel(t, ...)` |
| `sprintf("Exam: mean %d, std %d", m, s)` | `%d`에 정수가 아닌 값을 주면 `%e` 형식으로 바뀐다. `m = 79`는 정수라 그대로 | 제목 `Exam: mean 79, std 1.321844e+01` | `"Exam: mean %.1f, std %.1f"` |
| `nA = sum(score > 90);` | "90점 이상"은 `>=`. 90점이 빠진다 | `nA`가 3이 아니라 **2**. 텍스트도 `A: 2` | `score >= 90` |
| 같은 줄 끝 `;` | 표시해야 할 값의 표시를 막았다 | Command Window에 `nA =`가 안 나온다 | `;` 삭제 |
| `fprintf(...);` | **오류 아님**. `fprintf` 뒤 `;`는 출력을 막지 않는다. `mean = 79.0, std = 13.2`가 그대로 찍힌다 | — | — |
| `histogram(score, [5])` | **오류 아님**. `[5]`는 1×1, 즉 스칼라 5와 **완전히 같다**. 구간 개수 5로 해석된다. (교재 5.3.4 함정 문구가 `[5]`를 경계 벡터처럼 썼지만, 원소 하나짜리 대괄호는 스칼라다) | — | — |
| `title(t, sprintf(...))` | **오류 아님**. `t`가 레이아웃 핸들이므로 전체 제목이 된다 | — | — |
| 100점 | **오류 아님**. 마지막 구간만 양 끝을 포함하므로 100점은 90~100 구간에 든다 | — | — |

실행 순서: 오류 메시지 없이 끝까지 돈다. Command Window에는 `fprintf` 한 줄만 나오고 `nA`는 나오지 않는다. 그림에서는 오른쪽 막대가 4개, 왼쪽 칸에 축 이름이 없고, 제목 끝은 지수 표기, 텍스트는 `A: 2`다.

고친 코드:

```matlab
clear, clc, close all
score = [88 72 95 61 79 84 58 90 67 100 73 81];
m = mean(score); s = std(score);
fprintf("mean = %.1f, std = %.1f\n", m, s);
t = tiledlayout(1, 2);
nexttile
histogram(score, 5)
xlabel("Score"), ylabel("Students")
nexttile
edges = [0 60 70 80 90 100];
histogram(score, edges)
xlabel("Score"), ylabel("Students")
title(t, sprintf("Exam: mean %.1f, std %.1f", m, s))
nA = sum(score >= 90)
text(92, nA + 0.3, "A: " + nA)
```

```
mean = 79.0, std = 13.2
nA =

     3

```

## 문제 B28 🐞 로그 축, fplot, polarplot

익명 함수 안의 `^`, `fplot` 범위 형식, 함수 이름의 x/y, `polarplot` 인수 순서, 로그 축의 0·음수를 묻는다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `G = @(w) 1 ./ sqrt(1 + w^2);` | 벡터에 `^`는 행렬 거듭제곱이다 (5.3.6). 정의할 때는 오류가 없고 **호출할 때** 터진다 | `semilogy(w, G(w))` 줄에서 **실행 오류**: 거듭제곱하려면 정방 행렬이어야 함 | `w.^2` |
| `semilogy(w, G(w))` | 이름에 붙은 축이 로그다. 가로축을 로그로 하려면 `semilogx` (5.3.2) | 가로축은 선형, 세로축이 로그. 0.01~100 구간의 저주파가 왼쪽 끝에 뭉친다 | `semilogx(w, G(w))` |
| `fplot(G, 0.01, 100)` | 범위는 2원소 **배열** 하나다 (5.3.6) | **실행 오류**: 구간 입력이 잘못됨 | `fplot(G, [0.01 100])` |
| `polarplot(r, deg*pi/180)` | 순서는 `polarplot(theta, r)`, 각도가 먼저 (5.3.1) | 오류 없이 각도 0~1 rad(약 0°~57°) 범위를 반지름 0~2π로 오가는 엉뚱한 곡선. 8자 모양 방사 패턴이 아니다 | `polarplot(deg*pi/180, r)` |
| `semilogy(tt, y)` | 로그 눈금에는 0과 음수를 올릴 수 없다 (5.3.2) | 오류 없이 t = 0~4.5 구간만 그려진다. t = 5(y = 0)부터 뒤는 빠진다 | 요구 자체가 불가능하다. 전 구간이 필요하면 `plot(tt, y)`, 로그 축이 필요하면 y > 0 구간(`tt < 5`)만 그린다 |
| `deg*pi/180` | **오류 아님**. 도를 라디안으로 바꾸는 올바른 식 | — | — |
| `1 ./ sqrt(...)` | **오류 아님**. 분자가 스칼라라 `/`여도 되지만 `./`이 안전하다 | — | — |
| `logspace(-2, 2, 200)` | **오류 아님**. 10⁻²~10²를 로그 간격 200점으로 (5.3.2 보강) | — | — |

실행 순서: 첫 칸의 `G(w)`에서 바로 멈추므로 그림은 빈 첫 타일 하나뿐이다. `.^`로 고치면 첫 칸이 (틀린 축으로) 그려지고 `fplot` 줄에서 멈춘다. 범위를 배열로 고치면 끝까지 돌지만 극좌표 칸과 마지막 칸이 조용히 틀린다.

고친 코드:

```matlab
clear, clc, close all
G = @(w) 1 ./ sqrt(1 + w.^2);
w = logspace(-2, 2, 200);                 % rad/s
tiledlayout(2, 2)
nexttile
semilogx(w, G(w)), title("Gain (data)")
nexttile
fplot(G, [0.01 100]), title("Gain (fplot)")
nexttile
deg = 0:5:360;
r = abs(cos(deg*pi/180));
polarplot(deg*pi/180, r), title("Antenna pattern")
nexttile
tt = 0:0.5:10;
y = 5 - tt;
plot(tt, y), title("y = 5 - t")           % 0과 음수가 있어 로그 축 불가
```

그림: 첫 칸은 로그 가로축에서 1 근처를 평탄하게 가다 ω = 1 부근부터 떨어지는 곡선, 셋째 칸은 0°–180° 방향으로 잎이 난 8자 모양이다.

## 문제 B29 🐞 meshgrid 곡면과 colormap

`meshgrid`로 만든 행렬에 `^`를 썼고, `plot3`의 세 입력 길이가 다르다. `shading`과 `colormap`은 오류는 없지만 범위가 의도와 다르다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `Z = X.^2 - Y^2;` | `Y`는 21×41 행렬. `^`는 행렬 거듭제곱이라 정방 행렬이 필요하다 (5.4.2) | **실행 오류**: 정방 행렬이어야 함. 이 줄에서 멈춰 `size(Z)`도 안 나온다 | `Y.^2` |

| `plot3(..., LineWidth = 2)` | **오류 아님**. `Name=Value`가 맨 뒤 | — | — |

## 문제 B30 🐞 yyaxis 배터리 그래프와 저장

`linspace`의 셋째 인수는 간격이 아니라 **점 개수**다. 핸들 대입에 `;`가 없고, `exportgraphics`는 확장자가 필요하며, `clf`는 창을 닫지 않는다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `tmin = linspace(0, 60, 10);` | 셋째 인수는 점 **개수**. 10점(간격 6.67분)이 된다 (3장) | 데이터는 7개라 `h = plot(tmin, V, ...)`에서 **실행 오류**: 벡터 길이가 맞아야 함 | `0:10:60` 또는 `linspace(0, 60, 7)` |
| `h = plot(tmin, V, "-o")` | 핸들 대입에 `;`가 없다 | `h =` 다음에 Line 객체의 속성 몇 줄(Color, LineStyle, LineWidth, Marker 등)이 표시된다 | 끝에 `;` |
| `yyaxis right` … `yyaxis left` | 왼쪽·오른쪽을 바꿔 썼다 (5.3.5) | 전압이 오른쪽 축, 온도가 왼쪽 축. 범례는 **왼쪽 계열 → 오른쪽 계열** 순이라 온도 선에 "V", 전압 선에 "T"가 붙는다 | 전압 앞에 `yyaxis left`, 온도 앞에 `yyaxis right` |
| `exportgraphics(gcf, "battery")` | 확장자가 없으면 형식을 정할 수 없다 (5.7) | **실행 오류**. 표는 만들어지지 않는다 | `"battery.png"` |
| `clf` | 활성 창의 **내용만** 비운다. 창은 남는다 (5.1.1) | 빈 figure 창이 열린 채 끝난다 | `close all` |
| `sprintf("... %d min, drop %.2f V", ...)` | **오류 아님**. `tmin(end) = 60`은 정수라 `%d`가 맞고, `4.20 − 3.60`은 `%.2f`로 `0.60` | — | — |
| `table(tmin', V', T', VariableNames = [...])` | **오류 아님**. 열 벡터로 전치했으므로 7×3 표. `VariableNames = [...]` Name=Value도 R2026a에서 된다 | — | — |
| `"-o"`, `"-s"` | **오류 아님**. string LineSpec도 받는다 | — | — |

실행 순서: `yyaxis right`로 축만 만들어진 뒤 `h = plot` 줄에서 멈춘다. `tmin`을 고치면 `h`의 속성이 출력되고, 축이 뒤바뀐 그림과 범례가 그려진 뒤 `exportgraphics`에서 멈춘다. 확장자를 붙이면 `report = ` 다음에 `7×3 table`이 표시되고, `clf` 때문에 빈 창이 남는다.

고친 코드:

```matlab
clear, clc, close all
tmin = 0:10:60;                                % min
V = [4.20 4.05 3.95 3.88 3.80 3.71 3.60];      % V
T = [25 27 30 32 33 35 38];                    % degC
yyaxis left
h = plot(tmin, V, "-o");
ylabel("Voltage (V)")
yyaxis right
plot(tmin, T, "-s")
ylabel("Temperature (^oC)")
xlabel("Time (min)")
legend("V", "T")
title(sprintf("Battery test: %d min, drop %.2f V", tmin(end), V(1) - V(end)))
exportgraphics(gcf, "battery.png")
report = table(tmin', V', T', VariableNames = ["t_min" "V" "T"])
close all
```

Command Window에는 `report =`, `7×3 table`, 그리고 `t_min V T` 열 머리와 7행이 출력된다. 그림: 제목 `Battery test: 60 min, drop 0.60 V`, 왼쪽 축 전압(파랑), 오른쪽 축 온도(주황)가 `battery.png`로 저장된 뒤 창이 닫힌다.

> `saveas(gcf, "battery.png")`도 동작하지만 문서용으로는 `exportgraphics`가 권장된다 (5.7).

## 문제 B31 🐞 함수 파일 이름과 함수 안의 `clear`·`;`

함수 파일은 **파일 이름**으로 불리고, 함수 안의 `clear` 는 입력 인수를 지우며, 출력 변수는 정의줄에 적은 **그 이름**에 대입해야 한다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| 파일 이름 `beam_stress.m` ↔ `function ... beam_sigma(...)` | 파일 이름과 함수 이름이 다르면 MATLAB은 **파일 이름**으로 찾는다(6.1) | 스크립트 4행 `beam_sigma(F, A)` 에서 실행 오류: `beam_sigma` 은(는) 인식할 수 없는 함수 또는 변수. 1~3행만 실행됨 | 파일 이름을 `beam_sigma.m` 으로 바꾼다(또는 둘을 같은 이름으로 맞춤) |
| `clear` (함수 안) | 함수의 workspace 를 지운다. 방금 받은 **입력 `F`, `A` 가 사라진다**(6.1.6) | 실행 오류: `F` 인식할 수 없는 함수 또는 변수 | 줄 삭제. 함수 안에서는 `clear`·`clc` 를 쓰지 않는다 |
| `s = F ./ A` | 함수 안에서도 `;` 없는 줄은 결과를 표시한다 | 호출할 때마다 `s =` 와 Pa 값 세 개(5×10⁶, 10⁷, 2×10⁷)가 화면에 찍힘 | `s = F ./ A;` |
| `sigma_MPa = s / 1e6;` | 출력 변수 `sigma` 에 아무것도 대입하지 않았다(6.1) | 실행 오류: 출력 인수 `sigma` 가 호출 중에 설정되지 않음 | `sigma = s / 1e6;` |
| `max(sigma_MPa)` (스크립트) | 함수 안의 변수는 local. 호출이 끝나면 workspace 에 없다(6.1.6) | 실행 오류: `sigma_MPa` 인식할 수 없음. 그 직전의 세 줄은 이미 출력됨 | `max(sig)` |
| `function sigma = beam_sigma(F, A);` | **오류 아님**. 정의줄 끝 `;` 는 허용된다(비관용일 뿐) | — | `;` 를 빼는 것이 관례 |
| `fprintf('%4d ...', [F; sig])` | **오류 아님**. `F` 는 정수라 `%d` 가 그대로 정수로 찍히고, `[F; sig]` 로 행을 쌓아 열 우선 소비가 짝을 맞춘다(7.2.2) | — | — |

실행 순서: 이름 오류(4행) → 고치면 함수 안 `clear` 때문에 `F` 없음 → 그것을 지우면 `s =` 가 찍힌 뒤 `sigma` 미대입 오류 → 그것을 고치면 세 줄이 출력된 뒤 마지막 줄에서 `sigma_MPa` 없음. `s` 줄의 `;` 는 오류 메시지는 없지만 "중간값이 보이면 안 된다"는 목적을 어긴다.

고친 코드 (`beam_sigma.m`):

```matlab
function sigma = beam_sigma(F, A)
% BEAM_SIGMA  하중 F(N)와 단면적 A(m^2)로 응력(MPa)을 계산한다
s = F ./ A;
sigma = s / 1e6;
end
```

스크립트:

```matlab
clear, clc
F = [1000 2000 4000];       % N
A = 2e-4;                   % m^2
sig = beam_sigma(F, A);
fprintf('%4d N -> %6.2f MPa\n', [F; sig])
fprintf('Peak: %.2f MPa\n', max(sig))
```

```
1000 N ->   5.00 MPa
2000 N ->  10.00 MPa
4000 N ->  20.00 MPa
Peak: 20.00 MPa
```

## 문제 B32 🐞 다중 출력 받기와 출력 순서

출력이 여러 개인 함수는 `[R, H, T] = f(...)` 처럼 **대괄호**로 받아야 하고, 하나만 받으면 **첫 번째 출력**만 온다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `R, H = trajectory(v0, th);` | 쉼표는 문장 구분자다. `R` (표시)와 `H = trajectory(...)` 두 문장으로 해석된다(6.1.3) | 실행 오류: `R` 인식할 수 없는 함수 또는 변수. 4행에서 멈추고 아무것도 출력 안 됨 | `[R, H, T] = trajectory(v0, th);` |
| `H = (v0*sind(deg))^2/(2*g);` | `deg` 가 1×3 이라 `^` 는 행렬 거듭제곱(6.1) | 실행 오류: 거듭제곱의 밑이 정사각행렬이어야 함 | `.^2` |
| `T = trajectory(v0, th);` | 출력을 하나만 받으면 **첫 번째 출력 `R`** 이 온다. 이름 `T` 와 무관하다(6.1.3) | 조용히 틀린 값: `T` 에 사거리 `[79.45 91.74 79.45]` 가 들어감 | 줄 삭제(첫 줄에서 셋 다 받음) 또는 `[~, ~, T] = ...` |
| `fprintf(..., th, R, H, T)` | 배열을 따로 주면 `th` 를 다 쓰고 `R` 로 넘어간다(7.2.2) | 조용히 어긋난 출력. 첫 줄이 `30 deg: R =  45.0 m, H = 60.0 m, T = 79.45 s`, 둘째 줄의 `%2d` 에는 91.74 가 들어가 `9.174312e+01 deg` 처럼 지수 표기 | `[th; R; H; T]` |
| `R = v0^2*sind(2*deg)/g;` | **오류 아님**. `v0` 가 스칼라라 `^` 로 충분하고, `/g` 도 스칼라 나눗셈이다 | — | — |
| `sind(...)` | **오류 아님**. 각도가 도 단위이므로 `sin` 이 아니라 `sind` 가 맞다(3.4) | — | — |

실행 순서: 4행 실행 오류가 먼저 보인다. 고치면 함수 안 `^` 오류, 그것도 고치면 오류 없이 끝까지 돌지만 `T` 가 사거리로 덮이고 `fprintf` 짝이 어긋나 표가 엉망이 된다. 둘 다 오류 메시지가 없는 **조용한** 오류다.

고친 코드:

```matlab
clear, clc
v0 = 30;                     % m/s
th = [30 45 60];             % deg
[R, H, T] = trajectory(v0, th);
fprintf('%2d deg: R = %5.1f m, H = %4.1f m, T = %4.2f s\n', [th; R; H; T])

function [R, H, T] = trajectory(v0, deg)
g = 9.81;
R = v0^2*sind(2*deg)/g;
H = (v0*sind(deg)).^2/(2*g);
T = 2*v0*sind(deg)/g;
end
```

```
30 deg: R =  79.5 m, H = 11.5 m, T = 3.06 s
45 deg: R =  91.7 m, H = 22.9 m, T = 4.32 s
60 deg: R =  79.5 m, H = 34.4 m, T = 5.30 s
```

## 문제 B33 🐞 `nargin` 기본값 범위, `nargout`, 함수 안 `clc`, handle

기본값은 **인수 하나마다** `if nargin < k` 로 따로 채워야 하고, 요청 여부와 상관없이 첫 출력은 항상 대입해야 한다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `if nargout == 2 ... Q = ...` | `Q1 = pipe_flow(0.1)` 은 출력을 1개 요청(`nargout = 1`) → `Q` 를 만들지 않는다(6.1.5) | 실행 오류(스크립트 2행): 출력 인수 `Q` 가 설정되지 않음. 화면에는 아무것도 없음 | `if` 를 없애고 `Q = n * v * A;` 를 항상 계산 |
| `if nargin < 3` 안에 `v = 2;` 와 `n = 1;` | 입력이 2개(`nargin = 2`)여도 조건이 참이라 **받은 `v = 3` 을 2로 덮어쓴다**(6.1.5) | 조용히 틀린 값: `Q2 = 0.0157` (기대 `0.0236`) | `if nargin < 2, v = 2; end` 와 `if nargin < 3, n = 1; end` 로 분리 |
| `clc` (함수 안) | 호출될 때마다 Command Window 를 지운다 | 오류 없이 **앞서 표시된 `Q1`, `Q2` 가 다음 호출에서 지워진다**. `[Q4, A4] = ...` 호출 뒤에는 화면이 비어 있음 | 줄 삭제 |
| `fprintf(..., A)` | `A` 는 함수의 local 변수. 스크립트 workspace 에 있는 것은 `A4` 다(6.1.6) | 실행 오류: `A` 인식할 수 없음 | `A4` |
| `fplot(pipe_flow, [0.05 0.3])` | `@` 가 없으면 `pipe_flow` 를 **인수 없이 호출**한 결과를 넘기려 한다(6.4, 6.5) | 실행 오류: 입력 인수가 부족(`d` 가 없음) | `fplot(@pipe_flow, [0.05 0.3])` |
| `[Q4, A4] = pipe_flow(0.2);` | **오류 아님**. 값은 다음 줄 출력에 쓰므로 `;` 로 표시를 막은 것이 맞다 | — | — |

실행 순서: 2행 `nargout` 오류가 먼저 난다. 고치면 `Q1`, `Q2`, `Q3` 이 차례로 나오지만 `clc` 때문에 매번 앞의 것이 지워지고 `Q2` 는 틀린 값이다. 이어서 `A` 오류, 그다음 `fplot` 에서 입력 부족 오류.

고친 코드 (`pipe_flow.m`):

```matlab
function [Q, A] = pipe_flow(d, v, n)
% PIPE_FLOW  지름 d(m), 유속 v(m/s, 기본 2), 관 개수 n(기본 1)의 총 유량 Q와 단면적 A
if nargin < 2
    v = 2;
end
if nargin < 3
    n = 1;
end
A = pi*d.^2/4;
Q = n * v * A;
end
```

스크립트:

```matlab
clear, clc
Q1 = pipe_flow(0.1)
Q2 = pipe_flow(0.1, 3)
Q3 = pipe_flow(0.1, 3, 4)
[Q4, A4] = pipe_flow(0.2);
fprintf('Area of 0.2 m pipe: %.4f m^2\n', A4)
fplot(@pipe_flow, [0.05 0.3])
```

```
Q1 =

    0.0157


Q2 =

    0.0236


Q3 =

    0.0942

Area of 0.2 m pipe: 0.0314 m^2
```

그림: 지름 0.05~0.3 m 에서 `Q = 2·πd²/4` 포물선이 그려진다.

## 문제 B34 🐞 local function 위치, 바깥 변수, `global` 이름

스크립트의 local function 은 **파일 끝**에 와야 하고, 함수는 스크립트 변수를 볼 수 없으며, `global` 은 **같은 이름**으로 양쪽에서 선언해야 공유된다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `function P = heat_loss(dT) ... end` 가 2~5행 | 스크립트 안 함수 정의는 **모든 실행 코드 뒤**에 와야 한다(6.1, 6.2) | 파일 전체가 실행되지 않음(스크립트의 함수 정의는 파일 끝에 있어야 한다는 오류). `clear, clc` 조차 실행 안 됨 | 함수 블록을 파일 맨 끝으로 옮기고 `end` 로 닫는다 |
| `P = K_WALL * AREA * dT;` 의 `AREA` | 스크립트 변수는 함수 안에서 보이지 않는다(6.1.6) | 실행 오류: `AREA` 인식할 수 없는 함수 또는 변수 | `AREA` 를 입력 인수로 받는다: `heat_loss(dT, A)` |
| `global K_wall` ↔ 함수 안 `global K_WALL` | 이름은 대소문자를 구별한다. 함수 쪽 `K_WALL` 은 어디서도 값을 받지 않은 전역 변수라 **`[]`**(6.1.7) | 조용히 틀린 값: `[] * 25 * 15` 는 오류가 아니라 `[]`. `P` 가 빈 배열 | 양쪽 모두 `global K_WALL`, `K_WALL = 0.8;` |
| `P = heat_loss(15);` | 결과를 **표시**하는 것이 목적인데 `;` 로 표시를 막았다 | 오류도 출력도 없이 끝난다. 화면이 비어 있음 | `P = heat_loss(15, AREA)` (`;` 없음) |
| `global` 을 스크립트와 함수에 **두 번** 쓴 것 | **오류 아님**. 전역 변수는 쓰는 곳마다 선언해야 한다. 중복이 아니라 필수다(6.1.7) | — | — |

실행 순서: 처음엔 위치 오류로 아무것도 안 돈다. 함수를 끝으로 옮기면 `AREA` 오류. `AREA` 를 인수로 넘기면 오류는 없어지지만 `P = []` 이고, `;` 때문에 그것조차 보이지 않아 "잘 돈 것처럼" 보인다. `;` 를 빼야 비로소 `P = []` 가 드러나 `global` 이름 불일치를 의심하게 된다.

고친 코드:

```matlab
clear, clc
global K_WALL
K_WALL = 0.8;          % W/(m^2*K)
AREA = 25;             % m^2
P = heat_loss(15, AREA)

function P = heat_loss(dT, A)
global K_WALL
P = K_WALL * A * dT;
end
```

```
P =

   300

```

> 전역 변수 대신 `heat_loss(dT, A, K)` 처럼 열관류율도 입력으로 받는 편이 더 낫다(6.1.7: "거의 항상 입력 인수로 넘기는 편이 낫다").

## 문제 B35 🐞 익명 함수의 캡처·원소별 연산과 function function 인수

익명 함수는 **정의 시점의** `c` 를 박제하고, handle 에는 산술 연산을 할 수 없으며, `fzero`·`fminbnd`·`integral` 에는 **handle** 과 정해진 개수의 인수를 줘야 한다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `v = @(t) c*t*exp(-t/2);` (`*`) | `t` 가 벡터면 `t*exp(...)` 는 두 행 벡터의 행렬곱(6.4) | `fplot` 은 "배열 입력에서 예상과 다르게 동작" 경고를 내고, `integral` 행에서 실행 오류(행렬 곱의 내부 차원 불일치) | `c*t.*exp(-t/2)` |
| `c = 20;` 뒤에 `v` 정의, 그다음 `c = 25;` | 익명 함수는 **만들 때의** `c = 20` 을 복사해 둔다. 나중에 바꾼 25 는 반영 안 됨(6.4) | 조용히 틀린 값: 최대 속도와 거리가 0.8배(14.72, 76.77)로 작게 나오고 `t5` 도 달라진다 | `c = 25;` 를 `v` 정의 **앞**에 두고 `c = 20;` 삭제 |
| `neg = -v;` | function handle 에는 단항 `-` 같은 연산자가 정의되어 있지 않다(문제 25의 `f + 1` 과 같은 함정) | 실행 오류: `function_handle` 형식 피연산자에 연산자 `-` 를 쓸 수 없음 | `neg = @(t) -v(t);` |
| `fminbnd(neg, [0 10])` | 구간은 **두 개의 스칼라** `a, b` 로 준다(6.5) | 실행 오류: 입력 인수가 부족 | `fminbnd(neg, 0, 10)` |
| `fzero(v(t) - 5, 0.3)` | 첫 인수는 handle 이어야 한다. `v(t)` 는 변수 `t` 로 **지금** 계산하려 함(6.5) | 실행 오류: `t` 인식할 수 없는 함수 또는 변수 | `fzero(@(t) v(t) - 5, 0.3)` |
| `fplot(v, [0 10])`, `integral(v, 0, 10)` | **오류 아님**. `v` 자체가 이미 handle 이므로 `@` 를 또 붙이지 않는다. `@` 가 필요한 것은 `@pipe_flow` 처럼 **이름 있는 함수**를 넘길 때다 | — | — |

실행 순서: `fplot` 은 경고만 내고 그린다. 6행 `-v` 에서 첫 실행 오류. 고치면 `fminbnd` 인수 오류, 그다음 `integral` 의 `*` 오류, 그다음 `fzero` 의 `t` 오류. 전부 고쳐도 `c` 캡처 때문에 최대 속도·거리가 0.8배로 작게 나온다.

고친 코드:

```matlab
clear, clc
c = 25;
v = @(t) c*t.*exp(-t/2);                % m/s
fplot(v, [0 10])
neg = @(t) -v(t);
[tmax, vneg] = fminbnd(neg, 0, 10);
dist = integral(v, 0, 10)
t5 = fzero(@(t) v(t) - 5, 0.3)
fprintf('Max %.2f m/s at t = %.2f s\n', -vneg, tmax)
```

```
dist =

   95.9572


t5 =

    0.2237

Max 18.39 m/s at t = 2.00 s
```

그림: 0~10 s 에서 t = 2 에 봉우리(약 18.4 m/s)가 있는 곡선. (손 계산: 최대 `50/e`, 거리 `100 − 600e⁻⁵`.)

## 문제 B36 🐞 `input` 의 `"s"`, char 비교, `disp` 결합

`input` 은 친 것을 **식으로 계산**하므로 글자는 `"s"` 로, 숫자는 `"s"` 없이 받아야 하며, `disp` 는 인수 하나에 **문자열 하나**만 받는다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `name = input('Customer name: ');` | `"s"` 가 없으면 `Kim` 을 변수 이름으로 계산하려 한다(7.1) | 오류 메시지(`Kim` 인식할 수 없는 함수 또는 변수)가 뜨고 **같은 질문이 다시 나온다**. 따옴표를 쳐 주지 않으면 진행 불가 | `input('Customer name: ', "s")` |
| `kwh = input('Usage (kWh): ', "s");` | `"s"` 로 받으면 숫자도 **char `'350'`** 이다(7.1) | 조용히 틀린 값: `kwh * rate` 가 문자 코드 `[51 53 48]*120 = [6120 6360 5760]` | `"s"` 를 뺀다 |
| `if name == 'Park'` | char 끼리 `==` 는 글자별 비교. `'Kim'`(1×3)과 `'Park'`(1×4)는 길이가 달라 비교 불가(8장) | 실행 오류: 배열 크기가 호환되지 않음 | `name == "Park"` (한쪽이 string 이면 문자열 전체 비교) |
| `disp('Customer:', name)` | `disp` 는 인수를 하나만 받는다(7.2.1) | 실행 오류: 입력 인수가 너무 많음 | `disp("Customer: " + name)` |
| `disp(['Bill: ' bill ' won'])` | char 와 숫자를 `[ ]` 로 이으면 숫자가 **문자 코드**로 바뀐다(7.2.1) | 오류는 없지만 `Bill: ` 뒤에 코드 42000 번 글자 한 개가 찍혀 **깨진 글자** | `disp(['Bill: ' num2str(bill) ' won'])` |

실행 순서: 첫 `input` 이 계속 다시 묻는다. 사용자가 `'Kim'` 처럼 따옴표를 치면 넘어가지만, `kwh` 가 글자라 요금이 3원소 벡터가 되고, 6행에서 길이 다른 char 비교로 멈춘다. 그 뒤로 `disp` 두 줄의 오류가 차례로 드러난다.

고친 코드:

```matlab
clear, clc
name = input('Customer name: ', "s");       % Kim
kwh  = input('Usage (kWh): ');              % 350
rate = 120;                                 % 원/kWh
bill = kwh * rate;
if name == "Park"
    bill = bill * 0.9;
end
disp("Customer: " + name)
disp(['Bill: ' num2str(bill) ' won'])
```

```
Customer name: Kim
Usage (kWh): 350
Customer: Kim
Bill: 42000 won
```

## 문제 B37 🐞 `;` 로 막을 수 없는 출력과 `fprintf` 서식

`;` 는 **대입·식의 결과 표시**만 막는다. `fprintf` 가 찍는 글자는 `;` 와 상관없이 나오고, 행렬은 **열 우선**으로 소비된다.

실제 화면 출력:

```
data =

  101.0000   21.5000   45.0000
  102.0000   23.0000   52.0000
  103.0000   19.8000   38.0000

debug: 9 values
Sensor 101: 102 C, 103%
Sensor 2.150000e+01: 23 C, 1.980000e+01%
Sensor 45: 52 C, 38%
Average temp: 21.4 C, max hum: 
```

> **[확인 필요]** `data =` 행렬의 열 폭(공백 수).

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `data = [id' temp' hum']` | `;` 가 없어 대입 결과가 표시된다 | `data =` 와 3×3 행렬이 찍힘(기대 출력에 없음) | `data = [id' temp' hum'];` |
| `fprintf('debug: ...');` | 출력 함수 뒤 `;` 는 **아무 효과가 없다**(7.2.2) | `debug: 9 values` 가 그대로 찍힘 | 줄 삭제(또는 `%` 로 주석 처리) |
| `fprintf(..., data)` | 3×3 행렬은 열 우선으로 101 102 103 21.5 23 19.8 45 52 38 순서로 소비된다(7.2.2) | 첫 줄 `Sensor 101: 102 C, 103%` 처럼 짝이 어긋남 | `data'` (한 줄에 들어갈 값이 한 열에 모이게) |
| 온도 자리의 `%d` | 정수가 아닌 값에 `%d` 는 `%e` 로 바뀐다(7.2.2) | `2.150000e+01`, `1.980000e+01`. 23.0 은 정수라 `23` 으로 찍혀 `23.0` 도 안 됨 | `%.1f` |
| 마지막 `fprintf(..., mean(temp))` | 자리표시자 2개에 값 1개 → 값이 떨어진 자리에서 **멈춤**(7.2.2) | `Average temp: 21.4 C, max hum: ` 까지만 찍히고 줄바꿈도 없음 | `mean(temp), max(hum)` |
| `%d%%` | **오류 아님**. `%%` 는 퍼센트 기호 한 개를 찍는다. `%d` 뒤에 바로 붙여도 된다 | — | — |
| `id`, `hum` 자리의 `%d` | **오류 아님**. 정수 값이므로 `%d` 가 맞다 | — | — |

고친 코드:

```matlab
clear, clc
id   = [101 102 103];
temp = [21.5 23.0 19.8];                       % degC
hum  = [45 52 38];                             % 상대습도(%)
data = [id' temp' hum'];                       % 3x3 자료 행렬
fprintf('Sensor %d: %.1f C, %d%%\n', data')
fprintf('Average temp: %.1f C, max hum: %d%%\n', mean(temp), max(hum))
```

```
Sensor 101: 21.5 C, 45%
Sensor 102: 23.0 C, 52%
Sensor 103: 19.8 C, 38%
Average temp: 21.4 C, max hum: 52%
```

## 문제 B38 🐞 행 벡터 `table`, `title` 서식, `ginput(n)`, `%s` 에 숫자

`table` 에는 **열 벡터**를, `title` 에는 **`sprintf` 로 완성된 문자열**을 줘야 하고, `ginput` 은 개수를 주지 않으면 Enter 를 칠 때까지 기다린다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `VariableNames = ["Name" "Score" "Grade"]` | 변수는 2개인데 이름은 3개(7.2.4) | 실행 오류(5행): 변수 이름 개수가 변수 개수와 맞지 않음. 5행 전까지만 실행 | `["Name" "Score"]` |
| `table(name, score, ...)` | 입력이 **행 벡터**라 각 변수가 1×4 한 칸인 **1행 2열** 표가 된다(7.2.4) | 오류 없이 `disp(T)` 가 한 줄에 이름 넷, 점수 넷을 찍음 | `table(name', score', ...)` → **4행 2열** |
| `title("Class average = %.1f", avg)` | `title` 은 서식을 해석하지 않는다. 숫자 둘째 인수는 **부제목**이 된다(7.2.3) | 제목에 `Class average = %.1f` 가 글자 그대로, 그 아래 부제목 `79.5` | `title(sprintf("Class average = %.1f", avg))` |
| `[px, py] = ginput;` | 개수를 생략하면 **Enter 를 칠 때까지** 점을 계속 받는다(7.3) | 막대를 한 번 클릭해도 프로그램이 멈춘 것처럼 기다림. 여러 번 찍으면 `py` 가 벡터라 `Clicked:` 줄이 여러 개 | `ginput(1)` |
| `fprintf('Top: %s\n', max(score))` | `%s` 에 숫자를 주면 **문자 코드**로 해석. 92 는 역슬래시(7.2.2) | `Top: \` 가 찍힘 | `fprintf('Top: %s (%d points)\n', name(score == max(score)), max(score))` |
| `disp(T);` | **오류 아님**. `;` 는 `disp` 출력을 막지 않는다. `disp` 로 감싼 덕분에 `T =` 줄 없이 표만 나온다 | — | — |
| `text(1:4, score + 2, "" + score)` | **오류 아님**. `"" + score` 는 1×4 string 배열 `["78" "92" "85" "63"]` 이라 막대마다 한 개씩 붙는다 | — | — |

실행 순서: 5행 이름 개수 오류가 먼저. 이름을 고치면 1행짜리 표가 찍히고 그림이 그려지지만 제목이 서식 문자열 그대로다. 이어서 `ginput` 이 Enter 를 기다리고, 마지막 줄은 `Top: \` 로 끝난다.

고친 코드:

```matlab
clear, clc, close all
name  = ["Ann" "Ben" "Cho" "Dan"];
score = [78 92 85 63];
avg = mean(score);
T = table(name', score', VariableNames = ["Name" "Score"]);
disp(T);
bar(score)
title(sprintf("Class average = %.1f", avg))
text(1:4, score + 2, "" + score)
ylabel("Score")
[px, py] = ginput(1);                 % 막대 하나를 클릭
fprintf('Clicked: %.1f\n', py)
fprintf('Top: %s (%d points)\n', name(score == max(score)), max(score))
```

```
    "Ann"     78  
    "Ben"     92  
    "Cho"     85  
    "Dan"     63  

Clicked: (클릭한 높이)
Top: Ben (92 points)
```

> **[확인 필요]** 표의 열 폭(공백 수).

그림: 막대 4개, 제목 `Class average = 79.5`, 막대 위에 점수.

## 문제 B39 🐞 `save` 함수형, `fopen` 모드, `fid` 위치, `fclose`, `-ascii` 의 `load`

`save` 함수형에는 변수 **이름**을 글자로 주고, 파일에 쓰려면 `'w'` 로 열어 `fid` 를 `fprintf` 의 **첫** 인수로 준 뒤 `fclose` 로 닫는다. `-ascii` 파일을 `load` 하면 **파일 이름**이 변수가 된다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `save('temps', T)` | 함수형에서는 변수 **이름**을 문자열로 준다. `T` 는 숫자 배열이다(2.5) | 실행 오류(4행): 인수가 문자형이어야 함. 1~3행만 실행 | `save('temps', 'T')` 또는 `save temps T` |
| `fopen('report.txt', 'r')` | `'r'` 은 읽기 모드. 없는 파일이라 열기 실패 → `fid = -1`(7.2.2) | 오류 없이 `fid = -1` | `'w'` (새로 쓰기. `'a'` 면 실행할 때마다 이어 붙음) |
| `fprintf('...', [hour; T], fid)` | `fid` 는 **첫 인수**여야 한다. 끝에 두면 그냥 데이터 하나가 된다(7.2.2) | 파일이 아니라 **화면**으로 출력되고, 마지막에 `-1` 이 데이터로 찍힘 | `fprintf(fid, '...', [hour; T]);` |
| 서식 끝 `/n` | 줄바꿈은 `\n`. `/n` 은 글자 그대로 찍힌다(7.2.2) | 모든 줄이 한 줄에 `/n` 으로 이어 붙음 | `\n` |
| `fclose(fid)` 없음 | 슬라이드가 요구하는 세 단계(열기·쓰기·닫기)의 마지막을 빠뜨림(7.2.2) | 파일 내용이 끝까지 기록되지 않을 수 있고 파일이 계속 열려 있음 | `fclose(fid);` (`;` 없으면 `ans = 0` 이 찍힌다) |
| `load logT.txt` 뒤 `mean(T)` | `-ascii` 파일에는 변수 이름이 없어 **파일 이름 `logT`** 가 변수가 된다. `T` 는 방금 지웠다(2.5) | 실행 오류: `T` 인식할 수 없는 함수 또는 변수 | `avg = mean(logT)` |
| `save logT.txt T -ascii` | **오류 아님**. 명령형에서는 파일·변수·옵션을 공백으로 나열한다 | — | — |
| `fprintf(...);` 의 `;` | **오류 아님**. 효과가 없을 뿐 해롭지도 않다 | — | — |

4행을 고친 뒤 화면 출력(7행, 한 줄로 이어짐; 끝에 줄바꿈 없음):

```
 0:00  17.9 C/n 3:00  18.4 C/n 6:00  21.0 C/n 9:00  24.6 C/n12:00  25.3 C/n-1:00 
```

`[hour; T]` 의 값 10개 뒤에 `fid = -1` 이 11번째 값으로 붙어 `%2d` 에 `-1` 이 들어가고, `%5.1f` 자리에서 값이 떨어져 멈춘다. 그 뒤 10행에서 `T` 오류가 난다.

## 문제 B40 🐞 함수 본문의 `;`, 쉼표 구분자, `[ ]` 안의 `;`

함수 안이든 밖이든 `;` 없는 대입은 **그 변수 이름으로** 표시되고, `,` 는 결과를 보이는 구분자이며, `[ ]` 안의 `;` 는 행을 나눈다.

실제 화면에 나오는 순서: `P =` 1000 → `years =` 열 벡터 → (함수 안) `rate =` 0.0500 → (함수 안) `A =` 3×1 → `disp(result)` 의 **6×1** 열 → (함수 안) `rate =` 0.0500 → (함수 안) `A =` 2.6533e+03.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `P = 1000, r = 5;` | `,` 는 구분자이지만 앞 문장의 결과를 **표시**한다(2장) | `P =` 와 `1000` 이 찍힘 | `P = 1000; r = 5;` |
| `years = [1; 5; 10]` | `;` 가 없어 대입 결과 표시 | `years =` 와 1, 5, 10 이 찍힘 | 끝에 `;` |
| `rate = r/100` (함수 안) | 함수 안에서도 `;` 없는 줄은 표시된다(6.1) | **호출할 때마다** `rate =` `0.0500` 이 찍힘(두 번) | `rate = r/100;` |
| `A = P*(1 + rate).^n` (함수 안) | 같은 이유 | 호출마다 함수 안의 `A =` 가 찍힘(3×1 한 번, 2.6533e+03 한 번) | `A = P*(1 + rate).^n;` |
| `result = [years; A];` | `[ ]` 안의 `;` 는 **행 구분**. 3×1 위에 3×1 을 쌓아 **6×1** 이 된다 | 조용히 틀린 모양: 기간과 원리금이 한 열에 이어짐 | `[years, A]` → 3×2 |
| `compound(P, r, 20);` | 결과는 `ans` 에 들어가지만 `;` 때문에 **표시되지 않는다** | 20년 값은 함수 안 `A =` 줄(오류 2) 덕분에 우연히 보일 뿐, 그것을 고치면 아무것도 안 보인다 | `A20 = compound(P, r, 20)` |
| `function A = compound(P, r, n);` | **오류 아님**. 정의줄 끝 `;` 는 허용된다 | — | — |
| `disp(result);` | **오류 아님**. `disp` 뒤 `;` 는 출력을 막지 않으며, 목적대로 행렬이 찍힌다 | — | — |
| `(1 + rate).^n` | **오류 아님**. `n` 이 벡터라 `.^` 가 맞다 | — | — |

두 버그가 서로를 가리는 점이 핵심이다. 함수 본문의 `;` 누락이 마지막 줄의 `;` 를 "보완"해 20년 값이 화면에 나오지만 이름이 `ans` 가 아니라 `A` 다. 함수 본문을 고치는 순간 20년 값이 사라지므로 마지막 줄도 함께 고쳐야 한다.

고친 코드 (`compound.m`):

```matlab
function A = compound(P, r, n)
% COMPOUND  원금 P, 연이율 r(%), n년 뒤 원리금 A (복리)
rate = r/100;
A = P*(1 + rate).^n;
end
```

스크립트:

```matlab

P = 1000; r = 5;                   % 원금(원), 연이율(%)
years = [1; 5; 10];                % 기간(년)
A = compound(P, r, years);
result = [years, A];               % 1열: 기간, 2열: 원리금
disp(result);
A20 = compound(P, r, 20)
```

```

    0.0010    1.0500
    0.0050    1.2763
    0.0100    1.6289


A20 =

   2.6533e+03

```

> **[확인 필요]** `disp` 가 공통 지수 `1.0e+03 *` 를 쓸 때의 앞뒤 빈 줄 개수.

## 문제 B41 🐞 관계·논리 연산자 표기

수학식 표기(`a ≤ x ≤ b`, `x > 30 & < 45`)와 C 문법(`!=`)을 MATLAB에 그대로 옮기면, 일부는 문법 오류가 되고 일부는 조용히 "전부 참"이 된다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `hot = T > 30 & < 45` | `&` 오른쪽에 피연산자가 없다. 비교는 매번 양쪽을 다 써야 한다 (8.1) | **문법 오류**. 파일 전체가 실행되지 않는다: "연산자 사용이 유효하지 않음"(4번째 줄) | `T > 30 & T < 45` |
| `moved = T != 22;` | MATLAB에 `!=`는 없다 (8.1) | **문법 오류**. 위를 고치면 이 줄(7번째)이 같은 메시지로 걸린다 | `T ~= 22` |
| `inRange = 20 <= T <= 30` | 왼쪽부터 `(20 <= T) <= 30`. 앞 결과가 0/1이라 언제나 30 이하 (8.1) | 조용히 틀림: `1 1 1 1 1 1 1`, 마지막 줄 `7 of 7 readings in range` | `20 <= T & T <= 30` |
| `warm = ~T <= 20` | `~`가 관계 연산자보다 먼저다. `~T`는 0이 아닌 원소를 전부 0으로 → `0 <= 20` (8.1) | 조용히 틀림: `1 1 1 1 1 1 1` | `~(T <= 20)` (또는 `T > 20`) |
| `out = xor(T < 20, T > 30)` | **오류 아님**. 두 조건이 동시에 참일 수 없으므로 "정확히 하나"(`xor`)와 "하나 이상"(`|`)이 같은 결과를 낸다 | — | — |
| `fprintf(..., sum(inRange), numel(T))` | **오류 아님**. logical의 `sum`은 참의 개수 | — | — |

문법 오류 두 개가 있으므로 원본은 아무것도 실행되지 않고, MATLAB은 먼저 만난 4번째 줄만 알려 준다. 그 줄을 고치면 7번째 줄의 `!=`가 걸리고, 둘 다 고쳐야 비로소 실행되는데 그때 `inRange`와 `warm`이 **오류 없이** 전부 1로 나온다. "실행됐다 = 맞다"가 아닌 대표 사례다.


## 문제 B42 🐞 `find`는 인덱스를 준다

`find`의 결과는 **값이 아니라 위치 번호**다. 이 사실을 잊으면 평균·출력·개수가 전부 조용히 틀린다. 게다가 보여 줘야 할 줄에는 `;`가 붙어 있다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `idx = find(P > 40);` | 의도는 `idx`를 보이는 것인데 `;`가 표시를 막는다 | 출력 없음. `idx`는 만들어지지만 화면에 안 나온다 | `idx = find(P > 40)` |
| `avgHigh = mean(idx)` | 인덱스 `[2;3;4;8]`의 평균을 구했다 (8.3) | 조용히 틀림: `avgHigh = 4.2500` | `mean(P(idx))` → `50.7500` |
| `fprintf('row %d, col %d\n', r, c)` | `fprintf`는 인수를 **r 전체 → c 전체** 순서로 소비한다. 짝이 깨진다 (8.3, 7.2.2) | `row 2, col 3` / `row 1, col 2` / `row 1, col 1` / `row 2, col 3`. 12 kW인 (1,1)까지 나온다 | `fprintf(..., [r c]')` |

## 문제 B43 🐞 logical 마스크의 자료형과 길이

logical indexing은 마스크가 **logical**이고 **대상 배열과 길이가 맞을 때**만 안전하다. double 0/1, 지운 뒤 다시 쓰는 옛 마스크, 원소가 하나 모자란 이름 배열이 모두 이 규칙을 어긴다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `good = len(keep)` | `keep`은 **double** `[1 1 0 0 1 0]`. 0을 "0번 원소"로 읽는다 (8.4) | **실행 오류**(4번째 줄): "배열 인덱스는 양의 정수이거나 논리값이어야 함". 이 줄 전까지만 실행 | `keep = logical([1 1 0 0 1 0]);` |
| `bad = len > 51 \| len < 49.5` | 의도는 표시하지 않는 것인데 `;`가 없다 | 화면에 `bad =`, `1×6 logical array`, `0 0 1 1 0 1`이 찍힌다 | 끝에 `;` |
| `avgBad = mean(len(bad))` | 바로 위에서 `len`이 3개로 줄었는데 6칸짜리 옛 마스크를 썼다. 4·6번째 참이 범위를 벗어난다 (8.4) | **실행 오류**: "인덱스가 배열 범위를 벗어남". `nGood = 3`까지는 찍힌 뒤 멈춘다 | 지우기 **전**에 평균을 구한다 |
| `labels = ["A" "B" "C" "D" "E"];` | 볼트는 6개인데 이름이 5개. `bad(6)`이 참이라 6번째 이름을 찾는다 | **실행 오류**(`fprintf` 줄): "인덱스가 배열 범위를 벗어남" | `"F"`를 추가 |
| `len(find(bad)) = [];` | **오류 아님**. `len(bad) = []`와 같은 원소를 지운다. `find`가 한 단계 더 거칠 뿐 | — | — |
| `fprintf('Rejected: %s\n', labels(bad))` | **오류 아님**(이름이 6개라면). 인수가 3개라 서식이 세 번 **재사용**되어 한 줄에 하나씩 찍힌다 | — | — |

원본은 4번째 줄에서 바로 멈춘다. `keep`을 고치면 `good`과 (원치 않는) `bad`가 표시되고, 지우기와 `nGood = 3`까지 간 뒤 `avgBad`에서 멈춘다. 순서를 바꾸면 마지막으로 이름 배열 길이 문제가 드러난다. "마스크를 만든 뒤 원본을 바꿨다면 마스크도 다시 만든다"가 핵심이다.

고친 코드:

```matlab
clear, clc

keep = logical([1 1 0 0 1 0]);
good = len(keep)
bad = len > 51 | len < 49.5;
avgBad = mean(len(bad))
labels = ["A" "B" "C" "D" "E" "F"];
fprintf('Rejected: %s\n', labels(bad))
len(find(bad)) = [];
nGood = numel(len)
```

## 문제 B44 🐞 `elseif` 순서와 경계, 배열 `if`

`elseif` 사슬은 **위에서 처음 참인 가지 하나**만 실행한다. 넓은 조건이 앞에 오면 뒤 가지는 죽고, 경계를 `>`로 쓰면 25가 어느 가지에도 들어가지 못한다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `error('Speed must be nonnegative, got' v)` | 함수 호출 괄호 안에서 공백은 인수 구분자가 아니다. 쉼표도 서식(`%g`)도 없다 (8.5.2, 7.2.2) | **문법 오류**: "예기치 않은 'v'". 파일 전체가 실행되지 않는다 | `error('Speed must be nonnegative, got %g', v)` |
| `elseif v < 25` 가 `elseif v < 15`보다 먼저 | 5 이상이면 전부 여기서 잡힌다. 아래 `v < 15` 가지는 영원히 실행되지 않는다 (8.5.3) | 조용히 틀림: `v = 9.0 m/s: gale` | `v < 15`(breeze)를 먼저, 그다음 `v < 25`(gale) |
| `elseif v > 25` | 25 정각이 어느 가지에도 안 들어가고 `else`도 없다 (8.5.3) | `v = 25`이면 `level`이 정의되지 않아 **실행 오류**(`fprintf` 줄): "'level'은 인식할 수 없는 함수 또는 변수" | `else` |
| `if gust >= 25; ...` | 배열 조건은 **모든** 원소가 참이어야 참. `[0 0 1 0]` → 거짓 (8.5.1) | 출력 없음. 27 m/s 돌풍이 있는데 경고가 안 나온다 | `if any(gust >= 25); ...` |
| `if ... ;` 의 `;` | **오류 아님**. 조건 뒤 `;`는 허용된다 | — | — |
| `fprintf(...);` 의 `;` | **오류 아님**. 출력 함수 뒤 `;`는 아무 효과가 없다. 출력은 그대로 찍힌다 | — | — |

원본은 문법 오류 때문에 아무것도 나오지 않는다. `error` 줄을 고치면 `v = 9.0 m/s: gale` 한 줄만 나오고 경고는 없다. 순서와 `else`, `any`까지 고쳐야 기대 출력이 된다.

고친 코드:

```matlab
clear, clc
v = 9;                             % m/s
gust = [12 18 27 9];               % m/s
if v < 0
    error('Speed must be nonnegative, got %g', v)
elseif v < 5
    level = "calm";
elseif v < 15
    level = "breeze";
elseif v < 25
    level = "gale";
else
    level = "storm";
end
fprintf('v = %.1f m/s: %s\n', v, level);
if any(gust >= 25); disp('Storm gust detected'), end
```

```
v = 9.0 m/s: breeze
Storm gust detected
```

## 문제 B45 🐞 `input`의 `"s"`, `| 'c'`, `else if`, char `==`

char 비교와 `input`은 "어떤 입력이 들어오느냐"에 따라 터지는 시점이 다르다. 실행 전, 입력 단계, 특정 답에서만 나는 오류를 나눠 봐야 한다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|

## 문제 B46 🐞 `menu`는 번호를 돌려준다

`menu`의 반환값은 **눌린 버튼의 번호(double)** 다. `case`에 이름을 쓰거나, `case 3, 4`로 두 값을 묶으려 하거나, C처럼 `break`를 쓰면 각각 다른 방식으로 망가진다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `break` | `switch`에는 fall-through가 없어 `break`가 필요 없고, loop 밖의 `break`는 쓸 수 없다 (8.5.4) | **문법 오류**: "BREAK는 FOR 또는 WHILE 루프 안에서만". 메뉴 창조차 뜨지 않는다 | 줄 삭제 |
| `case "Circle"` | `pick`은 숫자인데 string과 비교한다 (8.5.5) | **어느 버튼을 눌러도** 첫 `case`에서 실행 오류: "string과 double 간의 비교는 지원되지 않음" | `case 1` |
| `case 3, 4` | 쉼표는 `case` 식을 끝낸다. `4`는 `case 3` 블록의 **첫 문장**이 된다. 여러 값은 `{3, 4}`로 묶지만, 이 문제는 넓이 공식도 달라 `case 4`를 따로 둬야 한다 (8.5.4) | Triangle: `ans = 4`가 찍힌 뒤 `Triangle: 1.732 m^2`. Hexagon: 걸리는 `case`가 없어 `fprintf` 줄에서 "'A'은(는) 인식할 수 없는 함수 또는 변수" | `case 3`, `case 4` 따로 |
| `otherwise` 없음 | 창을 닫으면 `pick = 0`. 아무 `case`에도 안 걸린다 (8.5.5) | `A`가 없어 실행 오류. "No shape selected"가 나오지 않는다 | `otherwise, error("No shape selected")` |
| `case 2;` | **오류 아님**. `case` 식 뒤 `;`는 허용된다 | — | — |
| `shapes(pick)` | **오류 아님**(1~4일 때). string 배열에서 번호로 이름을 꺼낸다. 0이면 인덱스 오류지만 `otherwise`의 `error`가 먼저 멈춘다 | — | — |

고치는 순서대로 보면 이렇다. `break`를 지우면 메뉴가 뜨지만 어느 버튼이든 `"Circle"` 비교에서 멈춘다. 그것을 고치면 Square와 Triangle은 넓이가 나오지만 Triangle에는 `ans = 4`가 섞이고, Hexagon과 창 닫기는 `A`가 없다는 오류로 끝난다.

고친 코드:

```matlab
clear, clc
shapes = ["Circle", "Square", "Triangle", "Hexagon"];
pick = menu("Choose a shape", shapes);
a = 2;                                   % m
switch pick
    case 1
        A = pi*a^2;
    case 2;
        A = a^2;
    case 3
        A = sqrt(3)/4*a^2;
    case 4
        A = 3*sqrt(3)/2*a^2;
    otherwise
        error("No shape selected")
end
fprintf('%s: %.3f m^2\n', shapes(pick), A)
```

버튼별 출력: `Circle: 12.566 m^2`, `Square: 4.000 m^2`, `Triangle: 1.732 m^2`, `Hexagon: 10.392 m^2`. 창을 닫으면 `No shape selected` 오류로 멈춘다.

## 문제 B48 🐞 성적 처리 종합

`=` 두 개가 서로 다른 오류가 된다. `=>`는 문법 오류지만, 인덱스 안의 `scores = max(scores)`는 R2026a에서 **이름=값 인수**로 해석되어 실행 오류다. 그 뒤로 `&&` 배열, `switch` 범위 `case`, logical `%d`가 차례로 나온다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `pass = scores => 70;` | `>=`를 `=>`로 뒤집어 썼다. MATLAB에 `=>` 연산자는 없다 (8.1) | **문법 오류**(13번째 줄): "'=' 연산자를 잘못 사용". 아무것도 실행되지 않는다 | `scores >= 70` |
| `top = names(scores = max(scores))` | 괄호 안 `이름 = 값`은 Name=Value 문법이라 `names("scores", 99)`가 된다 (8.1) | **실행 오류**(4번째 줄): "string 유형의 값은 인덱스로 사용할 수 없음". `top`도 안 찍힌다 | `scores == max(scores)` |
| `if top == "Jung" && scores > 60` | `scores > 60`은 1×6. `&&`는 스칼라 전용 (8.1). 앞이 참이라 뒤를 계산하다 걸린다(앞이 거짓이었다면 short-circuit으로 오류가 숨는다) | **실행 오류**: "&&, \|\|의 피연산자는 논리형 스칼라여야 함". `top = "Jung"`까지 찍힌다 | `&& all(scores > 60)` |
| `case s >= 90` / `case s >= 80` | `case` 식이 0/1로 계산된다. 85는 0과도 1과도 같지 않다 (8.5.4) | 조용히 틀림: `Park scored 85: C` | `if/elseif/else`로 |
| `fprintf('%d of %d passed\n', pass, ...)` | logical 배열 6개가 그대로 인수가 된다. 인수 7개를 서식 2칸씩 재사용 (7.2.2) | `1 of 1 passed` / `1 of 0 passed` / `1 of 1 passed` / `6 of `에서 멈춤(줄바꿈 없음) | `sum(pass)` |
| `bar(...), ..., title(...)` | y축 이름 누락 (5.1.1) | 축 이름 없는 막대그래프 | `ylabel('Score')` |
| `otherwise,    grade = "C";` | **오류 아님**. `otherwise` 뒤 `,`로 같은 줄에 문장을 둘 수 있다 | — | — |

시험에서 "`=`는 언제나 문법 오류"라고 쓰면 틀린다. 조건문 `if x = 3`이나 `v(end) = ...`처럼 왼쪽이 이름 하나가 아니면 문법 오류이고, `f(name = 값)` 꼴은 이름=값 인수로 받아들여져 **실행할 때** 엉뚱한 오류가 난다.

고친 코드:

```matlab
clear, clc

names = ["Kim" "Lee" "Park" "Choi" "Jung" "Han"];

if top == "Jung" && all(scores > 60), disp("Jung leads, and everyone is above 60"), end

    grade = "A";
elseif s >= 80
    grade = "B";
else
    grade = "C";
end
fprintf('%s scored %d: %s\n', names(3), s, grade)
pass = scores >= 70;
fprintf('%d of %d passed\n', sum(pass), numel(scores))
bar(scores), xticklabels(names), title('Midterm scores'), ylabel('Score')
```

```
    "Jung"

Park scored 85: B
5 of 6 passed
```

그림: 막대 6개, x 눈금에 이름, 제목과 y축 이름 `Score`가 달린다.

## 문제 B49 🐞 local function과 `switch` 종합

`switch`에 **string 배열**을 넘기면 숫자 배열과 달리 오류가 나지 않고 **어느 `case`에도 맞지 않는다.** `otherwise`도 없으니 출력 `r`이 비어 오류가 난다. 메시지가 가리키는 곳(`r`)과 원인(`mats`)이 다르다는 점이 핵심이다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| `function r = density(mat)` … 끝 | 스크립트 안 local function은 `end`로 닫아야 한다. `switch`의 `end`만 있다 (6.2) | **문법 오류**: "스크립트의 모든 함수는 'end'로 닫혀 있어야 함". 아무것도 실행되지 않는다 | 파일 끝에 `end` 추가 |
| `rho = density(mats)` | 1×3 string 배열을 넘겼다. string 배열 `switch`는 어떤 `case`와도 같지 않다(숫자 배열이면 "SWITCH 식은 스칼라 또는 문자형 벡터여야 함" 오류) (8.5.4) | **실행 오류**: "출력 인수 `r`이 설정되지 않음". 아무것도 표시되지 않는다 | `density(mats(1))` |
| `otherwise` 없음 | 모르는 재료가 오면 `r` 미정의로 끝난다. 의도는 재료 이름을 알리는 `error` (8.5.4) | 위와 같은 "출력 인수 미설정" 오류. 원인을 알 수 없다 | `otherwise, error("Unknown material: %s", mat)` |
| `case "aluminum", "alu", r = 2700;` | 쉼표가 `case` 식을 끝낸다. `"alu"`는 블록의 첫 문장이다 (8.5.4) | 조용히 틀림: `"aluminum"`이면 `ans = "alu"`가 찍힌 뒤 2700. `"alu"`는 어느 `case`에도 안 맞는다 | `case {"aluminum", "alu"}` |
| `m = @(L) rho*L^3;` | `L`은 1×4 벡터. `^`는 행렬 거듭제곱 (6.4, 2.4) | **실행 오류**(`plot` 줄에서 `m(L)` 호출 시): "행렬을 거듭제곱할 수 없음". `rho = 7850`까지 찍힌다 | `L.^3` |
| `case 'copper'` | **오류 아님**. R2026a `switch`는 char와 string을 내용으로 비교한다 | — | — |
| `big = L(find(m(L) > 5, 1))` | **오류 아님**. 위치를 얻어 `L`에서 값을 꺼냈다 | — | — |

고쳐 가는 순서: `end`를 넣으면 실행되지만 `density` 안에서 "출력 인수 미설정"으로 멈춘다. 호출을 `mats(1)`로 고치면 `rho = 7850`이 찍히고 `m(L)`의 `^`에서 멈춘다. `.^`까지 고치면 끝까지 돈다. `"alu"`와 `otherwise` 문제는 이 스크립트의 steel 실행에서는 드러나지 않는 **잠복 오류**다.

고친 코드:

```matlab
clear, clc
mats = ["steel" "aluminum" "copper"];
rho = density(mats(1))
m = @(L) rho*L.^3;                       % kg, L in m
L = linspace(0.05, 0.2, 4);
plot(L, m(L)), xlabel('Side, m'), ylabel('Mass, kg')
big = L(find(m(L) > 5, 1))

function r = density(mat)
switch lower(mat)
    case "steel",              r = 7850;
    case {"aluminum", "alu"},  r = 2700;
    case 'copper',             r = 8960;
    otherwise
        error("Unknown material: %s", mat)
end
end
```

```

        7850

big =

    0.1000

```

질량은 0.98, 7.85, 26.49, 62.80 kg이므로 처음 5 kg을 넘는 L은 0.1 m다. 그림: 네 점을 잇는 꺾은선, 두 축 이름이 달린다.

## 문제 B50 🐞 전기 요금 종합

`any`/`all`의 기본 방향은 **열**(dim 1)이다. 요금 구간의 빈틈은 이 데이터(1420 kWh)에서만 터지고, 파일을 연 뒤 `fclose`가 없다.

| 줄 | 원인 | 현상 | 수정 |
|---|---|---|---|
| 13번째 줄 `end` | 짝이 없는 `end`. `if` 블록은 바로 위 `end`로 이미 닫혔다 (8.5.1) | **문법 오류**: "예약된 키워드 end의 사용이 적절치 않음". 아무것도 실행되지 않는다 | 줄 삭제 |
| `if fid <> -1, ...` | `<>`는 MATLAB 연산자가 아니다 (8.1) | **문법 오류**: "연산자 사용이 유효하지 않음". 위를 고친 다음에야 보인다 | `fid ~= -1` |
| `mon = any(use > 400, 1)` | dim 1은 **열마다**(가구마다). 달마다는 dim 2 (8.1, 3.5) | 조용히 틀림: 4×1 대신 `hh`와 같은 1×3 `0 1 1` | `any(use > 400, 2)` → `1;1;0;1` |
| `elseif tot > 1500` | 1200 초과 1500 이하 구간이 빠졌고 `else`도 없다. `tot = 1420`이 여기 걸린다 (8.5.3) | **실행 오류**(`fprintf` 줄): "'rate'은(는) 인식할 수 없는 함수 또는 변수". `hh`, `mon`은 이미 찍힌 뒤 | `else` |
| `fclose` 없음 | 슬라이드 규칙: `fopen`한 파일은 반드시 닫는다 (7.2.2) | 파일이 열린 채 남는다. 위 오류로 멈추면 `bill.txt`는 **빈 파일**로 생성되어 열린 채 남는다 | `fclose(fid);` |
| `hh = any(use > 400)` | **오류 아님**. 기본 dim 1 = 열마다 = 가구마다. 의도와 같다 | — | — |
| `fprintf(fid, ...);` | **오류 아님**. 파일로 쓰는 `fprintf` 뒤 `;`는 효과가 없고, 화면에는 원래 아무것도 안 나온다 | — | — |

MATLAB은 문법 오류를 **한 번에 하나만** 알려 준다. 원본에서는 13번째 줄 `end`만 보이고, 그것을 지우면 `<>`가 보인다. 둘을 고치면 `hh`와 틀린 `mon`이 찍힌 뒤 `rate`에서 멈춘다. 이때 `fopen`은 이미 실행되어 `bill.txt`는 0바이트이고 파일 식별자는 닫히지 않는다.

고친 코드:

```matlab
clear, clc
use = [180 220 410; 350 90 510; 260 300 120; 150 470 380];   % kWh
hh = any(use > 400)
mon = any(use > 400, 2)
```
