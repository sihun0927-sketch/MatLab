# exam/ — 지필 시험 대비 문제집

교수 공지: **슬라이드(PDF)에 나온 예제·예시 코드를 변형해서 출제**한다. 시험은 종이에 쓰는 지필평가다.
공지된 출제 형식 두 가지:

- **A형 [출력]** 코드를 보여주고, Command Window에 찍히는 결과를 그대로 쓰기.
- **B형 [코드]** Command Window 결과를 보여주고, 그 결과를 만드는 코드를 쓰기.
  세미콜론 유무가 채점 포인트다. 결과가 보이는 줄은 세미콜론이 없고, 안 보이는 줄은 세미콜론이 있다.

MATLAB으로 실행·검증하지 않는다. 종이 시험이므로 "머리로 실행한 결과"를 정확히 쓰는 연습이 목적이다.

## 레이아웃

```
exam/chXX/
  README.md        출제 범위 요약, 절별 문제 수, 원본 예제 색인표
  questions.md     문제만. 시험지 형식. 해답·힌트 없음
  answers.md       해답 + 해설 + 근거(textbook 절 링크)
```

`README.md`의 원본 예제 색인표는 슬라이드에 등장한 **모든** 코드 예제를 한 줄씩 적는다.

| 슬라이드 쪽 | 원본 코드 요지 | 절 | 변형 문제 |
| --- | --- | --- | --- |
| p.12 | `x = 1:5; y = x.^2` | 2.4 | Q02-07, Q02-08 |

이 표가 "슬라이드 예제를 하나도 빠뜨리지 않았다"는 증거다. 예제가 없는 슬라이드(개념 설명만)는 적지 않는다.

`.m` 파일은 만들지 않는다. `example/`, `textbook/`은 수정하지 않는다.

## 작업 흐름

1. 브랜치 `exam/chXX`에서 작업한다.
2. PDF를 끝까지 읽으며 코드 예제를 전부 색인표에 적는다. 쪽수를 반드시 기록한다.
3. `textbook/chXX/*.md`를 읽어 절 구성, `⚠️ 함정`, `[보강]`을 파악한다.
4. 색인표의 예제마다 변형 문제를 1개 이상 만든다. 함정 콜아웃은 [오류]나 [출력] 문제로 바꾼다.
5. `answers.md`에 Command Window 출력을 아래 "출력 규칙"대로 정확히 쓴다.
6. 검증: 아래 "검증"의 체크를 통과시킨다.
7. 커밋 후 PR을 만든다. 제목 `exam/chXX: <챕터 제목>`, base는 `main`. 머지는 사용자가 한다.

## 문제 유형

문제 머리에 유형 태그와 난이도(★, ★★, ★★★)를 붙인다.

| 태그 | 형식 | 비고 |
| --- | --- | --- |
| `[출력]` | 코드 → Command Window 출력을 그대로 쓰기 | A형. 세미콜론 있는 줄과 없는 줄을 섞는다 |
| `[코드]` | Command Window 출력 → 코드 쓰기 | B형. 해답은 "가능한 답 하나"와 세미콜론 배치 근거 |
| `[변형]` | 슬라이드 원본 코드에서 값·연산자·함수 하나를 바꾼 것 | 원본과 변형의 결과 차이를 묻는다 |
| `[오류]` | 실행하면 오류가 나는 코드 | 왜 나는지, 오류 메시지 첫 줄, 고치는 법 |
| `[빈칸]` | 코드 빈칸 채우기 | 출력이나 설명을 주고 빈칸을 채운다 |
| `[단답]` | 개념, 함수 이름, 연산자 우선순위, 창 이름 등 | 짧은 답. 서술형은 2~3문장 |

- 챕터당 **30~45문제**. 절마다 최소 3문제. `[출력]`과 `[코드]`가 합쳐서 전체의 **절반 이상**.
- 문제 번호는 `Q02-01`처럼 장-순번. 절 헤더(`## 2.4 …`)로 묶는다.
- 문제마다 `원본: p.NN` 표기로 어느 슬라이드 예제의 변형인지 적는다. 슬라이드 밖에서 만든 문제는 `원본: [보강]`.
- 변형 포인트는 출제자처럼 고른다: 값 바꾸기, `*`↔`.*`, `/`↔`./`, `^`↔`.^`, `;` 유무, `'` 전치, `:` 범위·간격, `linspace` 인자, 함수 인자 순서, `format` 변경, 조건문 경계값(`<` vs `<=`), `&`/`|`/`~` 결합, `end` 인덱스, 빈 배열, `ans` 재사용, 변수 이름 규칙, `disp`/`fprintf` 서식 지정자, 플롯 함수 인자 순서, 함수 정의의 입출력 개수.
- `questions.md`에는 답을 유추할 수 있는 주석이나 힌트를 넣지 않는다. 시험지처럼 쓴다.
- 한국어 본문, 코드·함수명·전문 용어는 영어 그대로(CLAUDE.md 규칙 준용).

## Command Window 출력 규칙

MATLAB을 돌리지 않으므로 아래 규칙으로 R2026a 기본 상태(`format short`, `format loose`)의 화면을 재현한다. `answers.md`의 출력은 빈 줄까지 포함해 실제 화면과 같게 쓴다.

```
>> x = 5
x =

     5

>> y = 3.14159
y =

    3.1416

>> v = [1 2 3]
v =

     1     2     3

>> w = [1.5 2.5]
w =

    1.5000    2.5000

>> M = [1 2; 3 4]
M =

     1     2
     3     4

>> 2 + 3
ans =

     5

>> c = 'abc'
c =

    'abc'

>> s = "abc"
s = 

    "abc"

>> t = 3 > 2
t =

  logical

   1

>> u = [1 2 3] > 2
u =

  1×3 logical array

   0   0   1

>> e = []
e =

     []

>> disp(5)
     5
>> disp('hi')
hi
>> fprintf('%d apples\n', 3)
3 apples
>> a = 1, b = 2; c = 3
a =

     1

c =

     3

```

- 정수 값 double은 폭 6으로 오른쪽 정렬(`     5`, `   123`). 소수는 소수점 아래 4자리, 폭 10(`    3.1416`).
- 한 배열에 정수와 소수가 섞이면 전부 소수 형식으로 찍힌다(`    1.0000    2.5000`).
- 크기 차이가 크면 `   1.0e+03 *` 같은 공통 지수 줄이 먼저 나온다.
- `char`는 작은따옴표, `string`은 큰따옴표로 표시되고 `string`은 `s = ` 뒤에 공백이 하나 붙는다.
- `logical` 스칼라는 `  logical` 줄이, 배열은 `  1×3 logical array` 줄이 먼저 나온다. 값 폭은 4다.
- `disp`는 변수 이름과 빈 줄 없이 값만 찍는다. `fprintf`는 `\n`이 없으면 줄을 바꾸지 않는다.
- 같은 줄에서 `,`로 구분한 명령은 결과를 보이고 `;`로 구분한 명령은 숨긴다.
- `format long`은 15자리(`3.141592653589793`), `format bank`는 소수 둘째 자리까지, `format short e`는 `3.1416e+00`.
- 오류는 `Error using …` 또는 `Unrecognized function or variable 'x'.` 같은 첫 줄을 쓴다. 전체 메시지는 몰라도 된다.
- 창 너비에 따라 `Columns 1 through 13`으로 나뉘는 긴 벡터는 문제로 내지 않는다.
- 자신이 없는 표시 형식은 해답에 `> **[확인 필요]** …`를 남긴다. 나중에 MATLAB에서 확인할 목록이 된다.

## 해답 형식 (`answers.md`)

~~~markdown
### Q02-07 [출력] ★★

원본: p.12 `x = 1:5; y = x.^2` → 변형: `.^`를 `^`로

```
Error using  ^ 
Incorrect dimensions for raising a matrix to a power. ...
```

- 벡터에 `^`를 쓰면 행렬 거듭제곱이라 정방 행렬이 아니면 오류다. 요소별은 `.^`.
- 근거: [2.4](../../textbook/ch02/2.4-array-calculations.md) ⚠️ 함정
~~~

- 원본 코드와 변형점을 첫 줄에 적는다.
- `[코드]` 해답은 코드 블록 뒤에 "어느 줄에 세미콜론이 없어야 하는가"를 한 줄로 적는다.
- 근거는 `textbook/chXX/` 절 링크로 적는다.

## 검증

MATLAB 실행은 하지 않는다. 대신 다음을 확인한다.

- `questions.md`의 문제 번호 집합과 `answers.md`의 번호 집합이 같다(`grep -o 'Q[0-9][0-9]-[0-9][0-9]'`로 비교).
- 모든 상대 링크의 대상 파일이 존재한다.
- README 색인표의 "변형 문제" 열에 적힌 번호가 전부 `questions.md`에 있다.
- 절마다 3문제 이상, `[출력]`+`[코드]`가 절반 이상.
