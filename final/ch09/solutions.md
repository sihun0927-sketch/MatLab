## 09-01 — 정답 ③

loop의 다섯 부분 중 셋째가 "pass마다 parameter를 바꾸는 방법"이다. 슬라이드는 이것이 없으면 loop가 영원히 멈추지 않는다고 강조한다.

- ① 반대다. `for`는 반복 횟수를 알 때, `while`은 기준이 만족될 때까지.
- ② midpoint break loop는 loop 안 명령을 최소 한 번은 실행해야 할 때 쓴다.
- ④ vectorized 해법이 가능하면 loop를 피한다. 더 빠르고 단계가 적고 읽기 쉽다.
- ⑤ 경험 법칙은 "세 번보다 많이 반복되면 loop 후보"다. 두 번이고, "반드시"도 아니다.

복습: [Chapter 9 도입](../../textbook/ch09/README.md)

## 09-02 — 정답 ④

loop는 양수만 더한다: 4 + 7 + 2 = 13. `x > 0`은 `[1 0 1 0 0 1]`, `x(x > 0)`은 `[4 7 2]`, 그 합이 13이다. 슬라이드가 loop 대안으로 든 logical indexing이다.

- ① `sum(x > 0)`은 참의 개수 3이다. 합이 아니라 개수.
- ② `find(x > 0)`은 위치 `[1 3 6]`이라 합은 10. 값이 아니라 인덱스를 더했다.
- ③ `sum(x)`=9에서 음수 개수 2를 뺀 7. 개수와 값을 섞었다.
- ⑤ `[4 7 2]` 벡터 자체다. 더하지 않았다.

복습: [Chapter 9 도입](../../textbook/ch09/README.md)

## 09-03 — 정답 ①

index array `[3, 1, 4]`의 원소 하나마다 한 번, 모두 3 pass.

- pass 1: `k = 3`, `total = 9`
- pass 2: `k = 1`, `total = 10`
- pass 3: `k = 4`, `total = 26`

loop가 끝나도 `k`는 마지막으로 쓴 값 4를 유지한다.

- ② `k`가 pass 횟수(3)가 되는 것이 아니다. index는 index array의 원소 값이다.
- ③ `k^2`가 아니라 `k`를 더한 값(3+1+4=8).
- ④ `total = k^2`처럼 덮어썼을 때의 값.
- ⑤ index가 마지막 값을 "넘어선" 값으로 남지 않는다. 남는 것은 마지막 원소 4.

복습: [9.1 for loop](../../textbook/ch09/9.1-for-loops.md)

## 09-04 — 정답 ②

`p = 4^k`는 인덱스 없이 대입하므로 pass마다 덮어쓴다: 4 → 16 → 64. loop 뒤 `p`는 1×1 스칼라 64다. 5행 `p(2)`는 존재하지 않는 원소라 인덱스 범위 오류가 난다. 배열이 필요했다면 `p(k) = 4^k`.

- ① `p`가 `[4 16 64]`라고 착각한 값. 그건 `p(k) = …`일 때다.
- ③ loop 안에서도 스칼라 대입은 문제없다. 다만 덮어쓸 뿐이다.
- ④ `p`는 64지만 `p(2)`는 없다. `p(1)`이었다면 64.
- ⑤ loop 안에서 만든 변수는 loop 뒤에도 남는다.

복습: [9.1 for loop](../../textbook/ch09/9.1-for-loops.md)

## 09-05 — 정답 ⑤

loop 결과는 `y = [1 7 17 31]`(2·1−1, 2·4−1, 2·9−1, 2·16−1). vectorize할 때 원소별 거듭제곱은 `.^`다. `2*k.^2 - 1`은 `k.^2 = [1 4 9 16]` → `[1 7 17 31]`.

- ① `k^2`는 행렬 거듭제곱이다. 1×4는 정사각 행렬이 아니라 오류.
- ② `(2*k).^2 - 1` = `[4 16 36 64] - 1` = `[3 15 35 63]`. 괄호 위치가 다르다.
- ③ `-1`이 빠져 `[2 8 18 32]`.
- ④ `2.*`로 바꿔도 `k^2`가 그대로라 ①과 같은 오류.

## 09-12 — 정답 ②

`for` loop 결과는 `b = [3 9 27]`. ②는 `k`를 loop 밖에서 0으로 초기화하고, 증가를 먼저 한 뒤 `b(k)`에 대입한다. `k`가 1, 2, 3일 때 대입하고 `k = 3`에서 `k < 3`이 거짓이 되어 끝난다. 슬라이드 while 배열 예제와 같은 순서다.

- ④ 증가 전에 대입해 첫 pass가 `b(0)`이다. 인덱스 0은 오류.
- ⑤ `k = 3`에서도 `k <= 3`이 참이라 한 번 더 돌아 `[3 9 27 81]`.

## 09-15 — 정답 ①

`continue`는 이번 pass의 나머지만 건너뛰고 다음 pass로 간다. 음수 두 개(`k = 2, 4`)의 pass에서 `s`, `c` 갱신이 생략되어 `s = 3 + 4 + 5 = 12`, `c = 3`.

- ③ `s`를 0으로 리셋한 뒤 음수까지 더한다. 추적하면 `s = 4, c = 5`.
- ④ 음수를 0으로 바꿔 더하므로 `s = 12`지만 `c = 5`.
- ⑤ 메시지만 찍고 그대로 더해 `s = 10, c = 5`.

## 09-16 — 정답 ⑤

`while (1)`은 기준이 항상 참이라 `break`로만 나간다. 계산 후 중간에서 탈출을 판단하는 midpoint break loop다.

- ② `count`는 맞게 셌지만 `x`를 한 단계 전 값으로 잡았다.
- ③ 한 번 더 돌았을 때의 값(100/256).
- ④ `while (1)`이지만 `break`가 있어 3 pass 후 빠져나간다.

## 09-17 — 정답 ③

`while(1)`은 가상의 비교 결과를 강제로 참으로 만든 무한 루프이고, 슬라이드는 이 loop를 빠져나가는 유일한 방법이 `break` 구조라고 한다. 그래서 반복 횟수를 제한하는 코드를 넣어 두라고 권한다.

- ① 반대다. 기준이 거짓이 될 때까지 반복한다. 슬라이드의 "기준이 만족될 때까지"는 종료 조건을 말한 것이고, `while` 첫 줄의 식은 참인 동안 계속 돈다.
- ② midpoint break 전략은 `for` loop와 `while` loop 어느 쪽에나 쓸 수 있다.
- ④ 컴퓨터에게는 0이 아닌 것은 모두 참이다. `while(5)`도 `while(1)`과 같이 무한 루프다.
- ⑤ `4 < 2`의 결과는 0이고, 0이 거짓이다.

## 09-18 — 정답 ②

슬라이드의 "`max`를 중첩 loop로 흉내 내기"를 최솟값으로 바꾼 것이다. 바깥 `k`가 열(3개), 안쪽 `j`가 행(2개).

- ③ 행별 최솟값. 행·열을 바꿔 생각했다.
- ④ `m(k)` 대입은 빈 변수를 행 벡터로 늘린다. 열 벡터가 아니다.
- ⑤ 배열 전체의 최솟값. 이 코드는 열마다 값 하나를 남긴다.

## 09-19 — 정답 ④

슬라이드: loop가 시간을 거의 다 쓴 단계는 `B`에 원소가 하나씩 추가되며 추가 메모리를 1,000,000번 할당하는 부분이다. 그래서 `B`를 먼저 만들어 두면(사전할당) 빨라진다.

- ① `clock`/`etime`은 경과 시간(elapsed time)을 잰다. 그 코드에 쓰인 시간을 재는 것은 `timeit`.
- ② 코드 앞뒤에 한 줄씩 두는 것은 `tic`/`toc`다. `timeit`은 잴 코드가 함수로 저장되어 있어야 한다.
- ③ `tic`/`toc`도 경과 시간이라 housekeeping(백그라운드 작업) 때문에 잴 때마다 다르다.
- ⑤ 슬라이드 HINT: 중간 계산을 화면에 출력하면 실행 시간이 크게 늘어난다. 세미콜론으로 억제한다.

## 09-20 — 정답 ①

`B = A;`는 `A`와 같은 500×500 임시 배열을 만들어 필요한 메모리를 한 번에 확보한다. loop는 그 자리의 값만 바꾼다. 슬라이드의 사전할당 방식 그대로다. R2026a에서는 Code Analyzer가 `clock`/`etime`을 권장하지 않는다고 표시하지만 실행은 된다.

- ② 스칼라라 loop가 `B`를 한 칸씩 계속 늘린다. 사전할당이 아니다.
- ③ 1×500만 확보한다. 원소는 250,000개라 501번째부터 다시 늘리며 재할당한다.
- ④ 빈 배열은 메모리를 확보하지 않는다. 사전할당이 없는 것과 같다.
- ⑤ `clear` 뒤라 `k`가 정의되지 않아 오류. 정의되어 있어도 스칼라 하나다.
