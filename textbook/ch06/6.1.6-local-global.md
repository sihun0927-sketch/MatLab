# 6.1.6–6.1.8 local 변수, global 변수, 함수 코드 열람

## 6.1.6 local variable — 함수는 자기완결적이다

함수 안에서 쓰는 변수는 전부 **local variable**이다. 함수가 바깥과 정보를 주고받는 통로는 딱 두 가지뿐이다.

- 들어오는 길: **입력 인수**
- 나가는 길: **반환값(출력)**

그 외에는 서로 볼 수 없다. **양방향 모두** 막혀 있다.

### 방향 ① 함수 안의 변수는 workspace에 남지 않는다

`elemprod`는 중간에 `a = x .* y`를 계산하지만, 호출이 끝나면 `a`는 사라진다.

[`example/ch06/ex0616_local_variables.m`](../../example/ch06/ex0616_local_variables.m):

```
호출 후 workspace 에 있는 변수:
out  x    y

exist('a', 'var') = 0  (0 = workspace 에 없음)
```

Workspace 창에는 `x`, `y`, `out`만 보인다. 함수 내부의 `a`는 어디에도 없다. command window에서 `a`를 쓰려 하면 오류가 난다.

### 방향 ② 함수는 workspace 변수를 볼 수 없다

반대도 마찬가지다. workspace에 `g_from_workspace = 9.81`이 있어도 함수 안에서는 보이지 않는다.

```matlab
g_from_workspace = 9.81;

function w = needs_gravity(m)
w = m * g_from_workspace;   % ← 여기서는 이 이름이 존재하지 않는다
end
```

```
예상된 오류: 'g_from_workspace'은(는) 인식할 수 없는 함수 또는 변수입니다.
```

필요한 값은 전부 입력으로 받아야 한다.

```matlab
function w = weight(m, g)
w = m * g;      % 필요한 값은 전부 입력으로 — 함수는 자기완결적이어야 한다
end
```

이 격리가 불편해 보이지만 큰 장점이다. 함수 안에서 `i`나 `temp` 같은 이름을 마음대로 써도 바깥 프로그램을 망가뜨리지 않는다.

## 6.1.7 global variable

`global`로 선언한 변수는 프로그램 어디서나 접근할 수 있다. **일반적으로 쓰지 않는 것이 좋다.** MATLAB은 실수로 쓰는 것을 막기 위해 **양쪽 모두에서 선언**할 것을 요구한다.

- 호출하는 쪽(command window 또는 스크립트)에서 `global 이름`
- 그 값을 쓰는 함수 안에서도 `global 이름`

둘 중 하나라도 빠지면 공유되지 않는다.

[`example/ch06/gravity_force.m`](../../example/ch06/gravity_force.m):

```matlab
function F = gravity_force(m)
% GRAVITY_FORCE  질량 m(kg)에 작용하는 중력(N)을 계산한다.
global G_ACCEL
...
F = m * G_ACCEL;
end
```

[`example/ch06/ex0617_global.m`](../../example/ch06/ex0617_global.m):

```matlab
global G_ACCEL

G_ACCEL = 9.81;    fprintf('지구  : %6.2f N\n', gravity_force(70));
G_ACCEL = 1.62;    fprintf('달    : %6.2f N\n', gravity_force(70));
G_ACCEL = 3.71;    fprintf('화성  : %6.2f N\n', gravity_force(70));
```

```
지구  : 686.70 N
달    : 113.40 N
화성  : 259.70 N
```

함수를 고치지 않고, 인수로 넘기지도 않고 값만 바꿔가며 쓸 수 있다는 것이 장점이다.

**관례**: 전역 변수는 **대문자**로 쓴다(`G_ACCEL`). 코드를 읽는 사람이 "이건 어디서 바뀔지 모르는 값"임을 바로 알아채게 하기 위해서다.

**왜 나쁜 생각인가**: 어느 코드가 언제 값을 바꿨는지 추적할 수 없다. 함수가 자기완결적이지 않으므로 따로 떼어 테스트하기도 어렵다. 거의 항상 입력 인수로 넘기는 편이 낫다.

> **[보강]** 전역 변수를 지우려면 `clear global 이름`이 필요하다. 그냥 `clear 이름`은 현재 workspace의 링크만 끊고 전역 값 자체는 남는다.

## 6.1.8 함수 코드 열람 (`type`)

MATLAB이 제공하는 함수는 두 종류다.

| 종류 | 설명 | 코드 열람 |
|---|---|---|
| **built-in** | MATLAB 코어에 컴파일되어 들어간 것 (`sin`, `cos`, `plus`) | 불가능 |
| **toolbox의 .m 파일** | `toolbox/` 아래에 소스로 들어있는 것 (`sphere`, `mean`) | `type`으로 가능 |

[`example/ch06/ex0618_type.m`](../../example/ch06/ex0618_type.m):

```matlab
which sin        % built-in (C:\Program Files\MATLAB\R2026a\toolbox\matlab\elfun\sin)
which sphere     % ...\toolbox\matlab\graphics\...\sphere.m
exist('sin')     % 5 = built-in
exist('sphere')  % 2 = .m 파일
type sphere      % 소스 전체를 출력
```

```
--- which sin ---
built-in (C:\Program Files\MATLAB\R2026a\toolbox\matlab\elfun\sin)
--- which sphere ---
C:\Program Files\MATLAB\R2026a\toolbox\matlab\graphics\graphics\specgraph\sphere.m
--- exist / built-in 여부 ---
exist('sin')    = 5  (5 = built-in)
exist('sphere') = 2  (2 = .m 파일)
--- type sphere (앞부분) ---
    "function [xx,yy,zz] = sphere(varargin)"
    "%   Run "doc sphere" for more information."
    ...
```

`type`은 사용자가 쓴 함수에도 똑같이 쓸 수 있다. 남이 만든 함수가 무엇을 하는지 궁금할 때 `help`로 부족하면 `type`으로 소스를 직접 본다.

> **[보강]** `which -all 이름`은 같은 이름이 여러 군데 있을 때 전부 보여준다. 내 함수가 내장 함수를 가리고 있는지(shadowing) 확인할 때 가장 빠른 방법이다. `edit 이름`을 쓰면 편집기로 열린다.

## ⚠️ 함정

- **함수 안의 변수와 workspace 변수는 이름이 같아도 별개다.** 함수 안에서 `x`를 바꿔도 바깥 `x`는 그대로다. "값이 복사되어 들어간다"고 기억한다.
- **`global`은 양쪽에서 선언해야 한다.** 한쪽만 선언하면 함수 쪽에서는 빈 배열(`[]`)로 보이고, `[] * 70`은 오류 없이 `[]`를 돌려줘 조용히 틀린 결과가 나온다.
- **`clear 이름` ≠ `clear global 이름`.** 전역 값을 정말로 지우려면 뒤쪽을 써야 한다.
- **`exist` 반환값 헷갈리기**: 1은 변수, 2는 .m 등 파일, 5는 built-in, 7은 폴더. `exist('sin')`이 5인데 "없다"로 읽으면 안 된다.
- **`type`은 built-in에 통하지 않는다.** `type sin`은 파일이 없다는 오류가 난다. `which`로 먼저 확인한다.
