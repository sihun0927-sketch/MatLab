# 7.5 디버깅

## bug라는 말의 유래

software bug는 내가 쓴 코드에 들어 있는 문제다. 두 종류가 있다.

- **coding error**: 코드가 아예 돌지 않게 만드는 잘못. 오류 메시지가 뜬다.
- **logic error**: 돌긴 도는데 **답이 틀린** 잘못. 오류 메시지가 없다.

"bug"라는 말은 전자공학에서 왔다. 실제 벌레가 장비를 고장 냈기 때문이다. 가장 유명한 예가 1947년 초기 컴퓨터 **Harvard Mark II Aiken Relay Calculator**의 릴레이에 끼여 있던 나방이다. 그 벌레를 찾아낸 연구팀을 이끈 사람이 초기 컴퓨터 과학자이자 미 해군 소장이었던 **Grace Hopper**다.

> **[보강]** 둘 중 **logic error가 훨씬 무섭다**. 오류는 어디서 터졌는지 알려 주지만, 틀린 답은 아무 말도 하지 않는다. [`sol0705_2.m`](../../example/ch07/sol0705_2.m)에서 `fall_distance(9.81, 3)` 대신 `fall_distance('ten', 3)`을 부르면 오류가 나지 않고 원소 셋짜리 답이 돌아온다. char가 ASCII 코드로 계산에 끼어든 것이다. 결과의 **크기와 값을 직접 확인하는 습관**만이 이런 것을 잡는다.

## 7.5.1 Code Analyzer

script나 live script를 만들면 편집창 **오른쪽에 세로 막대**가 생긴다. 이 막대가 오류와 경고의 위치를 표시하고, 해당 코드가 강조된다.

| 색 | 뜻 |
|---|---|
| 주황 | **warning**. 돌아는 가지만 의심스러운 곳 |
| 빨강 | **error**. 그대로는 실행이 멈추는 곳 |

강조된 곳이나 막대 위에 커서를 올리면 **문제 설명과 고치는 방법**이 뜬다.

**경고가 전부 진짜 문제인 것은 아니다.** 슬라이드의 예처럼 "세미콜론을 빼서 결과가 출력된다"는 경고는, 결과를 일부러 보여 주려 한 것이라면 그대로 두면 된다.

Code Analyzer는 live script(`.mlx`)에서 생김새가 조금 다르지만 하는 일은 같다.

### 명령으로 돌리기 — `checkcode`

> **[보강]** 슬라이드는 편집창의 Code Analyzer 막대만 보여 준다. 아래 `checkcode`와 `%#ok` 억제는 같은 기능을 명령으로 쓰는 법으로, 슬라이드 밖 내용이다.

편집창 없이 같은 정보를 받는 함수가 `checkcode`다.

[`example/ch07/ex0705_code_analyzer.m`](../../example/ch07/ex0705_code_analyzer.m)이 일부러 경고를 넣어 둔 [`warn_demo.m`](../../example/ch07/warn_demo.m)을 검사한 결과:

```
L 5 (C 3): 스크립트의 출력을 숨기려면 명령문 다음에 세미콜론을 추가하십시오.
L 6 (C 6): 스크립트의 출력을 숨기려면 명령문 다음에 세미콜론을 추가하십시오.
L 13 (C 5): 스크립트 내에서 루프가 반복될 때마다 변수의 크기가 바뀌는 듯합니다.
            속도를 위해 사전할당(Preallocation)을 고려해 보십시오.
```

| 쓰는 법 | 하는 일 |
|---|---|
| `checkcode('파일.m')` | 경고 목록을 화면에 |
| `checkcode('파일.m', '-struct')` | 구조체 배열로 받아 코드로 처리 |
| `checkcode('파일.m', '-id')` | 경고 ID까지 같이 |

문법 오류가 있으면 이렇게 나온다.

```
L 2 (C 5): '('에 닫는 ')'이(가) 누락되었을 수 있으며, 이 경우 ';'에 있는 구문이 유효하지 않습니다.
```

### 경고 억제

의도한 코드인데 경고가 뜨면 줄 끝에 `%#ok<ID>`를 붙인다.

```matlab
x = 1:5    %#ok<NOPTS>
```

ID는 `checkcode(..., '-id')`로 확인한다. 위 예에서는 `NOPTS`(세미콜론 없음)와 `SAGROW`(배열이 자람)가 나왔다.

> **[보강]** 억제는 **"이건 내가 의도한 것"이라는 표시**다. 이해하지 못한 경고를 덮는 데 쓰면 안 된다. 특히 `SAGROW`는 반복문이 길어지면 실제로 느려지므로, 억제하기 전에 사전할당(`v = zeros(1,n)`)으로 고칠 수 있는지 먼저 볼 것.
>
> `mlint`는 `checkcode`의 옛 이름이다. 지금도 동작하지만 새 코드에는 `checkcode`를 쓴다.

## 섹션 — 프로그램을 토막 내서 돌리기

logic error를 찾을 때는 프로그램의 **일부만 돌리고 멈춰서** 무슨 일이 일어났는지 본 다음 계속 돌리는 것이 유용하다. 그 가장 간단한 수단이 **섹션**이다. 원서 학습목표의 7.7(Use sections to modify and run MATLAB programs)이 이것이다.

주석 기호 `%` 뒤에 `%`를 하나 더 붙인 줄이 섹션의 경계가 된다.

```matlab
%% 자료 준비
t = 0:0.1:10;
y = exp(-0.2*t) .* sin(3*t);

%% 그리기
plot(t, y)
grid on

%% 통계
fprintf('최댓값 %.4f, 평균 %.4f\n', max(y), mean(y));
```

- `%%`로 시작하는 줄이 **섹션 제목**이 되고, 편집창에서 그 아래가 옅은 배경으로 묶여 보인다.
- 커서가 놓인 섹션만 돌리는 것이 **Run Section**(`Ctrl+Enter`)이다.
- 돌리고 다음 섹션으로 넘어가는 것이 **Run and Advance**(`Ctrl+Shift+Enter`)다.

앞 섹션이 만든 변수는 workspace에 그대로 남아 있으므로, 뒤 섹션만 고쳐 가며 반복해서 돌릴 수 있다. 무거운 자료를 한 번 읽어 두고 그리는 부분만 손볼 때 특히 쓸모 있다.

> **[보강]** 섹션은 **편집창에서만** 의미가 있다. `run`이나 `-batch`로 스크립트를 통째로 돌리면 `%%`는 그냥 주석이라 아무 일도 일어나지 않는다. live script(`.mlx`)에서는 섹션마다 왼쪽에 실행 버튼이 붙는다.
>
> 7.2.1의 [`ex0721_disp_basics.m`](../../example/ch07/ex0721_disp_basics.m)처럼 `disp('--- ... ---')`로 단락을 나눈 예제들은, 편집창에서 보면 `%%`로 나누고 싶어지는 자리다. 2장에서 다룬 cell mode와 같은 기능이다.

## 7.5.2 디버깅 툴바

섹션으로 나눠 돌리는 것보다 더 본격적인 수단이 **디버깅 툴바**다.

> 디버깅 도구와 함수들은 **R2021b에서 갱신**되었다. R2021a 이전 그림과 생김새가 다를 수 있다. 바뀐 것은 아이콘 위치와 모양이지 동작이 아니다. 내 버전의 help를 확인할 것.

### breakpoint

**breakpoint**는 코드가 실행을 멈추는 자리다. 멈춘 동안 workspace의 변수를 들여다볼 수 있다.

- script든 live script든 **줄 번호를 더블클릭**하면 걸린다.
- 제대로 걸리면 **빨간 표시**가 나타난다.
- **회색 표시**면 걸리지 않은 것이다. 이유는 둘 중 하나다.
  - 문법 오류가 남아 있다
  - 최근 수정본을 저장하지 않았다

**문법 오류가 모두 해결되기 전에는 breakpoint를 쓸 수 없다.**

### 멈춘 다음

프로그램을 돌리면 디버깅 툴바가 켜지고, breakpoint에서 실행이 멈추며, 그 자리가 **초록 화살표**로 표시된다.

| 버튼 | 하는 일 | 명령 |
|---|---|---|
| Continue | 다음 breakpoint까지 계속 | `dbcont` |
| Step | 한 줄 실행 (함수 호출은 통째로) | `dbstep` |
| Step In | 사용자 정의 함수 **안으로** 들어간다 | `dbstep in` |
| Step Out | 함수에서 나와 부른 자리로 | `dbstep out` |
| Quit Debugging | 디버깅을 끝낸다 | `dbquit` |

**Step In**이 핵심 기능이다. 내가 만든 함수를 부르는 줄에서 Step In을 누르면 그 함수 안으로 들어가 한 줄씩 볼 수 있다. 다 봤으면 Step Out으로 나온다.

> 편집창에서 VIEW 탭의 좌우 분할(left/right) 옵션을 쓰면 메인 프로그램과 함수 파일을 나란히 놓고 볼 수 있다. 슬라이드의 예는 메인 live script와 함수 파일 `DR`을 나란히 띄운 화면이다. 함수 안에 들어가 있는 동안 메인 프로그램 쪽에는 **함수로 들어간 그 호출 줄이 강조**되어, 어디서 들어왔는지 보인다.

### 명령어판

> **[보강]** 슬라이드는 툴바 버튼만 보여 준다. 아래 `db*` 명령 표는 같은 동작을 명령으로 쓰는 법으로, 슬라이드 밖 내용이다.

툴바 버튼에는 모두 대응하는 명령이 있다. 자동화된 환경에서는 이쪽이 쓸모 있다.

[`example/ch07/ex0705_debug_tools.m`](../../example/ch07/ex0705_debug_tools.m):

| 명령 | 하는 일 |
|---|---|
| `dbstop in 파일 at 행` | breakpoint를 건다 |
| `dbstop if error` | 오류가 나는 **그 자리**에서 멈춘다 |
| `dbstop if naninf` | `NaN`이나 `Inf`가 생기는 순간 멈춘다 |
| `dbstatus` | 걸린 breakpoint 목록 |
| `dbclear all` | 전부 지운다 |
| `dbtype 파일 1:20` | 행 번호를 붙여 코드를 보여 준다 |
| `dbstack` | 지금 어느 호출 경로에 있는지 |

```
=== dbstack: 지금 어느 호출 경로에 있는가 ===
  1: level_two (66 행)
  2: show_stack (62 행)
  3: ex0705_debug_tools (23 행)
  4: run (100 행)
```

`dbstop if error`는 특히 쓸모가 많다. 오류가 난 그 순간의 workspace를 그대로 들여다볼 수 있어서, 무엇이 잘못된 값이었는지 바로 보인다.

> **[보강]** `dbstop`으로 실제로 멈추면 키보드 입력을 기다리므로 `-batch`에서는 쓸 수 없다. 예제에서는 멈추지 않고도 쓸 수 있는 `dbtype`, `dbstack`, `dbstatus`, `dbclear`만 실행한다.

## 멈추지 않고 디버깅하기

> **[보강]** 이 절 전체가 슬라이드 밖 내용이다. breakpoint를 걸 수 없는 환경(배치 실행, 자동 채점)에서 쓰는 방법들을 모았다.

breakpoint를 걸 수 없는 상황(배치 실행, 자동 채점, 남의 컴퓨터)에서 쓰는 방법들이다.

### 1. 세미콜론을 잠깐 빼거나 `fprintf`를 끼워 넣기

가장 싸고 가장 자주 쓰는 방법이다. 중간값 하나만 보면 되는 경우에는 이쪽이 훨씬 빠르다.

### 2. `try` / `catch`로 오류 정보 남기기

[`example/ch07/sol0705_2.m`](../../example/ch07/sol0705_2.m):

```matlab
try
    out = fall_distance(9.81);
catch err
    fprintf('오류: %s\n', err.message);
    fprintf('식별자: %s\n', err.identifier);
    for k = 1:numel(err.stack)
        fprintf('  %s (%d 행)\n', err.stack(k).name, err.stack(k).line);
    end
end
```

```
오류: 입력 인수가 부족합니다.
식별자: MATLAB:minrhs
  fall_distance (5 행)
  report_call (31 행)
  sol0705_2 (15 행)
```

| 필드 | 담긴 것 |
|---|---|
| `err.message` | 사람이 읽는 메시지 |
| `err.identifier` | 오류 종류를 가리키는 코드 (`MATLAB:minrhs` 등) |
| `err.stack` | 어느 함수의 몇 행에서 났는지, 호출 경로까지 |

`identifier`가 있으면 오류 종류별로 다르게 대응하는 코드를 쓸 수 있다.

> **[보강]** `try/catch`가 잡아 주는 것은 **터지는 오류뿐**이다. 조용히 틀린 답을 내는 logic error는 잡히지 않는다. 그쪽은 결과의 크기(`size`)와 값의 범위를 직접 확인하거나, `assert`로 가정을 코드에 적어 두어야 한다.
>
> ```matlab
> assert(isscalar(out), '스칼라를 기대했는데 %s 가 나왔다', mat2str(size(out)));
> ```

## ⚠️ 함정

- **회색 breakpoint는 안 걸린 것이다.** 저장했는지, 문법 오류가 남았는지 확인할 것.
- **경고(주황)와 오류(빨강)는 다르다.** 경고는 실행을 막지 않는다. 그렇다고 무시해도 되는 것은 아니다.
- **경고가 전부 진짜 문제는 아니다.** 억제는 "의도했다"는 표시로만 쓸 것.
- **`-batch`에서는 `dbstop`을 쓸 수 없다.** `fprintf`, `try/catch`, `assert`로 대신한다.
- **`try/catch`는 logic error를 못 잡는다.**
- **디버깅을 마치면 `dbclear all`.** breakpoint가 남아 있으면 다음 실행이 엉뚱한 데서 멈춘다.
- **R2021b에서 디버깅 UI가 바뀌었다.** 교재 그림과 버튼 모양이 다를 수 있다.
