# 9.4 Midpoint Break Loops

## 구조

9.3의 두 예제가 바로 **midpoint break loop**다. 이 구조에서는

1. loop에 **들어가고**,
2. 계산을 하고,
3. loop 안의 **임의 지점에서** 빠져나갈지 결정하고,
4. 나머지 계산을 하고,
5. 반복한다.

이 전략은 `for` loop와 `while` loop **어느 쪽에나** 쓸 수 있다. loop 안의 명령을 **최소 한 번은** 실행해야 하고, 빠져나갈지는 중간의 기준으로 정해야 할 때 유용하다. 수치해석에서 흔하다.

> **[보강]** 다른 언어의 `do … while`(먼저 실행, 나중에 검사)이 MATLAB에는 없다. MATLAB에서는 `while true` + `if … break`로 같은 구조를 만든다.

---

## `while(1)` — 0이 아니면 참

- `while` 구조에서 loop는 첫 줄의 기준이 **거짓이 될 때까지** 반복된다.
- 컴퓨터는 결과가 **0**이면 비교가 거짓이라는 것을 "안다". 예를 들어 MATLAB에서 `4 < 2`의 결과는 0, 즉 거짓이다.

  ```matlab
  4 < 2
  ```
  ```
  ans =
    logical
     0
  ```
- 우리는 보통 1을 참으로 생각하지만, 컴퓨터에게는 **거짓이 아닌 것은 모두 참**이다. 즉 **0이 아닌 것**(1 같은)은 참이다.

## `while(1)`로 무한 루프 만들기

- `while(1)`로 `while` loop를 만들면 가상의 비교 결과를 **강제로 참**으로 만든 것이므로 **무한 루프**가 된다.
- 이런 loop를 빠져나가는 **유일한 방법은 `break`** 구조다.
- 끝나지 않는 loop는 만들기 쉽다. 그러니 **어떤 loop든 반복 횟수를 제한하는 코드를 넣어 두는 것이 좋다.**

```matlab
% 1 + 2 + 3 + ... 가 처음으로 100을 넘는 n
total = 0;
n = 0;
while 1
    n = n + 1;              % 계산 (최소 한 번은 실행)
    total = total + n;
    if total > 100          % 중간에서 나갈지 결정
        break
    end
end
fprintf("n = %d, total = %d\n", n, total)
```
```
n = 14, total = 105
```

반복 횟수 제한을 함께 넣은 형태:

```matlab
x = 1;
count = 0;
while true
    count = count + 1;
    x = x / 2;
    if x < 0.01 || count >= 1000    % 목표 도달 또는 안전장치
        break
    end
end
fprintf("count = %d, x = %.6f\n", count, x)
```
```
count = 7, x = 0.007812
```

`count >= 1000`은 수렴하지 않는 경우를 대비한 **안전장치**다. 정상이라면 7번 만에 나가지만, 기준에 실수가 있어도 1000번에서 반드시 멈춘다.

> **[보강]** `while(1)`과 `while true`는 같다. `true`가 더 읽기 쉬워 요즘 코드에서 흔하다. 괄호도 필요 없다(`while 1`). `if`/`||`에서 `||`(short-circuit)를 쓴 것은 양쪽이 스칼라이기 때문이다(8.1).

## ⚠️ 함정

- **`while(1)` 안에 `break`가 없으면 진짜 무한 루프** → `Ctrl+C`.
- **`break` 조건이 절대 참이 될 수 없는 경우**(예: `total == 100`처럼 정확히 같기를 바라는 비교, 부동소수점 비교)도 무한 루프다. `>`·`>=`나 허용오차, 그리고 **횟수 제한**을 쓴다.
- **"0이 아니면 참"**: `while -1`, `while 0.5`도 무한 루프다. `while 0`은 한 번도 안 돈다.
- `break` 위치에 따라 결과가 한 칸 달라진다. 위 첫 예에서 `if`를 `total = total + n;` **앞**에 두면 `total`은 105 그대로지만 `n`이 15가 된다(덧셈 전에 검사하므로 한 pass 늦게 나간다). 무엇을 "마지막으로 계산하고" 나가는지 확인할 것.
