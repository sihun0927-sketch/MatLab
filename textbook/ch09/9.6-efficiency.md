# 9.6 Loop의 효율 개선

MATLAB에서는 `for` loop(또는 `while` loop)가 **배열 연산보다 대체로 덜 효율적**이다. 아주 큰 배열의 원소에 곱하기를 하는 시간을 재서 확인해 보자.

## `clock`과 `etime`

시간을 재는 코드의 뼈대:

```matlab
t0 = clock;
% ... 시간을 잴 코드
etime(clock, t0)
```

- **`clock`**: 컴퓨터 시계를 조회해 현재 시각을 돌려준다. `[년 월 일 시 분 초]` 형태의 `1×6` double 배열이다.
- **`etime`**: 현재 시각과 처음 시각을 비교해 **두 값의 차이**, 즉 **경과 시간**(초)을 준다.

### 배열 연산

```matlab
A = ones(1000);         % 1000×1000, 원소 백만 개
t0 = clock;
B = A*pi;               % 모든 원소에 1*pi (스칼라 곱)
time = etime(clock, t0)
```
```
time =
    0.0040
```

- 슬라이드에서는 0.003초가 걸렸다. **실행할 때마다 다른 값**이 나온다.
- `clock`과 `etime`은 처음 요청과 마지막 요청 **사이에 CPU가 일한 시간**을 잰다. 그런데 CPU는 이 문제 말고도 다른 일을 한다. 시스템 작업을 하고, 백그라운드에서 다른 프로그램을 돌리고 있을 수도 있다.

### 같은 계산을 loop로 — 더 오래 걸린다

메모리를 지우고(`clear`) 1로 된 배열을 다시 만든 뒤, loop로 같은 계산을 한다.

```matlab
clear
A = ones(1000);
t0 = clock;
for k = 1:length(A(:))
    B(k) = A(k)*pi;
end
time = etime(clock, t0)
```
```
time =
    0.3410
```

배열 연산보다 **수십~백 배** 느리다(슬라이드 0.098초, 이번 실행 0.341초).

### 왜 느린가 — 메모리 재할당

- loop를 한 번 돌 때마다 `B` 배열에 원소가 **하나씩 추가**되었다.
- 시간을 거의 다 잡아먹은 것은 이 단계다. 컴퓨터가 **추가 메모리를 1,000,000번 할당**해야 하기 때문이다.
- `B` 배열을 **먼저 만들어 두면**(메모리 할당이 한 번만 일어나도록) 그 뒤에는 값을 하나씩 **바꾸기만** 하면 되므로 시간이 줄어든다.

## 메모리를 먼저 할당하기 (preallocation)

```matlab
clear
A = ones(1000);
t0 = clock;
B = A;                  % 임시 배열: B에 필요한 메모리를 미리 확보
for k = 1:length(A(:))
    B(k) = A(k)*pi;     % 자리만 바꾼다
end
time = etime(clock, t0)
```
```
time =
    0.0480
```

`B = A`로 **임시 배열**을 만들어 필요한 메모리를 **사전할당**했다. 최종 `B` 값은 `for` loop 안에서 대입된다. 슬라이드에서는 0.098초 → 0.017초로 줄었다.

> **[보강]** 사전할당은 보통 `zeros`나 `ones`로 한다. 요약 슬라이드의 "**dummy variable**에 placeholder 값(`ones`, `zeros`)을 넣어 두고 loop에서 바꾼다"가 이것이다.
>
> ```matlab
> B = zeros(size(A));     % A와 같은 크기의 0 배열
> ```

> **[보강]** **사전할당하지 않은 `B`는 모양도 다르다.** 없던 변수에 `B(k) = …`(선형 인덱스 하나)로 대입하면 MATLAB은 **행 벡터**로 늘린다. 그래서 loop가 끝난 `B`는 `1000×1000`이 아니라 **`1×1000000`** 이다. `B = A`로 사전할당하면 `1000×1000`이 유지된다. 시간뿐 아니라 결과의 **크기**가 달라지는 시험 포인트다.

> **[보강]** `length(A(:))`는 `A`를 한 열로 펼친 뒤 길이를 잰 것이라 원소 개수(1,000,000)다. `length(A)`는 가장 긴 차원(1000)이므로 다르다. 같은 뜻으로 `numel(A)`를 쓸 수 있다.

## `tic`과 `toc`

비슷한 명령 쌍 **`tic`**과 **`toc`**으로도 코드 토막의 시간을 잴 수 있다. `tic`이 스톱워치를 시작하고, `toc`이 그때부터의 경과 시간을 출력한다.

```matlab
clear
A = ones(1000);
tic
B = A;
for k = 1:length(A(:))
    B(k) = A(k)*pi;
end
toc
```
```
경과 시간은 0.077375초입니다.
```

같은 프로그램을 다시 실행해도 **실행 시간이 다르게 나오는 것은 당연하다.** 컴퓨터는 실행할 때마다 서로 다른 백그라운드 작업으로 바쁘기 때문이다.

### Housekeeping functions

이런 **백그라운드 작업**을 흔히 **housekeeping function**이라고 부른다.

> **[보강]** R2026a(한국어 로케일)의 `toc` 출력은 `경과 시간은 … 초입니다.`이다. 슬라이드(영어)는 `Elapsed time is 0.014646 seconds.` 출력 대신 값으로 받을 수도 있다: `t = toc`.

## `timeit`

- `clock`/`etime`은 **경과 시간**(elapsed time)을 잰다. 코드가 실행을 시작한 때부터 끝난 때까지의 시간이다.
- `tic`/`toc`도 경과 시간을 잰다.
- 두 쌍 모두 같은 명령을 실행할 때마다 **다른 값**을 낸다. 컴퓨터가 프로그램을 실행하는 동안 다른 일도 하기 때문이다.
- 즉 둘 다 **특정 프로그램의 실행에만 쓰인 시간을 재지 않는다.**
- **`timeit`** 함수는 조금 더 복잡하지만, 경과 시간이 아니라 **그 코드를 실행하는 데 쓰인 컴퓨터 시간**을 잰다.
- 단, **시간을 잴 코드가 함수로 저장되어 있어야 한다.**

```matlab
t = timeit(@loopTimes)
t2 = timeit(@vecTimes)

function loopTimes()
A = ones(1000);
B = A;
for k = 1:numel(A)
    B(k) = A(k)*pi;
end
end

function vecTimes()
A = ones(1000);
B = A*pi;
end
```
```
t =
    0.0206
t2 =
    0.0099
```

`@loopTimes`는 함수 **핸들**이다(6장). `timeit`은 함수를 여러 번 실행해 대표값(중앙값)을 돌려준다. 슬라이드는 `f.m` 파일에 `function [] = f()`를 만들고 command window에서 `t = timeit(@f)`로 0.0104초를 얻었다.

> **[보강]** R2026a에서는 스크립트 끝의 **local function**(위처럼)에도 `timeit`이 동작한다. 별도 `f.m` 파일이 꼭 필요하지는 않다. 또 `timeit`에 넘기는 함수는 **입력 인수가 없어야** 한다. 입력이 필요하면 익명 함수로 감싼다: `timeit(@() myfun(x))`.

## 중간 계산 출력 억제 (HINT)

loop를 쓸 때는 **중간 계산의 출력을 억제**하라. 값을 화면에 출력하면 실행 시간이 크게 늘어난다. 용기가 있다면 앞의 예제에서 loop 안의 세미콜론을 지우고 이 주장을 확인해 보라. 실행은 `Ctrl+C`로 멈출 수 있다. `Ctrl+C`를 누를 때는 **command window가 활성 창**이어야 한다.

> **[보강]** R2026a에서 2000번짜리 loop로 확인한 예: 세미콜론 없이(`q = k^2`) 약 0.37초, 세미콜론을 붙이면(`q = k^2;`) 약 0.003초로 **백 배 넘게** 차이 났다. 백만 번짜리 loop라면 몇 분이 걸린다.

## R2026a 메모 — `clock`/`etime`은 권장되지 않음

> **[보강]** R2026a에서 `clock`과 `etime`은 **여전히 동작**하지만 Code Analyzer가 경고한다.
>
> - `'clock'은(는) 권장되지 않습니다. 코드를 적절히 변경하여 'datetime("now")'을(를) 대신 사용하십시오.`
> - `'etime'은 권장되지 않습니다. 코드를 적절히 변경하여 'datetime' 및 마이너스 연산자를 대신 사용하십시오.`
>
> 같은 측정을 권장 문법으로 쓰면:
>
> ```matlab
> t0 = datetime("now");
> B = A*pi;
> elapsed = seconds(datetime("now") - t0)   % double(초)
> ```
>
> 시험 답안은 슬라이드대로 `clock`/`etime` 또는 `tic`/`toc`를 쓰면 된다. 성능 측정 자체는 `timeit`이 가장 믿을 만하다.

> **[보강]** 요즘 MATLAB은 JIT(실행 중 컴파일) 덕분에 **사전할당된** 단순 loop가 예전만큼 느리지 않다. 위 결과에서도 사전할당 loop(0.02~0.05초)와 배열 연산(0.004~0.01초)의 차이는 수 배 정도다. 하지만 **사전할당 없는 loop**는 여전히 훨씬 느리고, vectorized 코드가 더 짧고 읽기 쉽다는 장점은 그대로다.

## ⚠️ 함정

- **`etime(t0, clock)`처럼 순서를 바꾸면 음수**가 나온다. `etime(나중, 처음)`.
- **`B`를 사전할당하지 않으면** 느릴 뿐 아니라 `1×N` 행 벡터가 된다.
- **사전할당 크기가 작으면** loop 중간부터 다시 늘리기 시작해 이득이 사라진다. 최종 크기로 잡는다.
- **`clear` 없이 다시 재면** 이전 실행의 `B`(이미 크기가 잡힌)가 남아 있어 "사전할당 안 한" 측정이 사실상 사전할당된 측정이 된다. 슬라이드가 매번 `clear`로 시작하는 이유다.
- **`tic`/`toc`·`etime` 값은 매번 다르다.** 한 번 잰 값으로 결론 내리지 말고 여러 번 재거나 `timeit`.
- **`timeit`은 스크립트 조각을 못 받는다.** 함수(핸들)로 만들어야 한다.
- **loop 안 세미콜론 누락**은 결과는 같아도 시간을 크게 늘린다.
