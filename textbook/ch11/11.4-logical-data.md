# 11.4 Logical Data

**logical array**는 1과 0으로 이루어진 배열처럼 **보인다**. MATLAB(을 포함한 여러 언어)이 이 숫자로 **true와 false**를 나타내기 때문이다. 그러나 클래스와 메모리가 다르다.

```matlab
T1 = [true, false, true]
T2 = [1 0 1]
```
```
T1 =
  1×3 logical 배열
   1   0   1
T2 =
     1     0     1
```

| 변수 | Size | Class | Bytes |
|---|---|---|---|
| `T1` | 1×3 | **logical** | **3** |
| `T2` | 1×3 | double | **24** |

logical은 원소당 **1 byte**, double은 8 bytes다.

## `logical` 함수로 변환

double 배열(`T2` 같은)은 **`logical`** 함수로 logical 배열로 바꿀 수 있다.

```matlab
T3 = logical(T2)
```
```
T3 =
  1×3 logical 배열
   1   0   1
```

> **[보강]** `logical`은 **0이 아닌 값을 모두 true**로 바꾼다. `logical([0 -3 0.5])` → `0 1 1`. `NaN`은 바꿀 수 없다: `logical([1 NaN])` → 오류 `NaN 값을 논리형으로 변환할 수 없습니다.`

## logical 배열은 주로 논리 연산의 결과로 생긴다

```matlab
x = 1:5;
y = [2,0,1,9,4];
z = x>y
```
```
z =
  1×5 logical 배열
   0   1   1   0   1
```

`z`는 logical 배열이다. `find` 같은 함수의 입력이나 **logical indexing**에 쓰이며, 사용자 눈에 보이지 않을 때도 많다.

## `find`는 logical 배열을 입력으로 쓴다

```matlab
find(z)        % 2 3 5
find(x>y)      % 2 3 5
```

logical 배열 `z`를 넣든, 비교식 `x>y`를 직접 넣든 결과가 같다.

**왜?** `x>y`를 계산하면 그 결과가 바로 **logical 배열**(`z`와 같은 것)이기 때문이다. `find`는 그 logical 배열에서 true인 위치를 돌려줄 뿐이다. 사용자가 `z`라는 이름을 붙였는지 아닌지만 다르다.

## Logical indexing

logical indexing은 logical 배열을 만들어 바로 **판단(decision)** 에 쓰는 예다. 앞에서 만든 `z`로 기존 벡터에서 조건이 **true인 원소만** 꺼낼 수 있다.

```matlab
w = x.^2 + y;
w(z)
```
```
ans =
     4    10    29
```

`w` = `[3 4 10 25 29]` 중 `z`가 true인 2, 3, 5번째 원소만 나온다.

> **[보강]** 반대 조건은 `~z`: `w(~z)` → `3 25`. 꺼낸 위치에 대입도 된다: `x(x<0) = 0` (음수를 0으로).

---

## ⚠️ 함정

- **double 0/1로 인덱싱하면 logical indexing이 아니다.** `x = [10 20 30]; x([1 0 1])`은 **오류** `배열 인덱스는 양의 정수이거나 논리값이어야 합니다.` (0번 원소는 없다). `x(logical([1 0 1]))`은 `10 30`.
- **double 1/2로 인덱싱하면 위치 인덱스다.** `x([1 1])`은 `10 10`(1번 원소 두 번), `x(logical([1 1 0]))`은 `10 20`.
- **보기에는 같아도 클래스가 다르다.** `T1`과 `T2`는 `1 0 1`로 똑같이 보이지만 `islogical(T1)` = 1, `islogical(T2)` = 0.
- **logical에 산술을 하면 double이 된다.** `true + true` = `2` (double). `sum(z)`로 true 개수를 센다.
