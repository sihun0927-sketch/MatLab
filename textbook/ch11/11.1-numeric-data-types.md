# 11.1 Numeric Data Types

컴퓨터가 숫자를 저장하는 방법은 여러 가지다. MATLAB은 다음을 지원한다.

- **double** precision floating-point (배정밀도 부동소수점) — **기본값**
- **single** precision floating-point (단정밀도 부동소수점)
- 여러 종류의 **integer** (정수)

## 11.1.1 Double-Precision Floating-Point Numbers

- MATLAB의 **기본 형식**은 double이다.
- **IEEE Standard 754**로 정의된다. IEEE = Institute for Electrical and Electronics Engineers.
- double 값 하나는 **8 bytes**를 차지한다. **1 byte = 8 bits**이므로 64비트다.
- Workspace 창에서 각 배열의 Size, Class, **Bytes**를 볼 수 있다. `A = 1`은 1×1 double 8 bytes, `B = 1:10`은 1×10 double **80** bytes, `C = [1 2 3; 4 5 6]`은 2×3 double **48** bytes다. 즉 bytes = 원소 수 × 8.

> **[보강]** Workspace 창 대신 `whos`로도 같은 정보를 볼 수 있다. `w = whos('C'); w.bytes`처럼 쓰면 바이트 수만 꺼낸다. 이 장의 바이트 수는 모두 이 방법으로 확인했다.

### 최대·최소 크기: `realmax`, `realmin`

```matlab
realmax          % double로 저장할 수 있는 가장 큰 수
realmin          % double로 저장할 수 있는 가장 작은 양수(정규화 수)
```
```
ans =
  1.7977e+308
ans =
  2.2251e-308
```

### 너무 큰 값은 `Inf`, 너무 작은 값은 `0`

```matlab
x = 5e400        % realmax보다 크다
x = 1e-400       % realmin보다 훨씬 작다
```
```
x =
   Inf
x =
     0
```

- 최댓값보다 큰 값을 입력하면 MATLAB은 **infinity(`Inf`)** 를 대입한다(overflow).
- 최솟값보다 작은 값을 입력하면 **0**을 대입한다(underflow).

> **[보강]** 엄밀히는 `realmin`보다 작아도 곧바로 0이 되지는 않는다. `1e-310`처럼 `realmin`과 약 `4.9e-324` 사이 값은 정밀도를 잃은 채(subnormal) 저장된다. 슬라이드의 `1e-400`은 그 아래라서 0이 된다. 시험 답안은 슬라이드 설명대로 "너무 작으면 0"으로 쓰면 된다.

## 11.1.2 Single-Precision Floating-Point Numbers

- single은 double 저장 공간의 **절반**을 쓰고, 그만큼 정보도 절반만 저장한다.
- 값 하나에 **4 bytes = 4 × 8 = 32 bits**.
- `single` 함수: double → single 변환.
- `double` 함수: single → double 변환.
- `realmax`, `realmin`에 **`"single"`** 을 입력하면 single의 범위를 알려 준다.

```matlab
D = single(5);
class(D)              % 'single'
realmax("single")
realmin("single")
```
```
ans =
    'single'
ans =
  single
  3.4028e+38
ans =
  single
  1.1755e-38
```

- Workspace에서 `D`는 1×1 single **4 bytes**로 보인다(double이면 8).
- 저장 공간이 절반이라 **표현할 수 있는 범위도 훨씬 좁다**: 약 $10^{38}$ vs $10^{308}$.
- 공학자가 single로 바꿀 일은 **드물다**. 요즘 컴퓨터는 저장 공간이 넉넉하고, single은 **round-off error(반올림 오차)** 문제를 일으키기 쉽다.

### Round-off error: 조화급수 예제

round-off error는 double보다 single에서 더 문제다. 그래서 MATLAB 기본값이 double이다.

**조화급수(harmonic series)** 는 1/n을 1부터 무한대까지 더한 것이다.

$$
\sum_{n=1}^{\infty}\frac{1}{n} = \frac11+\frac12+\frac13+\frac14+\frac15+\frac16+\frac17+\frac18+\cdots
$$

- 합은 계속 커지지만(발산), 마지막 항은 점점 작아진다.
- 결국 마지막 항이 너무 작아져서 컴퓨터가 **0과 구별하지 못한다**. 그 뒤로는 더해도 합이 변하지 않는다.

**`cumsum`** (cumulative sum, 누적합)은 급수의 **부분합**을 계산한다. 결과의 k번째 원소는 1번째부터 k번째 원소까지의 합이다. 이것으로 조화급수가 어떻게 커지는지, 어디서 마지막 항들이 더 이상 기여하지 못하는지 볼 수 있다.

```matlab
clear, clc, clf
% double precision
n = 1:1e7;
harmonic = 1./n;
partial_sum = cumsum(harmonic);
plot(partial_sum, LineWidth=1)
% single precision
m = single(1:1e7);
harmonic = 1./m;
partial_sum = cumsum(harmonic);
hold on
plot(partial_sum, '--', LineWidth=1)
title("Comparison of Double and Single Precision Calculations")
xlabel("Iteration Number")
ylabel("Cumulative Sum of the Harmonic Series")
legend("Double-Precision", "Single-Precision", Location="southeast")
grid on
```

- 결과 그래프: double(실선)은 $10^7$번까지 계속 천천히 올라가 약 **16.7**에 이른다. single(점선)은 약 **15.4**에서 **평평해진다**. 그 지점부터 single 누적합은 더 이상 변하지 않는다.

> **[보강]** R2026a 실측: double 합 `16.6953`, single 합 `15.4037`. single 누적합은 **2,097,152번째 항**부터 변하지 않는다(`find(diff(ps)==0, 1)` → `2097151`). 이때 1/n ≈ 4.8e-7은 15.4의 single 간격(약 9.5e-7)의 절반보다 작아서 더해도 반올림되어 사라진다.

## 11.1.3 Integers

- double이 기본이지만 integer 타입도 있다.
- 쓰임새: **셈하는 수(counting numbers)**. 방에 2.5명이 있을 수 없고, 배열의 1.5번째 원소도 없다. 정수인 값에 double의 저장 공간을 쓰는 것은 낭비다.
- MATLAB은 **8가지** integer 타입을 지원한다. 할당된 저장 공간(비트 수)과 **부호 유무(signed/unsigned)** 로 나뉜다. 저장 공간이 클수록 큰 값을 담는다.

**Table 11.1 MATLAB Integer Types** (이름의 숫자 = 값 하나에 필요한 **비트 수**)

| 부호 있음 (signed) | 함수 | 부호 없음 (unsigned) | 함수 |
|---|---|---|---|
| 8-bit signed integer | `int8` | 8-bit unsigned integer | `uint8` |
| 16-bit signed integer | `int16` | 16-bit unsigned integer | `uint16` |
| 32-bit signed integer | `int32` | 32-bit unsigned integer | `uint32` |
| 64-bit signed integer | `int64` | 64-bit unsigned integer | `uint64` |

```matlab
E = int8(10);        % 8 bits = 1 byte
intmax("int8")
intmax("uint8")
```
```
ans =
  int8
   127
ans =
  uint8
   255
```

- `E`는 1×1 int8 **1 byte**다(8 bits = 1 byte).
- **`intmax`** 로 각 integer 타입이 저장할 수 있는 최댓값을 구한다.
- signed 4종은 저장 공간 일부를 **부호(+/−)** 표시에 쓴다. unsigned 4종은 양수라고 가정하므로 그 정보가 필요 없고, 남는 공간을 값에 쓴다. 그래서 int8 최대 127, uint8 최대 255.

> **[보강]** 범위 공식: n비트 signed는 $-2^{n-1} \sim 2^{n-1}-1$, unsigned는 $0 \sim 2^n-1$. `intmin("int8")` = −128, `intmin("uint8")` = 0. `intmax("int32")` = 2147483647.
>
> integer 연산 규칙(R2026a 실측):
>
> | 코드 | 결과 | 이유 |
> |---|---|---|
> | `int8(200)` | `127` | 범위 밖은 **최댓값/최솟값으로 잘린다(saturation)**. Inf가 되지 않는다 |
> | `uint8(-5)` | `0` | unsigned는 음수를 0으로 |
> | `int8(2.5)`, `int8(-2.5)` | `3`, `-3` | 변환은 **반올림**(0.5는 0에서 먼 쪽) |
> | `int8(10)/int8(3)` | `3` | 나눗셈 결과도 반올림한 정수 |
> | `int8(10)*2.6` | `26` (int8) | integer와 double 스칼라 연산 → 결과는 **integer** |
> | `int8(5)+int16(5)` | 오류 | 서로 다른 integer 클래스끼리는 연산 불가 |
>
> 마지막 오류 메시지: `정수는 같은 클래스의 정수나 double형 스칼라와만 결합될 수 있습니다.` (Integers can only be combined with integers of the same class, or scalar doubles.)

## 복소수 (Complex Numbers)

- 복소수의 기본 저장 형식도 double이다. 그러나 **실수부와 허수부를 둘 다** 저장해야 하므로 저장 공간이 **두 배**다.
- 복소수도 single이나 integer로 저장할 수 있다.

> **[보강]** R2026a 실측: `z = 3+4i` → **16 bytes**(double 2개). `single(3+4i)` → 8 bytes. `int8(3+4i)` → `3 + 4i`, 2 bytes.

---

## ⚠️ 함정

- **overflow는 `Inf`, underflow는 `0`.** `5e400` → `Inf`, `1e-400` → `0`. 오류 메시지는 없다.
- **integer는 범위를 넘으면 `Inf`가 아니라 최댓값에 머문다.** `int8(100)+int8(100)` = **127**, `uint8(3)-uint8(5)` = **0**.
- **integer 나눗셈은 몫이 아니라 반올림.** `int8(7)/int8(2)` = **4** (3.5를 반올림). C처럼 버림이 아니다.
- **`realmax("single")`의 따옴표.** 인수는 클래스 이름 텍스트다. `realmax(single)`처럼 따옴표를 빼면 `single()`을 인수 없이 호출한 것이 되어 오류 `입력 인수가 부족합니다.`(Not enough input arguments.)가 난다.
- **`realmin`은 0이 아니라 가장 작은 *양수*.** 가장 작은 수(가장 음수)는 `-realmax`.
- **double의 바이트 수 = 원소 수 × 8.** 1×10은 80, 2×3은 48. single은 × 4, int8/uint8은 × 1, 복소 double은 × 16.
