# 11.10 Structure Arrays

- **structure array**는 cell array와 비슷하다.
- 데이터 타입과 크기가 서로 다른 여러 배열을 저장할 수 있다(cell array처럼).
- 차이: **content indexing**(`{ }`) 대신, 저장된 배열마다 **field**라는 자리를 **dot notation(점 표기)** 으로 지정한다.

## Structure array 만들기

11.9의 `A`, `B`, `C`, `D`를 그대로 쓴다.

```matlab
my_structure.some_numbers = A
```
```
my_structure = 
  다음 필드를 포함한 struct:

    some_numbers: [1 2 3]
```

- **dot notation**으로 field 하나짜리 structure를 만든다.
- structure 이름은 `my_structure`, field 이름은 `some_numbers`.
- Workspace에서 **1×1 struct**다.

## Field 추가하기

dot notation을 다시 써서 field를 하나씩 늘린다. 3개를 더 추가한다.

```matlab
my_structure.some_letters = B;
my_structure.some_strings = C;
my_structure.some_singles = D
```
```
my_structure = 
  다음 필드를 포함한 struct:

    some_numbers: [1 2 3]
    some_letters: 'abcdefg'
    some_strings: "Good Morning"
    some_singles: [2×3 single]
```

- `my_structure`는 여전히 **1×1** structure다. field만 **4개**가 되었다.
- 각 field는 **서로 다른 데이터 타입**을 담고 있다.

## Structure 확장하기

이미 정의한 field에 배열을 더 넣으면 structure의 **크기가 늘어난다**.

```matlab
my_structure(2).some_numbers = [2 4 6 8]
```
```
my_structure = 
  다음 필드를 포함한 1×2 struct 배열:
    some_numbers
    some_letters
    some_strings
    some_singles
```

이제 **1×2** struct 배열이다. struct 배열을 표시하면 값 없이 field 이름만 나온다.

## 표준 인덱싱으로 원소 꺼내기

표준 인덱싱으로 structure array의 각 원소를 꺼낸다. 이 경우 원소 하나는 **field 4개를 가진 structure 전체**다.

```matlab
my_structure(2)
```
```
ans = 
  다음 필드를 포함한 struct:

    some_numbers: [2 4 6 8]
    some_letters: []
    some_strings: []
    some_singles: []
```

데이터를 넣지 않은 field는 **비어 있다(`[]`)**.

## Field 하나만 꺼내기

field 하나에만 접근하려면 **field 이름을 덧붙인다**.

```matlab
my_structure(2).some_numbers
```
```
ans =
     2     4     6     8
```

## Field 안의 특정 원소

field 안의 특정 원소는 field 이름 **뒤에** 원소 인덱스를 쓴다.

```matlab
my_structure(2).some_numbers(2)
```
```
ans =
     4
```

## Variable Editor

- Workspace 창에서 변수 이름을 **더블클릭**하면 **variable editor**가 열린다. structure array(또는 다른 어떤 변수)의 내용을 볼 수 있다.
- variable editor에서 값을 **바꾸거나 추가**할 수도 있다. 슬라이드에서는 `some_strings` 열에 `"Good Evening"`(2번째), `"Good Afternoon"`(3번째)을 입력했고, 그 결과 structure 크기가 **1×3**으로 늘었다.
- variable editor에서 struct 배열은 행 = 원소 번호, 열 = field인 표로 보인다.

> **[보강]** variable editor 없이 코드로 같은 결과:
>
> ```matlab
> my_structure(2).some_strings = "Good Evening";
> my_structure(3).some_strings = "Good Afternoon";
> size(my_structure)           % 1 3
> ```
>
> 유용한 함수: `fieldnames(my_structure)` → field 이름 cell array, `isfield(my_structure,'some_letters')` → 1, `rmfield(s,'name')` → field 삭제. 한 줄로 만들기: `s = struct(name="Kim", score=90)`.
>
> 모든 원소의 한 field를 모으기: `[my_structure.some_strings]` → 1×3 string `"Good Morning" "Good Evening" "Good Afternoon"`. 대괄호 없이 `my_structure.some_strings`만 쓰면 `ans`가 3번 따로 출력된다.

## `struct2table`

- MATLAB **R2016b**(슬라이드 표기)에 table이 도입된 뒤로, **직사각형 데이터**에는 table array가 structure를 거의 대체했다.
- structure를 쓸지 table을 쓸지는 대체로 **스타일 문제**다.
- structure를 쓰는 **legacy code** 라이브러리가 많으므로, 기존 함수·프로그램과 함께 쓰려면 structure 동작을 알아야 한다.
- **직사각형(rectangular)** structure array는 **`struct2table`** 로 table로 바꿀 수 있다.

```matlab
T = struct2table(my_structure)
```
```
T =
  3×4 table
    some_numbers    some_letters      some_strings      some_singles
    ____________    ____________    ________________    ____________
    {[   1 2 3]}    {'abcdefg' }    "Good Morning"      {2×3 single}
    {[ 2 4 6 8]}    {0×0 double}    "Good Evening"      {0×0 double}
    {0×0 double}    {0×0 double}    "Good Afternoon"    {0×0 double}
```

struct 원소 하나가 table의 **행** 하나, field 하나가 **열** 하나가 된다. 크기가 제각각인 field는 cell로 담긴다.

> **[보강]** 슬라이드는 table 도입을 여기서 R2016b, 11.11에서 **R2013b**라고 적었다. table은 R2013b에 도입되었고 R2016b는 string 도입 연도다. 반대 방향은 `table2struct(T)` → 3×1 struct.

## ⚠️ 함정

- **struct 배열 표시에는 값이 안 나온다.** 1×2 이상이면 field 이름만. 값을 보려면 `my_structure(2)`.
- **확장하면 나머지 field는 `[]`.** `my_structure(2).some_numbers`만 넣으면 2번째 원소의 다른 3개 field는 빈 배열.
- **인덱스 위치에 주의.** `my_structure(2).some_numbers(2)`는 "2번째 struct의 some_numbers의 2번째 값". `my_structure.some_numbers(2)`는 struct 배열이 1×1이 아니면 오류(`중간에 있는 점 '.' 인덱싱이(가) 3개의 값이 쉼표로 구분된 목록을 생성했는데, …하나의 값을 생성해야 합니다.`).
- **field 이름은 변수 이름 규칙을 따른다.** 영문자로 시작, 공백·하이픈 불가.
