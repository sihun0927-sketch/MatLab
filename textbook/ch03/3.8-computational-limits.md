# 3.8 계산 한계

컴퓨터에 저장되는 변수는 넓은 범위의 값을 가질 수 있지만 무한하지는 않다.
대부분의 컴퓨터에서 그 범위는 대략 10⁻³⁰⁸ ~ 10³⁰⁸이다.

| 함수 | 뜻 | 값 |
|------|-----|-----|
| `realmax` | 표현 가능한 가장 큰 부동소수점 수 | `1.7977e+308` |
| `realmin` | 표현 가능한 가장 작은 (양의 정규화) 부동소수점 수 | `2.2251e-308` |
| `intmax` | 가장 큰 정수 (기본 `int32`) | `2147483647` |
| `intmin` | 가장 작은 정수 (기본 `int32`) | `-2147483648` |

## 지수 오버플로 (exponent overflow)

계산 결과가 `realmax`를 넘으면 `Inf`가 된다. 이것을 **지수 오버플로**라 한다.

```matlab
x = 2.5e200;
y = 1.0e200;
z = x*y
z =
   Inf
```

## 지수 언더플로 (exponent underflow)

반대로 결과가 너무 작아 메모리에 담을 수 없으면 0이 된다. 이것이 **지수 언더플로**다.

```matlab
x = 25e-200;
y = 1.0e200;
z = x/y
z =
     0
```

전체 코드: [`ex0308_limits.m`](../../example/ch03/ex0308_limits.m)

`ex0308_limits.m` 전체 실행 결과:
```text
realmax = 1.7977e+308
realmin = 2.2251e-308
intmax  = 2147483647
intmin  = -2147483648
intmax('int64') = 9223372036854775807
2.5e200 * 1.0e200 = Inf   <- exponent overflow
25e-200 / 1.0e200 = 0   <- exponent underflow
eps      = 2.2204e-16
1+eps/2 == 1 : 1   <- 더해도 값이 바뀌지 않는다
0.1+0.2 == 0.3 : 0
abs((0.1+0.2)-0.3) < eps : 1   <- 이렇게 비교해야 한다
```

⚠️ **함정 — 오버플로는 오류 메시지를 내지 않는다**
`Inf`나 `0`이 조용히 들어앉고 계산은 계속된다. 3.3절의 `factorial(200)/(factorial(198)*factorial(2))`이
그 예다. 중간값이 `Inf`가 되는 바람에 `Inf/Inf = NaN`이 되어 최종 결과가 쓰레기가 되었지만
MATLAB은 아무 경고도 하지 않았다. **중간 계산을 큰 수로 만들지 않도록 식을 정리하는 것**이 해법이다.

⚠️ **함정 — `intmax`는 `realmax`보다 훨씬 작다**
`intmax`는 약 2.1×10⁹, `realmax`는 1.8×10³⁰⁸이다. 이름이 비슷하다고 크기가 비슷하지 않다.
정수형이 필요하면 `intmax("int64")`처럼 형을 지정할 수 있다.

> **[보강] `eps`.** 1과 1보다 큰 그 다음 double 사이의 간격이다. 값은 `2.2204e-16`.
> `1 + eps/2 == 1`이 참이라는 사실이 부동소수점 계산의 본질을 보여준다.
> 그래서 `0.1 + 0.2 == 0.3`은 거짓이고, 다음처럼 비교해야 한다.
>
> ```matlab
> abs((0.1+0.2) - 0.3) < eps    % 1 (참)
> ```
>
> 3.4절의 `sin(pi) == 0` 문제와 뿌리가 같다.
