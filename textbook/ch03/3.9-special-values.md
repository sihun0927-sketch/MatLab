# 3.9 특수값과 기타 함수

대부분의 함수는 입력 인수를 필요로 하지만, 그렇지 않은 함수도 있다.
이 절에서 다루는 것들은 스칼라 상수처럼 쓰이지만 **사실은 입력이 없는 함수**다.

예를 들어 `pi`는 함수다. Excel처럼 빈 괄호를 요구하는 프로그램에 익숙하다면
MATLAB 명령창에 `pi()`를 입력해도 오류가 나지 않는 것을 보고 놀랄 수 있다.
오류가 나지 않는 이유는 `pi`가 애초에 함수이기 때문이다.

## 특수값 (Table 3.16)

| 이름 | 뜻 | 예 |
|------|-----|-----|
| `pi` | 원주율 π | `3.1416` |
| `i` | 허수 단위 | `0 + 1.0000i` |
| `j` | 허수 단위 (`i`와 같다) | `0 + 1.0000i` |
| `Inf` | 무한대. 오버플로나 0으로 나눌 때 | `5/0` → `Inf` |
| `NaN` | Not a Number. 정의되지 않은 계산 | `0/0` → `NaN` |
| `clock` | 현재 시각 `[년 월 일 시 분 초]` 6원소 배열 | |
| `date` | 현재 날짜를 문자열로 | `'22-Sep-2026'` |
| `eps` | 1과 그 다음 double 사이의 간격 | `2.2204e-16` |

전체 코드: [`ex0309_special_values.m`](../../example/ch03/ex0309_special_values.m)

```matlab
fprintf("pi   = %.4f\n", pi)
fprintf("pi() = %.4f\n", pi())

fprintf("5/0     = %g\n", 5/0)
fprintf("0/0     = %g\n", 0/0)
fprintf("Inf/Inf = %g\n", Inf/Inf)

v = [1 NaN 3];
fprintf("NaN == NaN : %d\n", NaN == NaN)
fprintf("sum(v)           = %g\n", sum(v))
fprintf("sum(v,'omitnan') = %g\n", sum(v, "omitnan"))
```

`ex0309_special_values.m` 전체 실행 결과 (시각은 실행할 때마다 달라진다):
```text
pi   = 3.1416
pi() = 3.1416   <- pi 는 상수가 아니라 입력이 없는 함수다
i = 0 +1i,  j = 0 +1i
5/0     = Inf
-5/0    = -Inf
0/0     = NaN   <- 정의되지 않으면 NaN
Inf/Inf = NaN
NaN == NaN : 0
isnan(v)   = false  true  false
sum(v)          = NaN   <- NaN 하나가 전체를 오염시킨다
sum(v,'omitnan') = 4
eps = 2.2204e-16
clock = [2026 9 22 13 57 37.482]
date = 22-Sep-2026
datetime('now') = 2026-09-22 13:57:37
```

⚠️ **함정 — `NaN == NaN`은 거짓이다**
NaN은 자기 자신과도 같지 않다. 그래서 `x == NaN`으로는 NaN을 절대 찾을 수 없다.
반드시 `isnan(x)`를 써야 한다.

⚠️ **함정 — NaN 하나가 통계 전체를 오염시킨다**
`sum([1 NaN 3])`은 `NaN`이다. `mean`, `max`, `std`도 마찬가지다.
결측값이 섞인 자료라면 `sum(v,"omitnan")`, `mean(v,"omitnan")`처럼 옵션을 주거나
`v(~isnan(v))`로 걸러낸 뒤 계산한다.

> **[보강]** `clock`과 `date`보다 `datetime("now")`가 최신 방식이다. 연·월·일·시·분·초를
> 하나의 datetime 객체로 다루므로 날짜 계산과 형식 지정이 훨씬 쉽다.
> 슬라이드에는 `clock`만 나오지만, R2026a에서 새 코드를 쓴다면 `datetime`을 권한다.

## 함수명을 변수명으로 쓰면 함수가 가려진다

MATLAB은 함수 이름을 변수 이름으로 쓰는 것을 **허용한다.** 하지만 현명하지 않고
예상치 못한 결과를 낳는다. 이것을 **shadowing(가림)** 이라 한다.

```matlab
sin = 10;
sin(5)
```

```text
오류 발생: 인덱스가 배열 요소 개수를 초과합니다. 인덱스는 1을(를) 초과해서는 안 됩니다.
```

`sin`이 변수가 되는 순간 `sin(5)`는 "사인 함수 호출"이 아니라 "1×1 배열의 5번째 원소"를 뜻하게 된다.
원소가 하나뿐이니 인덱스 초과 오류다. 복구 방법은 **변수를 지우는 것**이다.

```matlab
clear sin
sin(0)    % 다시 함수로 동작한다. ans = 0
```

자료 분석에서 가장 흔한 실수도 같은 형태다.

```matlab
max = max(x);   % 문법은 통과하지만 이후 max 함수를 쓸 수 없다
```

전체 코드: [`ex0309_shadowing.m`](../../example/ch03/ex0309_shadowing.m)

`ex0309_shadowing.m` 실행 결과 (일부 생략):
```text
변수 max = 5
오류 발생: 인덱스가 배열 요소 개수를 초과합니다. 인덱스는 1을(를) 초과해서는 안 됩니다.
clear 후 max(x) = 5
오류 발생: 인덱스가 배열 요소 개수를 초과합니다. 인덱스는 1을(를) 초과해서는 안 됩니다.
clear 후 sin(0) = 0
```

⚠️ **함정 — 오류 메시지가 원인을 직접 말해주지 않는다**
"인덱스가 배열 요소 개수를 초과합니다"라는 메시지만 보면 인덱싱 실수처럼 보인다.
하지만 진짜 원인은 함수 이름을 덮어쓴 것이다. 명령창에서 이 오류가 나면
MATLAB이 친절하게 `'sin' appears to be both a function and a variable` 같은 안내를 덧붙이기도 한다.

> **[보강] 가려졌는지 확인하는 방법.** `which 함수명`을 실행한다.
> 정상이면 `built-in (...\elfun\sin)` 같은 경로가 나오고, 가려졌으면
> `sin is a variable.`이라고 나온다. `clear 이름`으로 되돌린다.
>
> 피해야 할 이름은 대략 다음과 같다: `max`, `min`, `sum`, `mean`, `length`, `size`, `sin`, `cos`,
> `i`, `j`, `pi`, `end`, `plot`. 변수에는 `maxScore`, `nRows`처럼 뜻이 분명한 이름을 쓴다.
